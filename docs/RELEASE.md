# Выпуск: Studio → Dev → Prod

Решение 100. Игроки видят только то, что пользователь проверил в Dev-игре.

| | Dev | Prod |
|---|---|---|
| Игра (universe) | `10774871729`, «Steal from Space Dev» | `10775754016`, «Fly & Steal Space Eggs» |
| Плейс | `120029163657587` | `113469823655044` |
| Владелец | аккаунт пользователя | сообщество `1096766348` |
| Кто играет | пользователь, тестеры (роль Tester) | игроки |
| DataStore | свои | свои |

Покупки, пропуски, звуки и сообщество выбираются по `game.GameId`: у каждой игры свои ID (`MonetizationConfig`, `SoundLooks.GAMES`, `CommunityConfig`).

## 1. Разработка

- Работа — на ветке `<тип>/<кратко>`. Её показывают в Studio, в Dev-плейсе, через свой `rojo serve` (порт 34872). Studio занимают по очереди.
- После «да» пользователя — `lune run check` и fast-forward в `master`. Пуш — по слову пользователя.
- В `master` копится то, что пользователь видел в Studio, но не на телефоне.

## 2. Dev-игра: проверка на устройствах

1. Открыть Dev-плейс в Studio. `rojo serve` из `master` (основная копия), **Connect**.
2. Проверить в Edit через MCP, что код дошёл до Studio.
3. **File → Publish** (Alt+P).
   - Ctrl+S и MCP `save_place` только **сохраняют** плейс. Живые серверы Dev-игры работают на опубликованной версии.
4. Пользователь и тестеры играют в Dev-игру на iPhone и ПК. Найденное чинится по шагу 1.

## 3. Релиз в Prod

Только после слов пользователя «в прод» про конкретный `master`.

1. Метка версии на этот коммит: `git tag v<major>.<minor>.<patch>` и пуш метки. Prod всегда равен последней метке.
2. Новые звуки, анимации и картинки, загруженные с аккаунта пользователя, расшарить на Prod-игру. В Creator Hub это право `Use` для `Universe 10775754016` (asset permissions). Список звуков — `docs/design/SOUND.md`.
3. Новые наборы, вставляемые руками (папки в `ServerStorage` и `ReplicatedStorage`, см. `CLAUDE.md`), вставить и в Prod-плейс.
4. Открыть Prod-плейс в Studio. `rojo serve` с метки, **Connect**. Проверить в Edit:
   - ручные настройки: `AuthorityMode = Server`, `StreamingMinRadius = 2048`, `StreamingTargetRadius = 4096`, `TextChatService.ChatVersion = TextChatService`, `LightingStyle = Realistic`;
   - все наборы на месте;
   - в Output при старте Play нет `[AlienModel]`, `[GuardianModel]`, `[SerpentVisual]`, `[PvpKit]` о расхождении или нехватке;
   - Prod прописан везде, где настройки по играм: `MonetizationConfig` (каталог покупок), `SoundLooks.GAMES` (звуки), `CommunityConfig` (сообщество для подарка). Поиск `10774871729` по `src/` показывает все такие места: кроме скамьи (`DevConfig.BENCH_GAME_IDS`, только Dev) рядом с каждым должен стоять и `10775754016`.
5. **File → Publish** Prod-плейса.
6. Зайти в Prod-игру с телефона: вход, полёт, покупка в магазине открывается.
7. Заметка об обновлении — в сообщество.

**Срочное исправление:** ветка от метки → исправление → проверка в Dev → новая метка (`v1.0.1`) → шаг 3.

## Чего не делать

- **Не публиковать плейс целиком через Rojo** (`rojo upload`, `rojo build` в плейс): он заменяет весь плейс и стирает наборы, вставленные руками.
- **Не править Prod-плейс руками, если правка возможна в коде.** Каждая ручная правка плейса теперь нужна дважды, в Dev и в Prod. Если без неё никак — записать её в план релиза.
- **Не публиковать в Prod то, что не прошло Dev.**

## После запуска

- **Сохранения игроков настоящие.** Любое изменение формата профиля сохраняет прогресс: миграция плюс тест на старый профиль. Поле не удаляется, пока его читает миграция.
- Покупки не теряются. Матрица отказов — `docs/CONVENTIONS.md`, раздел 11.
