### 001. Код только в файлах, синхронизация через Rojo
**Дата:** 2026-11-02
**Решение:** весь код, конфиги и UI живут в Git и синхронизируются в Studio через Rojo. Studio — для запуска и тестов. Модели из Studio забираются в файлы (`rojo syncback` или экспорт в `assets/`).
**Почему:** двоичный `.rbxl` нельзя нормально хранить в Git и сливать. Правки в Studio при подключённом Rojo перетираются.

### 002. Одна команда проверки, без CI
**Дата:** 2026-11-02
**Решение:** `lune run check` (формат, линтер, типы, тесты, сборка) запускается локально перед каждым коммитом. CI не используем.
**Почему:** разработчик один, всё можно проверить на этой машине. Если появится команда, CI будет запускать ту же команду.

### 003. Без фреймворков, свой минимальный загрузчик
**Дата:** 2026-11-02
**Решение:** один скрипт на сервере и один на клиенте, сервисы с фазами `init`/`start`, явные зависимости.
**Отброшено:** Knit — архивирован в 2024 году.

### 004. Сеть — Zap
**Дата:** 2026-11-02
**Решение:** все remotes описываются в `net/remotes.zap`, код генерирует Zap (buffer-сериализация, типы).
**Отброшено:** Blink — примерно равен по скорости, у Zap лучше документация и шире сообщество. Голые `RemoteEvent` — нет типов, лишний трафик.

### 005. Данные на клиент — свой тонкий слой на Zap
**Дата:** 2026-11-02
**Решение:** снимок при входе + дельты через Zap, на клиенте — состояния Vide.
**Отброшено:** Replica — готова, но использует свои remotes в обход Zap. Хотим всю сеть в одном типизированном месте.

### 006. UI — Vide
**Дата:** 2026-11-02
**Решение:** Vide (`centau/vide`).
**Почему:** точечная реактивность — обновляется только изменившееся свойство. У нас много часто меняющихся чисел (доход, кислород, таймеры), важна производительность на телефонах.
**Отброшено:** React-lua — зрелее, но перерисовывает компоненты целиком.

### 007. Зависимости — Wally + wally-package-types

### 008. Данные игрока — ProfileStore
**Дата:** 2026-11-02
**Решение:** `lm-loleris/profilestore` (официальный пакет автора).
**Почему:** блокировка сессии, автосохранение, корректное завершение. Сырой DataStore без этого теряет и дюпает данные.

### 009. Большие числа — свой BigNum
**Дата:** 2026-11-02

**Отброшено:** EternityNum 2 — есть жалобы на округление, избыточна. GammaNum — новая, бенчмарки только от автора.

### 017. Локализация — свой модуль строк, а не LocalizationTable
**Дата:** 2026-11-02
**Решение:** строки в `src/shared/Locale/Strings.luau`, доступ через `Text.get` с типизированным ключом. Формы множественного числа и подстановки — свои.
**Почему:** строки проверяются в Lune (длина, стоп-лист, формы, подстановки), опечатка в ключе ловится проверкой типов, поведение одинаково на сервере, клиенте и в тестах.
**Отброшено:** `LocalizationTable` + `Translator` — нельзя проверить вне Roblox, нет русских форм множественного числа. Автоперевод на другие языки не нужен: поддерживаем только русский и английский.

### 018. Чистые серверные модули получают зависимости параметрами
**Дата:** 2026-11-02
**Решение:** логика сервера без Roblox API (например, `SessionManager`) не делает `require` модулей из `ReplicatedStorage`; хранилище, схему данных, часы ей передаёт сервис.
**Почему:** строковый `require` между `ServerScriptService` и `ReplicatedStorage` в Roblox не работает, а `require` через инстансы не работает в Lune. Параметры решают и это, и тестируемость (поддельное хранилище в тестах).

### 019. Server Authority — берём
**Дата:** 2026-11-02
**Решение:** движение игроков работает под Server Authority (`Workspace.AuthorityMode = Server`). Логика полёта — общий модуль, привязанный через `RunService:BindToSimulation`, запускается и на сервере, и на клиенте.
**Что проверили экспериментом (ветка `spike/server-authority`):**
- Полёт на `LinearVelocity` + `AlignOrientation` работает: сервер считает, клиент предсказывает (`PredictionStatus.Predicted`).
- Сервер видит ввод: свои `InputAction` (контекст под `Player`) и стандартный `Humanoid.MoveDirection`.
- Попытка читерства на клиенте (телепорт на 500 studs, скорость 2000) откатывается движком за долю секунды; позиция на сервере не меняется. Свой античит для движения не нужен.
- Переход полёт → ходьба (`Physics` → `Freefall` → `Running`) работает.
**Ограничения, которые учитываем:**
- `AuthorityMode` и связанные свойства не читаются и не пишутся из скриптов и MCP — включаются в Properties вручную (один раз на плейс).
- Внутри симуляции только API с Simulation Access, состояние — в атрибутах, ввод — опросом `GetState()` (события `Pressed` ненадёжны при откатах), объекты создаются и удаляются вне симуляции.
- Плавность при реальном пинге ещё не проверена: режим Play в Studio запускает сервер и клиент в одном процессе. Проверяем на опубликованной Dev-игре.
- Производительность сервера при 20+ игроках у Roblox ещё «требует работы» — замеряем на нагрузочном тесте (этап 8).
**Отброшено:** клиент владеет физикой + серверная проверка скорости — больше кода, хуже защита.

### 020. Управление полётом
**Дата:** 2026-11-02
**Решение:** джетпак включается сам за куполом станции (под куполом — гравитация и ходьба). В космосе летишь туда, куда смотрит камера (вперёд/назад/вбок — стандартное управление движением), плюс «вверх/вниз»: Space/Ctrl на ПК, R1/L1 на геймпаде, кнопки ▲▼ на телефоне.
**Почему:** без лишней кнопки включения, понятно детям и удобно на телефоне.
**Отброшено:** включение кнопкой; горизонтальный полёт только с отдельными кнопками высоты — больше кнопок на телефоне.

### 021. Джетпак и поза полёта
**Дата:** 2026-11-03
**Решение:** модель джетпака собирается кодом (`src/server/Character/JetpackModel.luau`) и приваривается к персонажу: баллоны на спине, джойстики в руках, шланги-`Beam`. Поза полёта — настоящая анимация, описанная данными (`FlightPose`), загружается на аккаунт и запускается внутри `SpaceSimulation`. Наклон корпуса по скорости — через `AlignOrientation` (`FlightLean`). Пламя — клиентские частицы.
**Почему:** под Server Authority анимации персонажа, запущенные вне симуляции, откатываются; переопределение суставов скриптом не доживает до физики (суставы — `AnimationConstraint`); временные анимации Studio персонаж игрока не играет. Поза как данные — в Git, правится и проверяется.
**Отброшено:** процедурная поза через `Transform` суставов — не работает с новыми суставами; готовые анимации Roblox — нет позы «держит джетпак».

### 022. 8 игроков на сервер, вход к другу обязателен
**Дата:** 2026-11-03
**Решение:** максимум 8 игроков на сервер (`ServerConfig.MAX_PLAYERS`, на станции 8 отсеков). Вход к другу (кнопка Join в профиле) обязателен: при публикации включить его и зарезервировать места для друзей (Game Settings → Places → Customize reserved slots). Распределение по серверам — штатное, Roblox.
**Почему:** у каждого игрока свой отсек; на 8 игроках засады и кражи живые, но новички успевают донести добычу; запас по производительности Server Authority; так же устроены похожие игры жанра.
**Отброшено:** 12–20 игроков — хаос в кражах, тяжелее для сервера, станция на 20 отсеков слишком большая.

### 023. Тревога без шума, захват с подсказкой
**Дата:** 2026-11-03
**Решение:** шума и шкалы тревоги нет. Страж спит, пока яйцо в гнезде; когда яйцо взяли, он просыпается через `aggroDelaySeconds` (около секунды) и гонится за тем, у кого яйцо. Захват — удержание E 2 / 2,5 / 3 с (обычное / необычное / редкое). Над ближайшим яйцом — подсказка с клавишей и полоска прогресса; на телефоне подсказку нажимают и держат (локальная привязка `UIButton` к тому же действию `Grab`), на геймпаде — X.
**Почему:** правило «взял — за тобой гонятся» понятно детям сразу; шкала шума наказывала за подлёт, который не видно и не объяснить. Секунда форы даёт начать побег. Подсказка над яйцом на телефоне не требует отдельной кнопки на экране.
**Отброшено:** шкала тревоги от шума джетпака и захвата — непрозрачно и спорит с полётом на полной скорости; короткий захват 0,5–1,5 с — кража слишком лёгкая.

### 024. Скорость — единственная характеристика, погоня по отношению скоростей
**Дата:** 2026-11-03
**Решение:**
- У игрока одна характеристика — **скорость ⚡** (`BigNum`, до сотен миллиардов): натренированное × множитель джетпака. Сила и запас кислорода как характеристики убраны.
- Скорость полёта (studs/s) — логарифм от ⚡. Исход погони решает **отношение** ⚡ стража к скорости вора с яйцом: скорость полёта стража = скорость полёта вора × отношение^0,5, в пределах 0,6–1,5.
- Над стражем — рекомендуемая скорость (для среднего яйца). Скорость с яйцом игроку не показываем.
- Стражи ведут себя одинаково (спят → через секунду после кражи гонятся напрямую → домой) и отличаются видом и скоростью. Плевки Слизня и рывки Краба из старого плана отброшены.
- Пойманный роняет яйцо, оно лежит на месте; подобрать может любой; нетронутое 3 минуты — возвращается в гнездо. Подобранное снова будит своего стража.
- Кислород — время полёта (~3 минуты), не прокачивается. У карты жёсткая граница внутри симуляции.
- Темп и экономика подбираются калькулятором баланса по конфигам. За робуксы продаём очки скорости — конкретное число; размер пакета привязан к текущей прибавке тренажёра, чтобы он не обесценивался.
**Почему:** игроку всегда ясно, чего не хватает, — скорости; это мотивирует качаться дальше. Отношение вместо абсолютных чисел даёт одинаковое ощущение погони на любом этапе и не ломает физику. Рекомендация без точного расчёта оставляет азарт.
**Отброшено:** отдельное поведение и навыки уворота для каждого стража — сложнее понять, чего не хватило; несколько характеристик (мощность, кислород, сила); физическая скорость, равная ⚡; подсказка «нужно ⚡ N» над каждым яйцом и показ скорости с яйцом — раскрывает точную цель прокачки.

### 025. Магнитный захват и удар стража
**Дата:** 2026-11-03
**Решение:** пока игрок держит захват рядом с яйцом, джетпак гасит дрейф и подтягивает его к яйцу (`Grab.magnetVelocity`, внутри симуляции). Поимка — «удар»: рывок стража, вора отбрасывает и закручивает на 1,2 с без управления (кувырок через `AlignOrientation`, угол — предсказываемый атрибут), двигатель глохнет и заводится вспышкой, красная вспышка и «Поймали!» на экране, тряска камеры; яйцо отлетает в сторону со следом. Признак стана — наличие атрибутов `HitVelocity`/`HitAxis`, которые сервер снимает по таймеру: часы сервера и клиента сравнивать не нужно.
**Почему:** в невесомости яйцо уплывало из рук в момент захвата — на телефоне это главный раздражитель, а «прилипание» ощущается как фишка. Поимка без обратной связи не читалась; «упасть» в космосе — значит потерять контроль над телом.
**Отброшено:** оставить дрейф как навык; `HitUntil` по `time()` — на сервере и клиенте это разные часы; звук удара — ждёт ассета.

### 026. Отсек: капсулы для пришельцев, инкубатор без лимита, пол и инвентарь
**Дата:** 2026-11-03
**Решение:**
- Капсула — место для пришельца, а не для яйца. Новичку 3 капсулы, дальше за монеты.
- Каждое доставленное яйцо вылупляется: лежит в инкубаторе отсека без ограничения на число, время случайное в диапазоне редкости (обычное 30 с – 10 мин, самые редкие яйца игры — до 5 ч), идёт офлайн по unix-времени сервера.
- У каждого стража свой набор (грейд) из 5 ступеней с названиями редкостей; доход ступеней ×1/×2/×5/×15/×50, набор следующего стража ×1,8. Удача яйца (редкость + размер) умножает вес ступени на (1 + удача)^(номер − 1).
- Вылупившийся идёт в свободную капсулу, иначе на пол отсека; с пола поднимается в инвентарь (10 мест); полный инвентарь — лежит на полу, хранится в профиле. Кнопка «Лучших — в капсулы» расставляет по доходу.
- Скрещивание 3 → 1 одного грейда: не ниже худшего из трёх, удача 0,5. Продажа — 2 минуты дохода пришельца.
- Пришельцы и яйца адресуются `uid` из счётчика профиля.
- `PlayerData.template`/`load` получают стартовые значения (`Defaults`) от `DataService`; домен конфигов не читает.
**Почему:** игрок должен вырастить каждое украденное яйцо — «яйцо пропало, нет места» убивает смысл кражи; капсулы как ограничение дохода дают повод их покупать; разброс времени не даёт яйцам вылупляться пачкой. Удача как множитель по ступеням оставляет шанс верхней ступени любому яйцу, а значит и азарт.
**Отброшено:** капсулы как место вылупления с лимитом яиц; яйцо без места остаётся в руках; хранение пришельцев по индексу (сдвигается, не переживёт мутации); чтение конфигов из домена (нетестируемо в Lune).

### 027. Конфиги: числа отдельно от внешнего вида; калькулятор баланса
**Дата:** 2026-11-03
**Решение:** конфиги с числами (`EggConfig`, `GuardianConfig`, `AlienConfig`, `BayConfig`, `UpgradeConfig`, `SpeedConfig`) — чистый Luau без `Color3`/`Vector3`/`Enum`; внешний вид живёт в `EggLooks` и `GuardianLooks`. Кросс-ссылки конфигов проверяются тестом `tests/Config/Configs.spec.luau`. Калькулятор `lune run balance` симулирует игрока по дням на настоящих конфигах и доменном коде (вылупление, капсулы, покупки) для трёх профилей; таблица темпа в GAME_DESIGN — его вывод. Подобранные им цифры: тренажёр 300 монет ×5, джетпак 2 000 ×8, доход наборов ×1,7 за стража.
**Почему:** глобалы Roblox в Lune не существуют и в модули не пробрасываются (проверено: `_G` не разделяется), поэтому конфиг с `Color3` нельзя ни проверить тестом, ни скормить калькулятору. Темп на реальных шансах и капсулах оказался вдвое быстрее согласованного — цены и рост дохода подобраны обратно к таблице.
**Отброшено:** подстановка глобалов в Lune; дублирование чисел в калькуляторе.

### 028. Репликация профиля по разделам, команды через одну калитку
**Дата:** 2026-11-03
**Решение:** клиент получает `ProfileSnapshot` при активации профиля (и по своему запросу `RequestSnapshot`), дальше — дельты по разделам: монеты отдельным событием раз в секунду, отсек целиком (`BayChanged`) после каждой перестройки. Все команды клиента проходят `NetService.guarded`: общий лимит частоты на игрока (5 в секунду) → активный профиль → `EconomyService`, который проверяет запрос на живом профиле и применяет одно изменение. Отказ — событие `NoticeSent` с причиной из перечисления Zap.
**Почему:** отсек — до 12 капсул, 10 мест инвентаря и несколько яиц; дельта «добавлен X / убран Y» для такого объёма даёт больше кода и больше способов разойтись с профилем, чем экономит трафика. Раздел целиком — всё ещё дельта относительно всего профиля (⚡ идёт атрибутами, служебные поля не уходят). Одна калитка для всех команд — один набор проверок, который нельзя забыть.
**Отброшено:** `RemoteFunction` для команд (ответ клиенту не нужен — он получит дельту); репликация через атрибуты игрока (инвентарь — приватные данные, атрибуты видны всем).

### 029. Прокачка: тренажёр в отсеке, улучшение на месте, джетпаки в магазине
**Дата:** 2026-11-03
**Решение:** у каждого игрока свой тренажёр в отсеке; качает только хозяина и только пока он стоит на площадке. Улучшение тренажёра покупается на месте (подсказка у площадки с ценой). Джетпаки продаются в одном магазине на станции; каждый уровень — ×2 к ⚡ и новый вид (цвет корпуса, цвет и сила огня). В профиле хранятся `trained`, `trainerLevel`, `jetpackLevel` (v3); формулы — в чистом `Domain/Upgrades`, числа — `UpgradeConfig.TUNING` того же типа, калькулятор баланса считает теми же функциями.
**Почему:** свой тренажёр — отсек становится местом, куда возвращаешься, а не только складом; «встал — качаешься» понятно без слов, и АФК-кач выглядит как игрок у себя дома. Магазин для джетпаков — отдельная цель прогулки по станции и витрина, где видно, за что платишь: следующий джетпак должен выглядеть желаннее. Улучшение тренажёра в магазине не нужно — оно про прибавку, а не про вид.
**Отброшено:** один общий тренажёр на станции (не видно, чей прогресс); тренировка просто за нахождение на станции (нет действия); окно «Прокачка» в HUD с обеими покупками (улучшение джетпака без его вида — просто цифра).

### 030. Контент раньше PvP; у каждого поста свой именованный страж; карта 1600
**Дата:** 2026-11-03
**Решение:** этап 5 — контент (четыре зоны, 24 поста стражей, 24 грейда, все редкости яиц), PvP переносится на этап 6. Каждый из 24 постов — отдельный именованный страж (имена в глоссарии), при этом тел-видов шесть: посты одного вида отличаются цветом и размером. Граница карты раздвинута с 1000 до 1600 studs, зоны — кольцами 190–320 / 430–620 / 760–1020 / 1150–1450.
**Почему:** после этапа 4 прокачка работает, а качаться не к чему: три стража из 24 закрывают 30 минут игры. Полный мир нужен и для проверки баланса в игре, и как основа для PvP (которое тестируется с несколькими игроками и на пустой карте бессмысленно). Отдельные имена постов нужны, потому что пришелец называется по стражу: два поста одного вида давали бы одинаковые имена разным грейдам. Карта больше, чтобы дальние зоны ощущались далёкими даже на высокой скорости полёта; баллона (3 мин) хватает до края и обратно с запасом.
**Отброшено:** имена пришельцев по зоне и номеру («Редкий · Пояс 3») — безлико; 24 уникальных вида сразу — арт-работа не для грейбокса.

### 031. Быстрый старт прогрессии: тренажёр ×10 и чаще, стражи с убывающим шагом
**Дата:** 2026-11-03
**Решение:** тренажёр даёт 3 ⚡/с (было 0,3) и платит 4 раза в секунду (было раз в секунду); улучшение тренажёра ×1,5 (было ×1,6), цены ×6 и ×10 за уровень (были ×5 и ×8). Рекомендация стража k = 10 × ∏ шагов, шаг i = 4,2 × 0,97^(i−1) (было ровно ×3): первые стражи расходятся шире, последние — плотнее, 24-й по-прежнему около триллиона. Калькулятор: конец Пояса к 24-й минуте, 10-й страж на второй день, Кит на 53-й день (×2 — 42-й, с пакетами — 22-й).
**Почему:** на плейтесте начало ощущалось вялым: «+0,3» раз в секунду не читается как рост, а стражи ×3 шли слишком ровно. Детям нужны быстрые растущие цифры с первых секунд и заметный скачок на каждом новом страже; при этом горизонт удержания (недели до последнего стража) хотелось сохранить — его держат более дорогие улучшения и более плотные поздние стражи.
**Отброшено:** просто умножить тренажёр на 10 без правки стражей и цен — Кит падал на 17-й день.
**Дополнение (тот же день):** доход тоже должен расти с первых минут, а не после десятиминутного ожидания вылупления: обычные яйца 10 с – 2 мин (было 30 с – 10 мин), необычные 1–6 мин, редкие 5–30 мин, эпические 30 мин – 2 ч, легендарные 1,5–5 ч (потолок 5 ч сохранён); первая докупаемая капсула 100 монет (было 250), рост ×3. По калькулятору конец Пояса сдвинулся с 24-й на 18-ю минуту, поздняя игра не изменилась.

### 032. Радиус стриминга больше карты (радиусы увеличены в 041)
**Дата:** 2026-11-03
**Решение:** `StreamingMinRadius = 1024`, `StreamingTargetRadius = 2048` (карта — радиус 1600); записаны в `default.project.json` как документация и выставлены в плейсе вручную, как `AuthorityMode`: свойства Workspace плагин Rojo в открытый плейс не пишет. Выключить `StreamingEnabled` нельзя: под Server Authority Studio держит его включённым (запись игнорируется). Код по-прежнему пишется стриминг-безопасно (CONVENTIONS).
**Почему:** мир — около тысячи простых частей (станция, 320 астероидов, 48 гнёзд, 48 стражей, 440 частей ориентиров); с радиусом по умолчанию (1024) клиент сразу после входа получал ~905 из них, а дальние зоны подгружались кусками по мере полёта — это и выглядело как «медленная загрузка кусками». Память такого мира ничтожна даже для телефона, а полный радиус убирает подгрузку и даёт стражам дальних зон таблички сразу.
**Отброшено:** оставить как есть до этапа оптимизации — заметно портит первое впечатление.

### 033. PvP: удар, гарпун, бомба у всех сразу; яйцо выпадает на месте; правило 10×
**Дата:** 2026-11-04
**Решение:** три атаки на трёх дистанциях — удар (ЛКМ, выпад, перезарядка 1,5 с), гарпун (луч ~50 studs, 20 с), гравибомба (область ~25 studs, 45 с); защита — щит и рывок, без мини-игр (рывок снят в 034, щит — в 060). Любая атака делает с жертвой то же, что поимка стражем: яйцо выпадает на месте, подбирает кто успел. Способности у всех сразу, без магазина: сервер логирует использования, решение про магазин — по ним. Защита новичков 20 минут игрового времени (в обе стороны), 10 с после респауна, под куполом PvP нет, нельзя атаковать игрока с ⚡ в 10 раз меньше своей.
**Почему:** «подлетел — само выпало» ощущается как не действие; удар с замахом и выпадом — ближний бой, который видно и в который можно промахнуться. Выпадение на месте повторяет уже знакомое игроку поведение при поимке стражем и не создаёт второй механики передачи яйца. Магазин способностей рано: сначала надо увидеть, пользуются ли ими. Правило 10× — страховка от травли ради травли: денег сильному с яйца младшего грейда нет, а отнять «чтобы было» — есть.
**Отброшено:** перехват удержанием E у носителя (не ощущается как бой); мини-игра «вырвись» (лишняя сложность); дымовая вспышка (пока не нужна, вернёмся, если удар с гарпуном окажутся слишком сильными).

### 034. Рывок снят; страж сторожит яйцо, а не гнездо
**Дата:** 2026-11-04
**Решение:** способности «рывок» нет (действие, атрибут `DashUntil`, множитель в симуляции и кнопка удалены). Страж держит «дом» там, где лежит его яйцо: выпало при поимке или от удара — страж зависает над ним на месте падения, поводок 220 studs считается оттуда (поводок снят в 035); яйцо подобрали, пока страж ещё летит, — он разворачивается и гонится с текущей точки; яйцо вернулось в гнездо — вернулся и страж.
**Почему:** на плейтесте рывок (×2,2 на 0,8 с) давал игроку с ⚡ 12 увести яйцо у стража с миллионами ⚡ на одной секундной форе — вся прокачка скорости теряла смысл. Поводок от гнезда оставлял дыру: пойманный за границей поводка вор просто подбирал яйцо снова, и страж за ним уже не летел. Сторожить яйцо — одно правило на оба случая, и повторная кража ощущается так же, как первая.
**Отброшено:** страж возвращает яйцо в гнездо сам (ломает «яйцо остаётся на месте, подбирает кто успел» из 033); поводок без границы (стражи стягиваются через всю карту).

### 035. Погоня кончается только у купола; маяк станции
**Дата:** 2026-11-04
**Решение:** у стража нет поводка (было 220 studs от его места) и лимита погони (было 25 с). Погоня кончается, только когда вор пропал (вышел, умер, потерял яйцо) или оказался под куполом: внутри сферы купола или в зоне станции. Вылетел с яйцом обратно — страж снова гонится. В космосе над куполом висит экранная метка «Станция» с расстоянием; станция за кадром — метка у края экрана со стрелкой к ней.
**Почему:** на плейтесте вор, улетевший с яйцом в сторону от станции, быстро «отрывался» от стража на невидимой границе — получалось, что уходить надо не к базе, а от неё, и скорость снова теряла смысл. Купол — черта, которую видно и которую игрок и так знает («стражи не проходят»). Без маяка игрок, улетевший далеко, терял станцию из виду и не знал, куда лететь назад; экранная метка, а не BillboardGui, — чтобы она была видна с любой дистанции и не пропадала, когда станция выгружается стримингом.
**Отброшено:** отдельная видимая граница вокруг станции, шире купола (вторая черта рядом с уже понятной); поводок побольше (та же невидимая граница, только дальше); маяк лучом света в мире (за кадром не помогает).

### 036. Граница станции — видимая черта погони
**Дата:** 2026-11-04
**Решение:** погоня кончается не у купола, а у границы станции — сферы радиусом 150 studs вокруг центра купола (`StationConfig.BORDER_RADIUS`). В мире она видна как бледная оболочка и светящееся кольцо по экватору. Стражи не залетают за неё (запас 6 studs), яйцо внутри неё не сторожат. Маяк станции показывает расстояние до границы и скрывается внутри неё. Остальное из 035 в силе: поводка и лимита времени нет.
**Почему:** пользователь попросил явную черту, до которой гонится страж: купол виден плохо и слишком близко к платформе, а кольцо издалека показывает, куда дотянуть. Радиус 150 оставляет зазор около 35 studs до ближайших возможных гнёзд Пояса обломков (190 studs от центра).
**Отброшено:** граница по куполу (было в 035 — черту плохо видно); плоский круг на уровне платформы без сферы (подлетая сверху или снизу, непонятно, пересёк ли).

### 037. Одно яйцо на гнездо, новое — после доставки
**Дата:** 2026-11-04
**Решение:** пока яйцо гнезда у вора или лежит выпавшим, гнездо пустое. Новое яйцо вырастает через 20 с после того, как старое доставили в отсек. Яйцо, которое не доставили (выпавшее истекло через 3 минуты, вор вышел из игры), возвращается в гнездо. Цикл — чистый модуль `Domain/NestCycle` с тестами.
**Почему:** на плейтесте за долгую погоню (после 035 она не ограничена) гнездо успевало вырастить второе яйцо через 20 с после кражи, и страж охранял сразу два: гнался за вором и одновременно «держал» новое яйцо в гнезде. Одно яйцо на гнездо — одна цель у стража.
**Отброшено:** таймер роста запускать при возврате яйца (возврат и так кладёт яйцо обратно); сторожить новое яйцо, бросая погоню (вор уходит, просто дождавшись нового яйца).

### 038. Купол не пускает выпавшие яйца; удар по прицелу в конце замаха
**Дата:** 2026-11-04
**Решение:** выпавшее яйцо держится снаружи купола с запасом 4 studs (`EggConfig.DOME_MARGIN`): дрейфуя к станции, скользит по куполу, а выбитое внутри выталкивается наружу (`Bounds.pushOutside`). Удар ищет цель по прицелу в конце замаха (0,3 с), а не в момент нажатия; коридор удара — 8 + 14 studs вперёд и ±45° от прицела (было 8 + 9 и ±35°).
**Почему:** на плейтесте вдвоём бомба у самой станции выбила яйцо, оно доплыло до платформы и зависло над ней: под куполом ходят пешком, достать его было нельзя. Удар почти не попадал: за замах цель уходила из коридора, зафиксированного при нажатии, и сам коридор был узким.
**Отброшено:** яйцо под куполом падает на платформу (кто-то получает яйцо, не долетев с ним; доставка по сути без кражи); яйцо под куполом сразу в гнездо (удар у станции становится способом вернуть яйцо стражу).

### 039. Удар — выпад с ударом по касанию
**Дата:** 2026-11-04
**Решение:** удар — выпад по прицелу на 0,25 с со скоростью полёта плюс 40 studs/s, с анимацией удара рукой (`StrikePose`, загружается как анимация полёта) и вспышкой джетпака. Яйцо выбивается только в момент касания: первая цель ближе 6 studs перед атакующим (±70°) во время выпада; в точке касания вспышка, яйцо летит дальше по направлению удара. Выпад без касания — промах, без стана (вместо полсекунды без хода из 033). Выпад считает симуляция (предсказание, без задержки у атакующего), касание — сервер каждый кадр. С яйцом в руках удара нет; удержание ЛКМ бьёт снова, как только прошла перезарядка 1,5 с.
**Почему:** на плейтесте вдвоём удар выглядел как «пролетел, кликнул — у соседа само выпало»: замаха не было видно, яйцо падало через 0,3 с без всякого удара. Выпад и касание делают причину видимой. Запрет бить с яйцом закрывает выпад как способ убегать от стража: иначе это тот же рывок из 034.
**Отброшено:** оставить замах и проверку коридора, добавив только анимацию (яйцо всё равно выпадает не от касания); выпад по нажатию на сервере (у атакующего задержка на пинг).

### 040. Игра остаётся на личном аккаунте
**Дата:** 2026-11-04
**Решение:** игра и все её ассеты (анимации полёта и удара, дальше модели, звуки, картинки) принадлежат личному аккаунту разработчика, а не группе. Правило CONVENTIONS «ассеты — от группы игры» заменено на «ассеты — от владельца игры».
**Почему:** разработчик один, доходом делиться не с кем; доход с личной игры (продажи, выплаты за Premium, DevEx) идёт на аккаунт так же, как с групповой. Обе анимации уже загружены с аккаунта.
**Отброшено:** группа сейчас — нужна для команды, общей казны и имени студии, ничего из этого пока нет. Цена отказа известна: при переезде в группу ассеты придётся перезалить от неё (анимации играют только в играх своего владельца).

### 041. Скорость до 250, карта вдвое больше, захват на скорости, медленный режим
**Дата:** 2026-11-04
**Решение:** скорость полёта — 48 studs/s на ⚡ 10 и +18,4 за каждые ×10 (было +8,2): ⚡ 1 трлн летит на ~250. Зоны отодвинуты сильнее с удалением: Пояс 285–480, Кольца 775–1115, Туманность 1445–1940, Горизонт 2300–2900, граница карты 3100; астероидов 700, ориентиры растянуты; гнёзд по зонам 14 / 20 / 25 / 32 — от гнезда до гнезда везде около 2,2 с полёта на скорости зоны (после плейтеста при 12 в каждой зоне яйца приходилось долго искать). Захват «ловит» яйцо с расстояния 0,2 с полёта на текущей скорости (не меньше 9 studs) и подтягивает к нему со скоростью полёта; прогресс захвата набирается только в пределах 9 studs и не сбрасывается, пока подтягивает. Медленный режим (Q / L3 / кнопка на телефоне) ограничивает скорость полёта стартовыми 48; стражи считают погоню от фактической скорости вора (`Simulation/TopSpeed`). Стриминг: `StreamingMinRadius = 2048`, `StreamingTargetRadius = 4096` (вручную в плейсе, как в 032).
**Почему:** на плейтесте максимальная скорость не впечатляла; 250 выглядит хорошо. С новой формулой полёт на прежней карте стал бы на 40 % короче, а хотелось длиннее, поэтому карта выросла сильнее, чем скорость: до своей зоны на её скорости — ~5 с в Поясе, ~7 в Кольцах, ~9 в Туманности, ~11 на Горизонте. На 250 studs/s зону захвата в 9 studs пролетаешь за сотые секунды — яйцо было почти не схватить.
**Отброшено:** равномерное увеличение карты (начало с 48 studs/s стало бы тягучим); медленный режим, который замедляет только игрока, а не погоню (иначе он ловушка рядом со стражем).

### 042. Аналитика: одна служба, факты — сигналами, частое — суммами
**Дата:** 2026-11-04
**Решение:** `MetricsService` — единственный, кто вызывает `AnalyticsService`; остальные службы сообщают факты сигналами. Меряем: воронку новичка из 9 шагов (вошёл, вылетел, схватил яйцо, доставил, вылупил, первая покупка, кража у стража 4, у стража 6, в Ледяных кольцах) — каждый шаг один раз на аккаунт, маской в профиле; прогресс по стражам (первая доставка от поста дальше прежнего); экономику монет и ⚡; воронку каждой кражи (взял → граница станции → доставил); события потери яйца, поимки стражем, смерти от кислорода, способностей PvP и скрещивания. Частые факты суммируются и уходят раз в 5 минут и при выходе. Профиль v5: `onboardingSteps`, `bestPost`.
**Почему:** этап 7 должен показать, где уходят новички и не ломают ли награды темп; решение о магазине способностей (033) ждёт чисел с живых серверов; скрещивание — отдельная механика, и важно знать, пользуются ли ею. Сигналы вместо вызовов аналитики внутри служб держат игровой код чистым, а суммы — запросы в пределах лимита Roblox (120 + 20 × онлайн в минуту).
**Отброшено:** события на каждую выплату дохода и каждый удар (упрёмся в лимит при большом онлайне); имена игроков в полях (сочетания значений ограничены 8 000); отправка из Studio (Roblox её не принимает).

### 043. Доска монет: заработано за всё время, логарифм в хранилище
**Дата:** 2026-11-04
**Решение:** доска ранжирует по монетам, заработанным за всё время (`coinsEarned`, профиль v6), а не по балансу. Все источники монет начисляют через `Domain/Wallet.earn` (баланс и счётчик вместе); у игроков до v6 счёт начинается с баланса. На сервере — колонка `●` в стандартном списке игроков строкой формата игры; по всем серверам — топ-10 на табличке у спавна. Общее хранилище — `OrderedDataStore`, в нём очки: десятичный логарифм монет × 10⁶, округлённый до целого. Сервер пишет изменившиеся очки раз в 5 минут и при выходе, читает топ раз в 2 минуты; игроки на сервере показываются точными числами поверх прочитанного. Строки рисует клиент на своём языке. В Studio без хранилищ — хранилище в памяти.
**Почему:** баланс падает от каждой покупки — игрок, который вложился в капсулы, проваливался бы в таблице; доска должна радовать за прогресс. Монеты — `BigNum` далеко за пределами целых чисел хранилища, а логарифм сохраняет порядок мест и даёт ~6 знаков, больше, чем показывает `BigNum.format`. Единая точка начисления не даст будущим наградам (задания, подарок за вход) пройти мимо доски. Числовое значение в списке игроков Roblox показывает плохо (1.5e15 обрезается, огромные — `e+…`), строка выглядит как в HUD. Колонка — значок монеты, потому что её имя одно на всех игроков.
**Отброшено:** доска по текущему балансу (наказывает за покупки); хранить мантиссу и порядок в двух хранилищах (сортировка только по одному числу); место игрока вне топа (у `OrderedDataStore` его не узнать дёшево); скорость и кражи на доске (договорились — только монеты).

### 044. Задания дня: награда — минуты своей игры, одна замена в день
**Дата:** 2026-11-04
**Решение:** 3 задания в UTC-сутки из пула (доставь N яиц; доставь яйцо из зоны своего самого дальнего стража; вылупи N пришельцев; потренируйся 5 минут; скрести пришельцев — когда есть 3 одного стража; выбей яйцо у игрока — после защиты новичка). Награда задания — 7–10 минут дохода игрока (не меньше 200 монет) и скорости его тренажёра; все три вместе — в среднем 25 минут. Награда считается в момент «Забрать» и забирается кнопкой. Раз в день одно невыполненное задание можно заменить на другое. Профиль v7: `quests`. Прогресс тренажёра — секунды, поэтому сигнал `TrainingService.trained` теперь несёт и время.
**Почему:** награда от собственного темпа одинаково ценна новичку и ветерану и не ломает экономику: калькулятор даёт +10 % ⚡ к 30-му дню и на 5–8 % более ранних дальних стражей — в пределах 10–15 % этапа 7. Кнопка «Забрать» — маленький праздник и видимая награда. Замена нужна прежде всего для PvP-задания на пустом сервере. Задания хранятся в профиле, поэтому перезаход их не меняет.
**Отброшено:** фиксированные суммы наград (на поздних стражах ничего не стоят, на ранних ломают темп); авто-выдача награды без кнопки; убрать PvP-задание из пула (тогда задания не подталкивают к PvP).

### 045. До 30 капсул в два яруса
**Дата:** 2026-11-04
**Решение:** максимум капсул — 30 (было 12). Цена прежняя: каждая следующая втрое дороже, 30-я стоит ~2,5·10¹⁴. В отсеке они стоят двумя ярусами по 3 ряда × 5: нижний на полу заполняется первым, верхний висит над ним (стойки верхнего яруса без столкновений); табличка капсул поднята над верхним ярусом. Отсек, тренажёр и места пришельцев на полу не сдвинулись.
**Почему:** 12 капсул набирались в первый же день, и улучшать ферму дальше было нечем. Улучшение фермы должно мотивировать всё время игры. По `lune run balance` (без покупок) капсулы теперь покупаются постоянно: 15 к первому дню, 21 к седьмому, 25 к 30-му, 27 к 60-му; последние — далёкая цель. Темп стражей почти не изменился (дальние — в пределах дня-двух), доход к 60-му дню выше (179M/с против 107M/с).
**Отброшено:** расширять платформу и отсеки под 30 капсул на полу (8 отсеков по кругу уже занимают почти всё место); мельче капсулы в один ярус (10 в ряд не влезает в ширину отсека).

### 046. Подарок за вход: 7 дней, минуты своей игры, яйцо на седьмой
**Дата:** 2026-11-04
**Решение:** подарок раз в UTC-сутки, серия из 7 дней подряд; пропуск — серия заново, после седьмого — новый круг. Подарок дня — 3, 4, 5, 6, 8, 10, 15 минут дохода игрока (не меньше 200 монет) и скорости его тренажёра; на седьмой день ещё редкое среднее яйцо от самого дальнего стража, с которого игрок доставлял (новичку — от первого). Подарок забирается кнопкой на экране, который открывается сам при входе после «С возвращением!»; кнопка «Подарок» с бейджем — если экран закрыли. Профиль v8: `loginGift`. Формула «минуты своей игры» вынесена в `Domain/PlayReward` — общая для заданий, подарка и будущего индекса.
**Почему:** награда от темпа одинаково ценна на любом этапе. Седьмой день должен ощущаться особым, а яйцо детям понятнее и радостнее цифр; но не самое жирное: эпическое или легендарное яйцо последнего стража раз в неделю — слишком много (пользователь). По `lune run balance` задания и подарок вместе ускоряют стражей на 6–8 % (дальние — на 2–3,5 дня из 44–52), ⚡ к 30-му дню выше на ~16 %.
**Отброшено:** фиксированные суммы (то ничего не стоят, то ломают темп); прощать один пропуск (серия перестаёт быть серией); выдавать подарок без кнопки.

### 047. Индекс пришельцев и единый реестр
**Дата:** 2026-11-04
**Решение:** индекс — список всех 120 пришельцев (24 стража × 5 ступеней). Пришелец найден, когда впервые пришёл к игроку (вылупился, скрещен, выдан командой); награда за него забирается в окне индекса нажатием на светящегося пришельца: минуты дохода по ступени — 1, 2, 3, 5, 10 (только монеты); за полный набор стража — разово 15 минут. Пришельцы, которые у игрока были до индекса, найдены сразу, без награды. Профиль v9: `index`. **Единый реестр:** все места кода (индекс, вылупление, скрещивание, калькулятор баланса, тексты) берут пришельцев только из `AlienConfig`; калькулятор больше не придумывает «синтетических» пришельцев для стражей за пределами конфига. Правило записано в CONVENTIONS (раздел 3) вместе с остальными точками правды: `Wallet`, `PlayReward`, `Bay.addEgg`, `UtcDay`, типы из `remotes.zap`, `UI/Window`, `Layout.placeInMenu`.
**Почему:** коллекция — сильный повод возвращаться, а награда «забрать» заставляет заглядывать в индекс. Монеты, а не ⚡: индекс про коллекцию, не про тренировку; на баланс почти не влияет (+~1 % к темпу сверх заданий и подарка). Единый реестр — требование пользователя: чтобы в будущем (ивентовые пришельцы, новые стражи) нигде не было расхождений. Пока делали шаг, нашли и убрали другие копии: начисление наград в трёх службах, расчёт наград на трёх экранах, создание яйца в трёх местах, ручные копии сетевых типов на клиенте, шапки окон.
**Отброшено:** награда сразу при открытии (в индекс не заходят); ⚡ за открытия (пересекается с заданиями и подарком); отдельный список пришельцев у индекса (расходился бы с реестром).

### 048. Каркас ивентов: часы на сервере, состояние в атрибутах
**Дата:** 2026-11-04
**Решение:** у каждого ивента свои часы на каждом сервере (`Domain/EventClock`: тишина → предупреждение → ивент); расписание, длительности и названия — `EventConfig`. Состояние публикуется атрибутами папки `ReplicatedStorage.Events`, клиент показывает строку с таймером сверху, большой анонс (с зоной, если ивент где-то) и метку к месту ивента. Игровые эффекты подключаются к сигналу `EventService.changed`, место ивента задаёт служба ивента. Солнечная буря — первый ивент в конфиге (5 мин тишины с 10-секундным предупреждением в конце, 15 с бури), но в расписании выключена до своего шага: таймер бури, после которой ничего не происходит, только запутал бы. Метка станции и метка ивента — один компонент `UI/ScreenPin` (маяк станции переведён на него).
**Почему:** атрибуты на реплицируемой папке видны и тем, кто зашёл посреди ивента, без отдельных сетевых событий и снимков; анонс — только своему серверу, как договорились. Каркас не знает, что делает ивент, — буря, метеоритный дождь и существо подключаются к нему, не меняя его.
**Отброшено:** сетевые события Zap для фаз (нужен ещё снимок для входящих посреди ивента); общее расписание на все сервера (анонс должен быть «на свой сервер»).

### 049. Солнечная буря и размер станции от одного числа
**Дата:** 2026-11-05
**Решение:** буря — 15 секунд после 5 минут тишины (последние 10 секунд — предупреждение). Её край — граница станции, та же, где останавливаются стражи (одно число). Кто в космосе в момент начала, переносится на платформу перерождением на спавне (`LoadCharacterAsync`), яйцо из рук сразу возвращается в гнездо, тост «Буря! Тебя вернуло на станцию». Кто на станции — может вылететь из купола, но не дальше границы: полёт упирается в неё, как в край карты. Инкубаторы всех игроков в бурю — ×30. Буря включена в расписание. **Размер станции** — одно число `StationSize.PLATFORM_RADIUS`; купол, граница, спавн, кольцо отсеков, кольца зон, поле астероидов, край карты, чёрная дыра, место киоска и доски — цепочкой от него. Сейчас все значения те же (90 / 150 / 285 / 2900 / 3100).
**Почему:** граница стражей и край бури — одна линия (пользователь); раз пользователь будет менять размер станции, все радиусы должны идти от него, иначе граница уедет внутрь купола или на гнёзда. Перерождение вместо длинного `PivotTo`: тот рвёт суставы персонажа. По `lune run balance` буря почти не меняет темп стражей (прогресс упирается в ⚡, а не в вылупление).
**Отброшено:** отдельный радиус «второго кольца» между границей и гнёздами (две линии, которые разъедутся); выпускать в бурю только до купола.

### 050. Метеоритный дождь: варианты пришельцев и яйца под охраной стража
**Дата:** 2026-11-05
**Решение:** раз в 15–25 минут (предупреждение 30 с) на 2 минуты у гнезда случайного стража идёт метеоритный дождь: падает 2 яйца на игрока сервера, не меньше 4 и не больше 16, по одному, равномерно за первые 75 % дождя, до 40 studs от гнезда. **Яйца охраняет страж этого гнезда** — так же, как выбитое яйцо (решение пользователя), грейд яйца — его грейд, редкость и размер — из лута его зоны. Гнездо яйцо не трогает: доставка не растит новое, потерянное исчезает; неподобранные гаснут в конце дождя, яйцо в руках остаётся. Из метеоритного яйца вылупляется **метеоритный вариант** пришельца того же стража и ступени с доходом ×2. Варианты — часть единого реестра `AlienConfig` (`VARIANTS`, `grade.variants`); id обычных не изменились, метеоритные — с суффиксом `.Meteor`. Скрещиваются только пришельцы одного грейда и одного варианта, результат — того же варианта. В индексе — отдельный раздел «Метеоритные» со своими наградами и наборами (вкладки в окне). Профиль v10: у яйца в инкубаторе `variant`, наборы индекса — по id (`"3"`, `"3.Meteor"`) вместо грейда.
**Почему:** без стража дождь в дальней зоне давал бы новичку яйца, до которых он по силе ещё не дорос; страж сохраняет темп прогресса и делает дождь общим испытанием (толпа против одного стража). Яйца от числа игроков — на пустом сервере есть что ловить, на полном — гонка. Варианты в общем реестре, а не отдельные «ивентовые пришельцы», — индекс, вылупление, скрещивание, калькулятор и тексты берут их оттуда же, без расхождений (решение 047). Скрещивание внутри варианта не даёт «размножать» метеоритных из обычных. По `lune run balance` (одно яйцо с дождя, если его страж по силам) темп стражей меняется в пределах шума — это приятный бонус, а не ускорение.
**Отброшено:** яйца без стража — гонка только между игроками (пускает новичков к старшим яйцам); грейд по ближайшему посту без охраны; смешанное скрещивание с метеоритным результатом; метеоритные пришельцы в общем разделе индекса (120 лишних ячеек в каждой строке).

### 051. Метеоритный дождь: кратеры полосой через все зоны, сразу после бури
**Дата:** 2026-11-05
**Решение:** меняет часть решения 050. Метеоры падают не у одного гнезда, а полосой от станции в случайном направлении, через все зоны поровну (по кругу от станции), до 150 studs вбок от линии и не ближе 60 studs к любому гнезду и другому кратеру. **Каждый метеор оставляет кратер** — временное гнездо с одним метеоритным яйцом и своим стражем; грейд и пост стража — как у ближайшего обычного гнезда зоны. Кратер — обычное гнездо для всей механики (кража, выбитое яйцо, возврат в гнездо), но новое яйцо в нём не растёт: после доставки он исчезает вместе со стражем; в конце дождя исчезает сразу, если яйцо на месте, а если яйцо в пути — когда его доставят или оно вернётся. Число метеоров прежнее: 2 на игрока, от 4 до 16. **Дождь начинается только сразу после бури**: прошёл его промежуток — ждёт конца ближайшей бури (поле `after` ивента в `EventConfig`), его предупреждение и сам дождь (2,5 мин) целиком помещаются в 5 минут тишины. Стражи держатся за одного вора, пока тот не пойман и не в безопасности, затем берут ближайшего.
**Почему:** один страж на много яиц не работает (пользователь): сильный игрок уводит стража и держит его на себе, а остальные, в том числе новички, растаскивают яйца старших зон и слишком быстро растут. С кратерами у каждого яйца свой страж, и вся проверенная механика гнёзд работает как есть. Полоса через все зоны даёт каждому яйца своего уровня в каждый дождь, а не раз из четырёх. Буря посреди дождя сжигала бы яйцо в руках (перенос на станцию) и закрывала бы космос на 15 секунд из 120. По `lune run balance` метеоритные яйца ускоряют дальних стражей на 5–10 % — в пределах 10–15 % этапа 7.
**Отброшено:** яйца у одного гнезда под его стражем (решение 050: увести стража — и яйца свободны); яйцо со стражем без гнезда (своя механика вместо проверенной); одна зона за дождь (новичку чаще всего нечего ловить); пропускать бурю во время дождя (таймер бури, видный всегда, прыгал бы).

### 052. Активность игроков: кто отошёл от клавиатуры
**Дата:** 2026-11-05
**Решение:** отдельная механика `ActivityService` (`Domain/Activity`, `ActivityConfig`). Игрок активен, пока за последние 3 минуты сдвинулся больше чем на 10 studs от прошлой точки или прислал любую команду (через `NetService`); перерождение движением не считается. Наружу — `isActive`, `activeCount`, `idleSeconds` и сигнал `changed`. Первое применение: метеоров в дожде — 2 на **активного** игрока (от 4 до 16). Ограничения на сам АФК (кик без геймпасса и т. п.) пока нет — идея записана на этап 8 (GAME_DESIGN, «Монетизация»).
**Почему:** АФК-кач на тренажёре — часть игры, поэтому на сервере может стоять 7 отошедших и 1 активный; считать их всех — значит отдать одному игроку 16 яиц (пользователь). Механика отдельная, потому что пригодится и дальше (пользователь): ограничение АФК без пропуска, награды «за присутствие», аналитика. Сервер судит по движению и командам, а не по вводу клиента: так меньше доверия клиенту, а `Player.Idled` есть только на клиенте.
**Отброшено:** лимит метеоритных яиц на игрока за дождь (не решает «один активный забирает всё», только откладывает); просто меньше яиц (на полном сервере активных тогда не хватит); `Player.Idled` с клиента (подделывается, и Roblox сам кикает через 20 минут простоя).

### 053. Метки дождя по зонам, метеор каждые 3 секунды, анонс каждого кратера
**Дата:** 2026-11-05
**Решение:** меняет часть решения 051. **Метеоры падают по одному каждые 3 секунды** (`MeteorConfig.FALL_STEP_SECONDS`), первый — через 3 секунды после старта, а не равномерно по 90 секундам: при 4 метеорах все кратеры есть через 13 секунд, при 16 — меньше чем через минуту; остальное время дождя — на кражу (тест: падение занимает не больше половины дождя). Во время дождя на экране не одна метка к середине первой зоны, а **по метке на каждую зону**, где есть кратер с яйцом на месте: к ближайшему к игроку такому кратеру зоны, с названием зоны и расстоянием. Яйцо унесли — метка зоны переходит к следующему кратеру; в зоне не осталось яиц — метка пропадает. **О каждом новом кратере — анонс** «Новый кратер в зоне …» (один раз за кратер: вернувшееся яйцо не объявляется). Сервер публикует такие места ивента как «споты» (`EventService.showSpot`/`hideSpot`, папка `Spots` у ивента в `ReplicatedStorage.Events`), клиент выбирает по ближайшему в зоне (`Domain/EventSpots`) и объявляет новые (`EventConfig.spotAnnounceKey`). Метки, которые налезли бы друг на друга (вдоль полосы и у края экрана — почти всегда), раздвигаются по вертикали: ближняя стоит на месте, дальние отходят к середине экрана (`ScreenMarker.separate`). Метка ивента (середина первой зоны) — в предупреждение и до первого кратера.
**Почему:** игрок видел только ближний кратер и не знал, что дальше по полосе есть кратеры старших зон; при одном игроке кратер дальней зоны появлялся через 90 секунд — пауза в 30 секунд между метеорами слишком большая (пользователь). С коротким шагом метки всех зон появляются почти сразу, а анонс говорит, где новый кратер. Метка на каждый кратер — до 16 штук — загромождает экран, а по зоне игрок и так выбирает, куда лететь. Число яиц не изменилось — баланс тоже.
**Отброшено:** метка на каждый кратер; BillboardGui над кратерами (дальние не подгружены стримингом); одна метка «ещё N» (не видно, в какой зоне); отмечать места падения заранее, до метеора (с шагом 3 секунды не нужно — решение пользователя); все метеоры одним залпом (16 разом сливаются, и тесно у ближних кратеров).

### 054. Звёздный змей: охота дальше первой зоны, удача яиц в награду
**Дата:** 2026-11-05
**Решение:** третий ивент этапа 7 — Звёздный змей (вместо кита; решения пользователя от 2026-11-05). Раз в 15–25 минут сразу после бури, как метеоритный дождь, и может совпасть с ним; предупреждение 30 секунд, охота 3 минуты. Змей выходит из Горизонта событий и охотится на **всех в космосе дальше Пояса обломков** (у станции и в первой зоне безопасно, новичков не трогает), держится за одного, как страж. Скорость — **как у стража**: у змея своя ⚡, как у среднего (3-го из 6) стража той зоны, где летит цель, и гонится он по формуле стражей (`Speed.chaseSpeed`: ⚡ цели с учётом веса яйца против ⚡ змея). Кто прокачан до середины своей зоны, уходит от змея и с обычным яйцом, кто слабее — теряет яйцо. (Сначала было 95 % скорости цели без яйца, но так ⚡ ничего не решала: с яйцом змей ловил всегда, налегке — никогда; исправлено по замечанию пользователя.) **Поимка — как у стража:** отброс и оглушение, яйцо выпадает и потом возвращается в гнездо; пойманного змей 20 секунд не трогает. **Награда — удача:** яйца, доставленные во время охоты, вылупляются с удачей +0,35 сверх своей (между редким и необычным яйцом). Удача хранится в яйце (`EggRecord.luck`, профиль v11) и идёт клиенту по сети; формула удачи одна — `EggConfig.luckOf`. Удар стража вынесен в `Character/Prey` и общий со змеем. Тело змея рисует клиент по следу головы (`Domain/SerpentBody`). По `lune run balance` дальние стражи наступают на 1–4 % раньше (в пределах 10–15 % этапа 7).
**Почему:** опасность, которая меняет обычную игру на 3 минуты, а не новая механика: поимка и погоня уже знакомы игроку по стражам. Скорость от цели — как у стражей (отношение скоростей, а не числа). Награда тянет игроков наружу именно в охоту; совпадение с дождём — «метеоритное яйцо с удачей» (пользователь).
**Отброшено:** змей кусает кислород (можно не долететь домой); уносит на станцию, как буря (выбивает из охоты целиком); охота на всех за границей станции (достаётся новичкам) или только на тех, кто с яйцом; монеты за побег (новая награда в балансе); без награды; своё расписание вне бури (буря посреди охоты переносит всех на станцию); тело змея из серверных деталей (рывки при репликации и трафик на каждый сегмент).

### 055. Звёздный змей, версия 2: выбей звёздное яйцо
**Дата:** 2026-11-05
**Решение:** заменяет механику решения 054 (расписание, тело змея, `Character/Prey`, удача в яйце — остаются). Змей больше не охотится на игроков: он **несёт звёздное яйцо**, одно за ивент на сервер. **Зона змея:** он выходит в одной случайной зоне за Поясом обломков (её называет анонс) и остаётся змеем этой зоны до конца охоты, куда бы его ни загнали: его ⚡ — ⚡ среднего стража этой зоны (`SerpentConfig.powerIn`), яйцо — грейда этого стража, бродит он по кольцу этой зоны (решение пользователя от 2026-11-05: скорость не меняется во время ивента). **Фаза 1:** змей бродит и убегает от ближайшего игрока со скоростью игрока со своей ⚡ — догонит тот, кто прокачан для зоны. **3 попадания по голове** на весь сервер (удар, гарпун, гравибомба; счётчик на метке) — яйцо вылетает. Правила PvP (новичок, перевес ⚡, щит) — про игроков, на змея не действуют. **Звёздное яйцо:** грейд среднего (3-го) стража зоны змея; редкость — по добыче зоны, но не ниже Редкой; удача +0,7 сверх своей. **Фаза 2:** змей сторожит яйцо, как страж: висит над выпавшим, гонится за носителем по формуле стражей и ловит (яйцо выпадает); метка ведёт к яйцу, другие игроки могут отбить его PvP. **Конец:** яйцо доставлено — анонс, змей уходит, ивент кончается досрочно; время вышло — змей уходит, яйцо в нём уходит с ним, выпавшее ещё 30 секунд лежит без охраны (`STAR_EGG_LINGER_SECONDS`; кто успел — тот и взял, решение пользователя после плейтеста: выбивание в последнюю секунду не пропадает), потом исчезает, яйцо в руках остаётся у игрока. Удачи всем яйцам, доставленным в охоту, больше нет. Своё «место» звёздного яйца — дом яйца `StarSerpent` (`Domain/EggHomes`) рядом с гнёздами: по нему `CarryService` узнаёт грейд, куда вернуть и кому сказать о доставке. План — [plans/STAR_SERPENT.md](plans/STAR_SERPENT.md).
**Почему:** на плейтесте версия 1 оказалась странной (пользователь): только наказание, непонятно, куда лететь, один змей на огромной карте почти не встречается, и это повтор стража. Охота на змея — одна цель на весь сервер, PvP вокруг неё, и награда видна сразу. Змей-сторож нужен, чтобы на сервере с одним игроком яйцо не было подарком без риска (решение пользователя).
**Отброшено:** змей кружит у Пояса обломков и стережёт дорогу домой; змей сам несётся к тому, кто взял яйцо; несколько змеев; змей разоряет гнёзда; один удар на выбивание (слишком просто); змей исчезает сразу после выбивания (на сервере с одним игроком — подарок); новый вариант пришельцев «звёздные» (большая отдельная работа, можно позже).

### 056. Джетпак: две модели у каждого, 21 уровень до ×2048
**Дата:** 2026-11-05
**Решение:** у джетпаков 1–10 по две модели (I, II): модель I удваивает множитель модели I предыдущего джетпака, модель II — ×1,5 к ней, так что множители читаются ×2, ×3, ×4, ×6, ×8, ×12 … ×1536; последний джетпак — Бесконечность ×2048, одна модель, выше уровней нет. После Антиматерии — четыре новых джетпака: Сингулярность, Гиперпривод, Червоточина, Бесконечность (названия — решение пользователя). Всего 21 покупка вместо 7 названных уровней и бесконечных «Антиматерия +1, +2» за ними. Цена — по множителю, а не по номеру уровня: каждое удвоение дороже в 10 раз, как раньше каждый уровень (×2 — 2000, ×4 — 20K, ×8 — 200K), промежуточная модель — пропорционально (×3 — 7,7K); цены округлены до двух значащих цифр (`Domain/Upgrades`: `jetpackModel`, `jetpackMultiplier`, `jetpackPrice`, `jetpackMaxLevel`). Покупка выше потолка — отказ `JetpackTop`. Профиль v12: старый уровень L (×2^L) — новый 2L−1, не выше 21. Вид меняется с джетпаком (обе модели одного джетпака выглядят одинаково; новые четыре — заготовки цветом).
**Почему:** на плейтесте за 10 минут было куплено 3 уровня из 7 названных — «маловато до конца игры»; ×1,26 за уровень плохо читается, а ряд ×2, ×3, ×4, ×6 — понятные числа (пользователь). Потолок ×128 (последний названный уровень) резал позднюю игру: баланс всегда считался с бесконечными «+N», и к 60-му дню калькулятор доходил до ×2048 (старый уровень 11) — его и сделали честным финалом.
**Баланс:** по `lune run balance` 24-й страж бесплатному игроку — на 48-й день (было ~48), игроку с геймпассом и набором — на 22-й (было 22); стражи 21–23 — на 5–15 % раньше (модели ×1,5 покупаются до полного удвоения), в пределах 10–15 % этапа 7.
**Отброшено:** ×1,26 за уровень (три модели на джетпак, та же кривая) — тяжело читается; потолок ×128 — поздняя игра встаёт (24-й страж не достижим за 60 дней), а компенсация тренажёром сдвигает середину игры; бесконечные «+N» без названий.

### 057. Гнёзда: у каждого стража зоны своё кольцо
**Дата:** 2026-11-05
**Решение:** кольцо зоны делится на 6 узких колец, по одному на пост: первый страж зоны — внутреннее, шестой — внешнее. Гнёзда поста стоят на своём кольце через равные углы с небольшим разбросом, кольца повёрнуты друг относительно друга на золотой угол, чтобы гнёзда соседних постов не выстраивались лучом (`Domain/NestLayout`). Пост гнезда задаёт раскладка (`NestSite.post`), а не ранг расстояния (`Domain/Posts` удалён). Гнёзд больше: на пост 4 / 5 / 6 / 7 по зонам — 24 / 30 / 36 / 42 вместо 14 / 20 / 25 / 32 (у каждого гнезда свой страж). Таблички стражей по-прежнему видны издалека (`ZoneLooks.GUARDIAN_SIGN_DISTANCE`, решение пользователя).
**Почему:** раньше расстояние гнезда от станции было случайным во всей ширине кольца, а пост — по рангу расстояния, так что соседние по кругу гнёзда оказывались первым и шестым постом зоны (разница в силе до 243 раз): «в одном месте гнёзда от невообразимо далёких по уровню до самых бесполезных» (пользователь). Теперь рядом с игроком гнёзда одного уровня, а дальше от станции — сильнее, шаг за шагом. 2–5 гнёзд на пост — мало (пользователь).
**Отброшено:** пост по сектору круга (сила зависела бы от направления, а не от расстояния); таблички ближе.

### 058. Места в инкубаторе и очередь яиц
**Дата:** 2026-11-06
**Решение:** в инкубаторе ограниченное число мест: у нового игрока 2, остальные покупаются за монеты, до 12 (робуксы — на этапе 8). Яйцо, доставленное в полный инкубатор, ложится на платформу отсека рядом с инкубатором и ждёт в очереди (не греется); освободилось место — первое из ждущих само переходит в инкубатор и начинает греться с момента освобождения (так и вне игры). Ничего не пропадает. Солнечная буря ускоряет только яйца на местах. Цена места растёт с каждым; первые дешёвые (подбор — `lune run balance`). Профиль v13: `incubatorSlots`, очередь `waiting` (яйцо с выпавшей длительностью `hatchSeconds` вместо `hatchAt`); старые профили не переносятся бережно — игра не в продакшене (пользователь), миграция только заводит поля. План — [plans/INCUBATOR.md](plans/INCUBATOR.md).

**Отброшено:** лишние яйца пропадают или не принимаются при доставке; очередь, которая греется (места теряют смысл); выбор игроком, какое яйцо греть первым (позже, если попросят).

### 059. Яйцо вылупляет игрок
**Дата:** 2026-11-06
**Решение:** меняет решение 058 в одном: яйцо, у которого вышло время, само не вылупляется. Оно становится **готовым** — над ним «Готово!» вместо таймера — и держит своё место, пока игрок его не вылупит. Вылупить можно только подсказкой «Вылупить» у самого яйца, в своём отсеке (сервер проверяет хозяина и расстояние, как у «Подобрать»); кнопки «Вылупить все» и вылупления из окна отсека нет (решения пользователя). Вылупил — пришелец идёт как раньше (капсула, инвентарь, пол), а на место сразу встаёт первое яйцо из очереди и греется **с этой минуты**. Вне игры яйца на местах дозревают и ждут игрока, очередь стоит. Солнечная буря ускоряет только недозревшие. На экране «С возвращением!» — сколько яиц готово. `HatchNow` делает яйца готовыми, а не вылупляет. План — [plans/INCUBATOR.md](plans/INCUBATOR.md).
**Почему:** вылупление — отдельное действие и маленький праздник, а не тост где-то в космосе (пользователь). Места начинают ощущаться: вне игры каждое место — ещё одно готовое яйцо к возвращению, а в игре готовое яйцо, которое не вылупили, задерживает очередь. Калькулятор показал, что при вылуплении само собой места почти не влияют на темп: очередь вылуплялась за ночь.
**Цены мест:** каждое следующее в 30 раз дороже (150, 4,5K, 135K, 4M, 121M, 3,6B, 109B, 3,3T, 98T, 2,95Qa) вместо ×3: доход растёт быстрее любой цены, и при ×3 к 7-му дню место стоило секунды дохода (решение пользователя — «круче геометрия»). По `lune run balance` бесплатный игрок берёт 3-е и 4-е место в первый час, 5-е и 6-е — в первую неделю, 7-е и 8-е — к третьей; дальше места модели не нужны, а стоят часы и дни дохода — для тех, кто крадёт быстрее модели, и для робуксов (этап 8). Темп не изменился: 24-й страж на 49-й день (было 48). Калькулятор вылупляет готовые яйца только в отсеке: в начале сессии и при каждой доставке.
**Отброшено:** цена в минутах текущего дохода (дорожает от каждого нового пришельца); вылупление само собой с остановкой очереди вне игры (тот же эффект без действия игрока); «Вылупить все» и вылупление из окна отсека из любой точки карты (отсек нужен реже).

### 060. Щита нет
**Дата:** 2026-11-06
**Решение:** способность «щит» (6 с неуязвимости, перезарядка 30 с, решение 033) убрана из игры: из правил PvP (`Domain/Pvp`, отказ `VictimShielded`), ввода (клавиша R / L2), HUD, тостов, сети и эффектов. Защита от атак — только скорость (вор с яйцом тяжелее) и правила честности: новичок, 10 с после респауна, перевес ⚡ в 10 раз, купол. Щит не продаётся и за робуксы.
**Почему:** щит делает PvP бессмысленным (пользователь): вор включает его, когда к нему подлетают, и любая атака уходит в пустоту. Продавать его за робуксы — тем более покупка неуязвимости.
**Отброшено:** щит за робуксы (перезарядка сейчас, защита на N минут); щит слабее или с долгой перезарядкой.

### 061. Каталог покупок за робуксы
**Дата:** 2026-11-06
**Решение:** покупки за робуксы только ускоряют то, что есть в игре и так; ничего случайного, цена и награда видны до покупки. **Пропуски:** «Двойная тренировка» — ×2 к прибавке тренажёра, вне игры тоже (299 R$); «Ночная смена» — вне игры доход 12 ч вместо 4, тренировка 24 ч вместо 8 (149 R$; потолки изменены решением 062: 8 ч и 16 ч). **Покупки:** час / 8 часов / сутки тренировки — ⚡ = прибавка тренажёра × время, число видно до покупки (25 / 99 / 249 R$, решение 024); «Яйцо готово сейчас» — одно яйцо на месте сразу готово, вылупляет игрок (3–20 R$: ступень = номер зоны стража яйца 0–3 + номер редкости 0–4, 8 ступеней 3 / 4 / 5 / 7 / 9 / 12 / 16 / 20); место в инкубаторе за робуксы по одному, вместо монет (3–6-е — 19, 7–9-е — 49, 10–12-е — 99 R$); «Забрать ×2» на экране возвращения — ещё раз столько же монет и ⚡ (29 R$). У покупки в Roblox одна цена, поэтому ступени — отдельные покупки с одним названием; какую показать, решает игра. Цены задаются в Creator Hub, игра показывает те, что вернёт Roblox. ID — по игре (`game.GameId`): у Dev и Prod (решение 011) свои; в неизвестной игре покупки выключены. Список с текстами — [plans/STAGE_8.md](plans/STAGE_8.md). **Покупка не теряется:** у покупки Roblox нет параметров, а чек может прийти и после перезахода, поэтому «Яйцо готово сейчас» применяется к выбранному яйцу, а если его уже нет — к греющемуся яйцу той же ступени или ниже, у которого дольше всего осталось; место за робуксы — следующее; если применить не к чему (яйца вылупились, все места уже куплены), игрок получает 30 минут своего дохода монетами (не меньше 100). Пакет тренировки считается по прибавке тренажёра с пропусками.
**Почему:** решения пользователя от 2026-11-06: каталог из четырёх групп; места — по одному; «готово сейчас» — по грейду и редкости, недорого (от 3 до 20); цены пропусков и пакетов — как предложено. Ступени вместо формулы: Roblox не даёт менять цену покупки из игры.
**Отброшено:** пропуск «Большой инкубатор» (+2 места или последние места только за робуксы); щит (решение 060); «готово сейчас» для всех яиц разом (цена зависит от яйца); VIP-скафандр сейчас (это внешний вид — к полировке).

### 062. «Ночная смена» удваивает потолки, а не утраивает
**Дата:** 2026-11-06
**Решение:** с «Ночной сменой» вне игры капсулы приносят монеты 8 часов вместо 4, тренажёр качает 16 часов вместо 8 (было в решении 061: 12 и 24). Цены пропусков прежние: «Ночная смена» 149 R$, «Двойная тренировка» 299 R$.
**Почему:** калькулятор баланса с пропусками (`lune run balance`, профили по пропускам): с потолками 12 / 24 «Ночная смена» за 149 R$ ускоряла путь до Кита в 2 раза, сильнее «Двойной тренировки» за 299 R$ (в 1,5 раза), а оба пропуска вместе — в 2,8 раза при цели GAME_DESIGN 1,5–2. С 8 / 16 каждый пропуск ускоряет примерно в 1,5 раза (49 дней → 33 и 32), оба — в 2,3 (22 дня). Решение пользователя от 2026-11-06.
**Отброшено:** оставить 12 / 24 и принять 2,8 раза; 8 / 12 (тренировка вне игры почти не растёт, пропуск ощущается слабо); поменять цены пропусков местами.

### 063. «Яйцо готово сейчас» — у самого яйца, и оно сразу вылупляется
**Дата:** 2026-11-06
**Решение:** пока яйцо греется, на нём подсказка «Вылупить за 6 R$» (только для хозяина отсека) с ценой ступени именно этого яйца; нажал — окно покупки Roblox для этого яйца. Это единственное место, где «готово сейчас» продаётся: кнопки «Готово за … R$» в окне отсека и строки в магазине нет (решение пользователя). Покупка для выбранного яйца вылупляет его сразу; чек, пришедший позже (после перезахода), или покупка без выбранного яйца по-прежнему только делают яйцо готовым (решение 061). Цены за робуксы клиент спрашивает у Roblox заново, когда они появляются на экране (окно отсека, магазин, экран возвращения, подсказка у яйца), не чаще раза в 30 с.
**Почему:** пользователь: строка «Готово за 3 R$» не говорит, за что именно платишь; покупка должна быть на самом яйце, с его ценой. Managed Pricing меняет цены во время игры: цена места, прочитанная при входе (14), разошлась с окном покупки (19) — игрок видит обман.
**Отброшено:** только «готово» после покупки и ещё одно нажатие E (покупка «вылупить» должна вылуплять); оставить и кнопки в окне отсека, и строку в магазине (там снова неясно, какое яйцо покупаешь).

### 064. «Забрать ×2» — цена по размеру награды, от 1 до 20 R$
**Дата:** 2026-11-06
**Решение:** у «Забрать ×2» 8 ступеней по монетам, которые принесло время без тебя (доход × время, уже с потолком): до 1M — 1 R$, до 10M — 2, до 100M — 3, до 1B — 5, до 10B — 7, до 100B — 10, до 1T — 15, от 1T — 20 (`MonetizationConfig.DOUBLE_TIER_LIMITS`, `Purchases.doubleTier`). Ступень считает сервер при расчёте награды и шлёт с ней (`OfflineReward.doubleTier`); пока экран открыт, цена не меняется. Чек ступени ниже, чем у награды (старый экран или покупка не с экрана), платит только до предела своей ступени, и ⚡ — в той же доле. По калькулятору после 4 часов без игры: первые часы — 1–2 R$, день 1 — 3–5 R$, неделя — 10 R$, месяц и дальше — 15–20 R$ (`lune run balance`, колонка `x2 tier`). Заменяет одну цену 29 R$ из решения 061.
**Почему:** пользователь: в начале ×2 должно стоить копейки, к концу — дороже; цена — по доходу × время, от 1 до 20 R$ («пусть детишки радуются»). Только по доходу короткое отсутствие на позднем этапе стоило бы дорого за маленькую добавку.
**Отброшено:** цена по времени отсутствия (не растёт с игрой); только по доходу в секунду; одна цена для всех.

### 065. Туториал: пять шагов основного цикла, без кнопки «Пропустить»
**Дата:** 2026-11-06
**Решение:** новичка ведёт одна строка подсказки внизу экрана и метка на цели (как маяк станции): укради яйцо у стража 1 → неси на станцию → вылупи → накачай ⚡ на тренажёре до рекомендации стража 2 → укради у стража 2 (или дальше) → «Дальше сам» с указанием на цель в HUD. Сначала кража: стартовой ⚡ 10 хватает на стража 1. Первое доставленное в туториале яйцо готово за 10 с (`TutorialConfig.FIRST_EGG_SECONDS`). Профиль хранит пройденные вехи (`tutorialStep`, v15: доставил, вылупил, натренировал, украл у сильного), подсказка выводится из вех и того, несёт ли игрок яйцо (`Domain/Tutorial`): выбили яйцо, кончился кислород, буря — подсказка сама возвращается к «укради». Шаг, уже сделанный раньше, пропускается. Ничего не блокируется, кнопки «Пропустить» нет; шага «купи улучшение» нет (первое улучшение — минуты ожидания дохода); буря и метеоры идут как обычно. Воронка `Tutorial` в аналитике. Профили, уже доставлявшие от стража 2 и дальше, считаются прошедшими. Вид панели и меток — грейбокс до полировки.
**Почему:** решения пользователя от 2026-11-06 («все по предложению»): обучать действием, а не текстом; первые минуты — самое интересное (кража), а не ожидание.
**Отброшено:** сначала тренажёр; кнопка или крестик «Пропустить»; шаг «купи улучшение»; пауза бури для новичков; шаги по нажатым кнопкам вместо состояния игрока.

### 066. Интерфейс: неоновое стекло и брифы экранов до кода
**Дата:** 2026-11-07
**Решение:** стиль интерфейса — «Б1 спокойный»: полупрозрачное тёмное стекло, у каждой кнопки свой цвет с мягким свечением, двухцветные иконки без подписей, шрифт Nunito Heavy, редкость — цвет обводки. Общие правила (цвета, шрифт, размеры, компоненты, раскладка экрана) — в `docs/design/DESIGN.md`. Каждый экран сначала описывается брифом `docs/design/screens/<экран>.md`: раскладка на телефоне, планшете и ПК, все состояния (обычное, пустое, загрузка, ошибка, закрыто), поведение, тексты, открытые вопросы. Код экрана пишется только по брифу со статусом `approved` (после слова пользователя). HTML-макеты лежат рядом, в `docs/design/mockups/`. Порядок экранов: HUD → окно отсека → магазин джетпаков → задания и подарок → индекс → магазин и экран возвращения → туториал.
**Почему:** пользователь выбрал стиль по HTML-макетам: полупрозрачность меньше мешает искать яйца на телефоне, яркий неон напрягал глаза. Порядок «бриф → утверждение → код» и обязательные состояния взяты из скилла `roblox-ui-implementation` (AshExplained/roblox-skills) по просьбе пользователя: без брифа экраны делаются только в счастливом состоянии и разъезжаются по стилю.
**Отброшено:** «Конфетный» (светлые окна сильнее закрывают космос), «Мультяшный sci-fi», яркий Б1 (напрягает глаза), Б2 «Цветное стекло»; Fredoka One (нет кириллицы в Roblox, буквы подменяются); код экранов без брифа.

### 067. Монеты и ⚡ — иконкой везде, и в текстах
**Дата:** 2026-11-07
**Решение:** сумма монет или ⚡ всегда показывается иконкой перед числом — в HUD, окнах, тостах, табличках в мире, на кнопках и на доске монет. В строках локализации знак `●` (монеты) или `⚡` стоит прямо перед числом («Награда: ●+12K и ⚡+3.4K»); `Locale/Marks.split` режет строку на слова и знаки, `UI/IconText` рисует знаки иконками `Coin` и `Bolt` в цвете ресурса. Его используют `ActionButton`, `Button`, `Toasts`, `WorldLabel`, `CoinBoard`, `WelcomeBack`, магазин джетпаков. Строка со знаками не переносится; предложение на экране возвращения больше не повторяет суммы (они крупно над ним). Слово «монеты» осталось только там, где нет числа. Иконки монеты и молнии перерисованы потолще (на монете — крупный знак $, пользователь), чтобы читаться мелко у числа. Исключение — колонка `●` в списке игроков Roblox: там картинку не поставить.
**Почему:** пользователь: монеты везде должны быть одной иконкой, а в текстах они были словом («монет») или знаком ● шрифта; молния в тексте тоже была знаком шрифта, а рядом с числами в окнах — иконкой.
**Дополнено (2026-11-07, бриф магазина):** цена в робуксах — так же, знак `R$` перед числом рисуется иконкой `Robux` (решение пользователя).
**Отброшено:** слово «монет» в тостах; знак ● шрифта; разметка вида `{coin}` (это переменная, а знак в строке понятен и переводчику, и проверке длины).
