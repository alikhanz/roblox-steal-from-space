### 001. Код только в файлах, синхронизация через Rojo
**Дата:** 2026-11-02
**Решение:** весь код, конфиги и UI живут в Git и синхронизируются в Studio через Rojo. Studio — для запуска и тестов. Модели из Studio забираются в файлы (`rojo syncback` или экспорт в `assets/`).
**Почему:** двоичный `.rbxl` нельзя нормально хранить в Git и сливать. Правки в Studio при подключённом Rojo перетираются.

### 002. Одна команда проверки, без CI
**Дата:** 2026-11-02
**Решение:** `lune run check` (формат, линтер, типы, тесты, сборка) запускается локально перед каждым коммитом. CI не используем.
**Почему:** разработчик один, всё можно проверить на этой машине. Если появится команда, CI будет запускать ту же команду.

### 003. Без фреймворков, свой минимальный загрузчик
**Дата:** 2026-11-02
**Решение:** один скрипт на сервере и один на клиенте, сервисы с фазами `init`/`start`, явные зависимости.
**Отброшено:** Knit — архивирован в 2024 году.

### 004. Сеть — Zap
**Дата:** 2026-11-02
**Решение:** все remotes описываются в `net/remotes.zap`, код генерирует Zap (buffer-сериализация, типы).
**Отброшено:** Blink — примерно равен по скорости, у Zap лучше документация и шире сообщество. Голые `RemoteEvent` — нет типов, лишний трафик.

### 005. Данные на клиент — свой тонкий слой на Zap
**Дата:** 2026-11-02
**Решение:** снимок при входе + дельты через Zap, на клиенте — состояния Vide.
**Отброшено:** Replica — готова, но использует свои remotes в обход Zap. Хотим всю сеть в одном типизированном месте.

### 006. UI — Vide
**Дата:** 2026-11-02
**Решение:** Vide (`centau/vide`).
**Почему:** точечная реактивность — обновляется только изменившееся свойство. У нас много часто меняющихся чисел (доход, кислород, таймеры), важна производительность на телефонах.
**Отброшено:** React-lua — зрелее, но перерисовывает компоненты целиком.

### 007. Зависимости — Wally + wally-package-types

### 008. Данные игрока — ProfileStore
**Дата:** 2026-11-02
**Решение:** `lm-loleris/profilestore` (официальный пакет автора).
**Почему:** блокировка сессии, автосохранение, корректное завершение. Сырой DataStore без этого теряет и дюпает данные.

### 009. Большие числа — свой BigNum
**Дата:** 2026-11-02

**Отброшено:** EternityNum 2 — есть жалобы на округление, избыточна. GammaNum — новая, бенчмарки только от автора.

### 017. Локализация — свой модуль строк, а не LocalizationTable
**Дата:** 2026-11-02
**Решение:** строки в `src/shared/Locale/Strings.luau`, доступ через `Text.get` с типизированным ключом. Формы множественного числа и подстановки — свои.
**Почему:** строки проверяются в Lune (длина, стоп-лист, формы, подстановки), опечатка в ключе ловится проверкой типов, поведение одинаково на сервере, клиенте и в тестах.
**Отброшено:** `LocalizationTable` + `Translator` — нельзя проверить вне Roblox, нет русских форм множественного числа. Автоперевод на другие языки не нужен: поддерживаем только русский и английский.

### 018. Чистые серверные модули получают зависимости параметрами
**Дата:** 2026-11-02
**Решение:** логика сервера без Roblox API (например, `SessionManager`) не делает `require` модулей из `ReplicatedStorage`; хранилище, схему данных, часы ей передаёт сервис.
**Почему:** строковый `require` между `ServerScriptService` и `ReplicatedStorage` в Roblox не работает, а `require` через инстансы не работает в Lune. Параметры решают и это, и тестируемость (поддельное хранилище в тестах).

### 019. Server Authority — берём
**Дата:** 2026-11-02
**Решение:** движение игроков работает под Server Authority (`Workspace.AuthorityMode = Server`). Логика полёта — общий модуль, привязанный через `RunService:BindToSimulation`, запускается и на сервере, и на клиенте.
**Что проверили экспериментом (ветка `spike/server-authority`):**
- Полёт на `LinearVelocity` + `AlignOrientation` работает: сервер считает, клиент предсказывает (`PredictionStatus.Predicted`).
- Сервер видит ввод: свои `InputAction` (контекст под `Player`) и стандартный `Humanoid.MoveDirection`.
- Попытка читерства на клиенте (телепорт на 500 studs, скорость 2000) откатывается движком за долю секунды; позиция на сервере не меняется. Свой античит для движения не нужен.
- Переход полёт → ходьба (`Physics` → `Freefall` → `Running`) работает.
**Ограничения, которые учитываем:**
- `AuthorityMode` и связанные свойства не читаются и не пишутся из скриптов и MCP — включаются в Properties вручную (один раз на плейс).
- Внутри симуляции только API с Simulation Access, состояние — в атрибутах, ввод — опросом `GetState()` (события `Pressed` ненадёжны при откатах), объекты создаются и удаляются вне симуляции.
- Плавность при реальном пинге ещё не проверена: режим Play в Studio запускает сервер и клиент в одном процессе. Проверяем на опубликованной Dev-игре.
- Производительность сервера при 20+ игроках у Roblox ещё «требует работы» — замеряем на нагрузочном тесте (этап 8).
**Отброшено:** клиент владеет физикой + серверная проверка скорости — больше кода, хуже защита.

### 020. Управление полётом
**Дата:** 2026-11-02
**Решение:** джетпак включается сам за куполом станции (под куполом — гравитация и ходьба). В космосе летишь туда, куда смотрит камера (вперёд/назад/вбок — стандартное управление движением), плюс «вверх/вниз»: Space/Ctrl на ПК, R1/L1 на геймпаде, кнопки ▲▼ на телефоне.
**Почему:** без лишней кнопки включения, понятно детям и удобно на телефоне.
**Отброшено:** включение кнопкой; горизонтальный полёт только с отдельными кнопками высоты — больше кнопок на телефоне.

### 021. Джетпак и поза полёта
**Дата:** 2026-11-03
**Решение:** модель джетпака собирается кодом (`src/server/Character/JetpackModel.luau`) и приваривается к персонажу: баллоны на спине, джойстики в руках, шланги-`Beam`. Поза полёта — настоящая анимация, описанная данными (`FlightPose`), загружается на аккаунт и запускается внутри `SpaceSimulation`. Наклон корпуса по скорости — через `AlignOrientation` (`FlightLean`). Пламя — клиентские частицы.
**Почему:** под Server Authority анимации персонажа, запущенные вне симуляции, откатываются; переопределение суставов скриптом не доживает до физики (суставы — `AnimationConstraint`); временные анимации Studio персонаж игрока не играет. Поза как данные — в Git, правится и проверяется.
**Отброшено:** процедурная поза через `Transform` суставов — не работает с новыми суставами; готовые анимации Roblox — нет позы «держит джетпак».

### 022. 8 игроков на сервер, вход к другу обязателен
**Дата:** 2026-11-03
**Решение:** максимум 8 игроков на сервер (`ServerConfig.MAX_PLAYERS`, на станции 8 отсеков). Вход к другу (кнопка Join в профиле) обязателен: при публикации включить его и зарезервировать места для друзей (Game Settings → Places → Customize reserved slots). Распределение по серверам — штатное, Roblox.
**Почему:** у каждого игрока свой отсек; на 8 игроках засады и кражи живые, но новички успевают донести добычу; запас по производительности Server Authority; так же устроены похожие игры жанра.
**Отброшено:** 12–20 игроков — хаос в кражах, тяжелее для сервера, станция на 20 отсеков слишком большая.

### 023. Тревога без шума, захват с подсказкой
**Дата:** 2026-11-03
**Решение:** шума и шкалы тревоги нет. Страж спит, пока яйцо в гнезде; когда яйцо взяли, он просыпается через `aggroDelaySeconds` (около секунды) и гонится за тем, у кого яйцо. Захват — удержание E 2 / 2,5 / 3 с (обычное / необычное / редкое). Над ближайшим яйцом — подсказка с клавишей и полоска прогресса; на телефоне подсказку нажимают и держат (локальная привязка `UIButton` к тому же действию `Grab`), на геймпаде — X.
**Почему:** правило «взял — за тобой гонятся» понятно детям сразу; шкала шума наказывала за подлёт, который не видно и не объяснить. Секунда форы даёт начать побег. Подсказка над яйцом на телефоне не требует отдельной кнопки на экране.
**Отброшено:** шкала тревоги от шума джетпака и захвата — непрозрачно и спорит с полётом на полной скорости; короткий захват 0,5–1,5 с — кража слишком лёгкая.

### 024. Скорость — единственная характеристика, погоня по отношению скоростей
**Дата:** 2026-11-03
**Решение:**
- У игрока одна характеристика — **скорость ⚡** (`BigNum`, до сотен миллиардов): натренированное × множитель джетпака. Сила и запас кислорода как характеристики убраны.
- Скорость полёта (studs/s) — логарифм от ⚡. Исход погони решает **отношение** ⚡ стража к скорости вора с яйцом: скорость полёта стража = скорость полёта вора × отношение^0,5, в пределах 0,6–1,5.
- Над стражем — рекомендуемая скорость (для среднего яйца). Скорость с яйцом игроку не показываем.
- Стражи ведут себя одинаково (спят → через секунду после кражи гонятся напрямую → домой) и отличаются видом и скоростью. Плевки Слизня и рывки Краба из старого плана отброшены.
- Пойманный роняет яйцо, оно лежит на месте; подобрать может любой; нетронутое 3 минуты — возвращается в гнездо. Подобранное снова будит своего стража.
- Кислород — время полёта (~3 минуты), не прокачивается. У карты жёсткая граница внутри симуляции.
- Темп и экономика подбираются калькулятором баланса по конфигам. За робуксы продаём очки скорости — конкретное число; размер пакета привязан к текущей прибавке тренажёра, чтобы он не обесценивался.
**Почему:** игроку всегда ясно, чего не хватает, — скорости; это мотивирует качаться дальше. Отношение вместо абсолютных чисел даёт одинаковое ощущение погони на любом этапе и не ломает физику. Рекомендация без точного расчёта оставляет азарт.
**Отброшено:** отдельное поведение и навыки уворота для каждого стража — сложнее понять, чего не хватило; несколько характеристик (мощность, кислород, сила); физическая скорость, равная ⚡; подсказка «нужно ⚡ N» над каждым яйцом и показ скорости с яйцом — раскрывает точную цель прокачки.

### 025. Магнитный захват и удар стража
**Дата:** 2026-11-03
**Решение:** пока игрок держит захват рядом с яйцом, джетпак гасит дрейф и подтягивает его к яйцу (`Grab.magnetVelocity`, внутри симуляции). Поимка — «удар»: рывок стража, вора отбрасывает и закручивает на 1,2 с без управления (кувырок через `AlignOrientation`, угол — предсказываемый атрибут), двигатель глохнет и заводится вспышкой, красная вспышка и «Поймали!» на экране, тряска камеры; яйцо отлетает в сторону со следом. Признак стана — наличие атрибутов `HitVelocity`/`HitAxis`, которые сервер снимает по таймеру: часы сервера и клиента сравнивать не нужно.
**Почему:** в невесомости яйцо уплывало из рук в момент захвата — на телефоне это главный раздражитель, а «прилипание» ощущается как фишка. Поимка без обратной связи не читалась; «упасть» в космосе — значит потерять контроль над телом.
**Отброшено:** оставить дрейф как навык; `HitUntil` по `time()` — на сервере и клиенте это разные часы; звук удара — ждёт ассета.

### 026. Отсек: капсулы для пришельцев, инкубатор без лимита, пол и инвентарь
**Дата:** 2026-11-03
**Решение:**
- Капсула — место для пришельца, а не для яйца. Новичку 3 капсулы, дальше за монеты.
- Каждое доставленное яйцо вылупляется: лежит в инкубаторе отсека без ограничения на число, время случайное в диапазоне редкости (обычное 30 с – 10 мин, самые редкие яйца игры — до 5 ч), идёт офлайн по unix-времени сервера.
- У каждого стража свой набор (грейд) из 5 ступеней с названиями редкостей; доход ступеней ×1/×2/×5/×15/×50, набор следующего стража ×1,8. Удача яйца (редкость + размер) умножает вес ступени на (1 + удача)^(номер − 1).
- Вылупившийся идёт в свободную капсулу, иначе на пол отсека; с пола поднимается в инвентарь (10 мест); полный инвентарь — лежит на полу, хранится в профиле. Кнопка «Лучших — в капсулы» расставляет по доходу.
- Скрещивание 3 → 1 одного грейда: не ниже худшего из трёх, удача 0,5. Продажа — 2 минуты дохода пришельца.
- Пришельцы и яйца адресуются `uid` из счётчика профиля.
- `PlayerData.template`/`load` получают стартовые значения (`Defaults`) от `DataService`; домен конфигов не читает.
**Почему:** игрок должен вырастить каждое украденное яйцо — «яйцо пропало, нет места» убивает смысл кражи; капсулы как ограничение дохода дают повод их покупать; разброс времени не даёт яйцам вылупляться пачкой. Удача как множитель по ступеням оставляет шанс верхней ступени любому яйцу, а значит и азарт.
**Отброшено:** капсулы как место вылупления с лимитом яиц; яйцо без места остаётся в руках; хранение пришельцев по индексу (сдвигается, не переживёт мутации); чтение конфигов из домена (нетестируемо в Lune).

### 027. Конфиги: числа отдельно от внешнего вида; калькулятор баланса
**Дата:** 2026-11-03
**Решение:** конфиги с числами (`EggConfig`, `GuardianConfig`, `AlienConfig`, `BayConfig`, `UpgradeConfig`, `SpeedConfig`) — чистый Luau без `Color3`/`Vector3`/`Enum`; внешний вид живёт в `EggLooks` и `GuardianLooks`. Кросс-ссылки конфигов проверяются тестом `tests/Config/Configs.spec.luau`. Калькулятор `lune run balance` симулирует игрока по дням на настоящих конфигах и доменном коде (вылупление, капсулы, покупки) для трёх профилей; таблица темпа в GAME_DESIGN — его вывод. Подобранные им цифры: тренажёр 300 монет ×5, джетпак 2 000 ×8, доход наборов ×1,7 за стража.
**Почему:** глобалы Roblox в Lune не существуют и в модули не пробрасываются (проверено: `_G` не разделяется), поэтому конфиг с `Color3` нельзя ни проверить тестом, ни скормить калькулятору. Темп на реальных шансах и капсулах оказался вдвое быстрее согласованного — цены и рост дохода подобраны обратно к таблице.
**Отброшено:** подстановка глобалов в Lune; дублирование чисел в калькуляторе.

### 028. Репликация профиля по разделам, команды через одну калитку
**Дата:** 2026-11-03
**Решение:** клиент получает `ProfileSnapshot` при активации профиля (и по своему запросу `RequestSnapshot`), дальше — дельты по разделам: монеты отдельным событием раз в секунду, отсек целиком (`BayChanged`) после каждой перестройки. Все команды клиента проходят `NetService.guarded`: общий лимит частоты на игрока (5 в секунду) → активный профиль → `EconomyService`, который проверяет запрос на живом профиле и применяет одно изменение. Отказ — событие `NoticeSent` с причиной из перечисления Zap.
**Почему:** отсек — до 12 капсул, 10 мест инвентаря и несколько яиц; дельта «добавлен X / убран Y» для такого объёма даёт больше кода и больше способов разойтись с профилем, чем экономит трафика. Раздел целиком — всё ещё дельта относительно всего профиля (⚡ идёт атрибутами, служебные поля не уходят). Одна калитка для всех команд — один набор проверок, который нельзя забыть.
**Отброшено:** `RemoteFunction` для команд (ответ клиенту не нужен — он получит дельту); репликация через атрибуты игрока (инвентарь — приватные данные, атрибуты видны всем).

### 029. Прокачка: тренажёр в отсеке, улучшение на месте, джетпаки в магазине
**Дата:** 2026-11-03
**Решение:** у каждого игрока свой тренажёр в отсеке; качает только хозяина и только пока он стоит на площадке. Улучшение тренажёра покупается на месте (подсказка у площадки с ценой). Джетпаки продаются в одном магазине на станции; каждый уровень — ×2 к ⚡ и новый вид (цвет корпуса, цвет и сила огня). В профиле хранятся `trained`, `trainerLevel`, `jetpackLevel` (v3); формулы — в чистом `Domain/Upgrades`, числа — `UpgradeConfig.TUNING` того же типа, калькулятор баланса считает теми же функциями.
**Почему:** свой тренажёр — отсек становится местом, куда возвращаешься, а не только складом; «встал — качаешься» понятно без слов, и АФК-кач выглядит как игрок у себя дома. Магазин для джетпаков — отдельная цель прогулки по станции и витрина, где видно, за что платишь: следующий джетпак должен выглядеть желаннее. Улучшение тренажёра в магазине не нужно — оно про прибавку, а не про вид.
**Отброшено:** один общий тренажёр на станции (не видно, чей прогресс); тренировка просто за нахождение на станции (нет действия); окно «Прокачка» в HUD с обеими покупками (улучшение джетпака без его вида — просто цифра).

### 030. Контент раньше PvP; у каждого поста свой именованный страж; карта 1600
**Дата:** 2026-11-03
**Решение:** этап 5 — контент (четыре зоны, 24 поста стражей, 24 грейда, все редкости яиц), PvP переносится на этап 6. Каждый из 24 постов — отдельный именованный страж (имена в глоссарии), при этом тел-видов шесть: посты одного вида отличаются цветом и размером. Граница карты раздвинута с 1000 до 1600 studs, зоны — кольцами 190–320 / 430–620 / 760–1020 / 1150–1450.
**Почему:** после этапа 4 прокачка работает, а качаться не к чему: три стража из 24 закрывают 30 минут игры. Полный мир нужен и для проверки баланса в игре, и как основа для PvP (которое тестируется с несколькими игроками и на пустой карте бессмысленно). Отдельные имена постов нужны, потому что пришелец называется по стражу: два поста одного вида давали бы одинаковые имена разным грейдам. Карта больше, чтобы дальние зоны ощущались далёкими даже на высокой скорости полёта; баллона (3 мин) хватает до края и обратно с запасом.
**Отброшено:** имена пришельцев по зоне и номеру («Редкий · Пояс 3») — безлико; 24 уникальных вида сразу — арт-работа не для грейбокса.

### 031. Быстрый старт прогрессии: тренажёр ×10 и чаще, стражи с убывающим шагом
**Дата:** 2026-11-03
**Решение:** тренажёр даёт 3 ⚡/с (было 0,3) и платит 4 раза в секунду (было раз в секунду); улучшение тренажёра ×1,5 (было ×1,6), цены ×6 и ×10 за уровень (были ×5 и ×8). Рекомендация стража k = 10 × ∏ шагов, шаг i = 4,2 × 0,97^(i−1) (было ровно ×3): первые стражи расходятся шире, последние — плотнее, 24-й по-прежнему около триллиона. Калькулятор: конец Пояса к 24-й минуте, 10-й страж на второй день, Кит на 53-й день (×2 — 42-й, с пакетами — 22-й).
**Почему:** на плейтесте начало ощущалось вялым: «+0,3» раз в секунду не читается как рост, а стражи ×3 шли слишком ровно. Детям нужны быстрые растущие цифры с первых секунд и заметный скачок на каждом новом страже; при этом горизонт удержания (недели до последнего стража) хотелось сохранить — его держат более дорогие улучшения и более плотные поздние стражи.
**Отброшено:** просто умножить тренажёр на 10 без правки стражей и цен — Кит падал на 17-й день.
**Дополнение (тот же день):** доход тоже должен расти с первых минут, а не после десятиминутного ожидания вылупления: обычные яйца 10 с – 2 мин (было 30 с – 10 мин), необычные 1–6 мин, редкие 5–30 мин, эпические 30 мин – 2 ч, легендарные 1,5–5 ч (потолок 5 ч сохранён); первая докупаемая капсула 100 монет (было 250), рост ×3. По калькулятору конец Пояса сдвинулся с 24-й на 18-ю минуту, поздняя игра не изменилась.

### 032. Радиус стриминга больше карты (радиусы увеличены в 041)
**Дата:** 2026-11-03
**Решение:** `StreamingMinRadius = 1024`, `StreamingTargetRadius = 2048` (карта — радиус 1600); записаны в `default.project.json` как документация и выставлены в плейсе вручную, как `AuthorityMode`: свойства Workspace плагин Rojo в открытый плейс не пишет. Выключить `StreamingEnabled` нельзя: под Server Authority Studio держит его включённым (запись игнорируется). Код по-прежнему пишется стриминг-безопасно (CONVENTIONS).
**Почему:** мир — около тысячи простых частей (станция, 320 астероидов, 48 гнёзд, 48 стражей, 440 частей ориентиров); с радиусом по умолчанию (1024) клиент сразу после входа получал ~905 из них, а дальние зоны подгружались кусками по мере полёта — это и выглядело как «медленная загрузка кусками». Память такого мира ничтожна даже для телефона, а полный радиус убирает подгрузку и даёт стражам дальних зон таблички сразу.
**Отброшено:** оставить как есть до этапа оптимизации — заметно портит первое впечатление.

### 033. PvP: удар, гарпун, бомба у всех сразу; яйцо выпадает на месте; правило 10×
**Дата:** 2026-11-04
**Решение:** три атаки на трёх дистанциях — удар (ЛКМ, выпад, перезарядка 1,5 с), гарпун (луч ~50 studs, 20 с), гравибомба (область ~25 studs, 45 с); защита — щит и рывок, без мини-игр (рывок снят в 034, щит — в 060). Любая атака делает с жертвой то же, что поимка стражем: яйцо выпадает на месте, подбирает кто успел. Способности у всех сразу, без магазина: сервер логирует использования, решение про магазин — по ним. Защита новичков 20 минут игрового времени (в обе стороны), 10 с после респауна, под куполом PvP нет, нельзя атаковать игрока с ⚡ в 10 раз меньше своей.
**Почему:** «подлетел — само выпало» ощущается как не действие; удар с замахом и выпадом — ближний бой, который видно и в который можно промахнуться. Выпадение на месте повторяет уже знакомое игроку поведение при поимке стражем и не создаёт второй механики передачи яйца. Магазин способностей рано: сначала надо увидеть, пользуются ли ими. Правило 10× — страховка от травли ради травли: денег сильному с яйца младшего грейда нет, а отнять «чтобы было» — есть.
**Отброшено:** перехват удержанием E у носителя (не ощущается как бой); мини-игра «вырвись» (лишняя сложность); дымовая вспышка (пока не нужна, вернёмся, если удар с гарпуном окажутся слишком сильными).

### 034. Рывок снят; страж сторожит яйцо, а не гнездо
**Дата:** 2026-11-04
**Решение:** способности «рывок» нет (действие, атрибут `DashUntil`, множитель в симуляции и кнопка удалены). Страж держит «дом» там, где лежит его яйцо: выпало при поимке или от удара — страж зависает над ним на месте падения, поводок 220 studs считается оттуда (поводок снят в 035); яйцо подобрали, пока страж ещё летит, — он разворачивается и гонится с текущей точки; яйцо вернулось в гнездо — вернулся и страж.
**Почему:** на плейтесте рывок (×2,2 на 0,8 с) давал игроку с ⚡ 12 увести яйцо у стража с миллионами ⚡ на одной секундной форе — вся прокачка скорости теряла смысл. Поводок от гнезда оставлял дыру: пойманный за границей поводка вор просто подбирал яйцо снова, и страж за ним уже не летел. Сторожить яйцо — одно правило на оба случая, и повторная кража ощущается так же, как первая.
**Отброшено:** страж возвращает яйцо в гнездо сам (ломает «яйцо остаётся на месте, подбирает кто успел» из 033); поводок без границы (стражи стягиваются через всю карту).

### 035. Погоня кончается только у купола; маяк станции
**Дата:** 2026-11-04
**Решение:** у стража нет поводка (было 220 studs от его места) и лимита погони (было 25 с). Погоня кончается, только когда вор пропал (вышел, умер, потерял яйцо) или оказался под куполом: внутри сферы купола или в зоне станции. Вылетел с яйцом обратно — страж снова гонится. В космосе над куполом висит экранная метка «Станция» с расстоянием; станция за кадром — метка у края экрана со стрелкой к ней.
**Почему:** на плейтесте вор, улетевший с яйцом в сторону от станции, быстро «отрывался» от стража на невидимой границе — получалось, что уходить надо не к базе, а от неё, и скорость снова теряла смысл. Купол — черта, которую видно и которую игрок и так знает («стражи не проходят»). Без маяка игрок, улетевший далеко, терял станцию из виду и не знал, куда лететь назад; экранная метка, а не BillboardGui, — чтобы она была видна с любой дистанции и не пропадала, когда станция выгружается стримингом.
**Отброшено:** отдельная видимая граница вокруг станции, шире купола (вторая черта рядом с уже понятной); поводок побольше (та же невидимая граница, только дальше); маяк лучом света в мире (за кадром не помогает).

### 036. Граница станции — видимая черта погони
**Дата:** 2026-11-04
**Решение:** погоня кончается не у купола, а у границы станции — сферы радиусом 150 studs вокруг центра купола (`StationConfig.BORDER_RADIUS`). В мире она видна как бледная оболочка и светящееся кольцо по экватору. Стражи не залетают за неё (запас 6 studs), яйцо внутри неё не сторожат. Маяк станции показывает расстояние до границы и скрывается внутри неё. Остальное из 035 в силе: поводка и лимита времени нет.
**Почему:** пользователь попросил явную черту, до которой гонится страж: купол виден плохо и слишком близко к платформе, а кольцо издалека показывает, куда дотянуть. Радиус 150 оставляет зазор около 35 studs до ближайших возможных гнёзд Пояса обломков (190 studs от центра).
**Отброшено:** граница по куполу (было в 035 — черту плохо видно); плоский круг на уровне платформы без сферы (подлетая сверху или снизу, непонятно, пересёк ли).

### 037. Одно яйцо на гнездо, новое — после доставки
**Дата:** 2026-11-04
**Решение:** пока яйцо гнезда у вора или лежит выпавшим, гнездо пустое. Новое яйцо вырастает через 20 с после того, как старое доставили в отсек. Яйцо, которое не доставили (выпавшее истекло через 3 минуты, вор вышел из игры), возвращается в гнездо. Цикл — чистый модуль `Domain/NestCycle` с тестами.
**Почему:** на плейтесте за долгую погоню (после 035 она не ограничена) гнездо успевало вырастить второе яйцо через 20 с после кражи, и страж охранял сразу два: гнался за вором и одновременно «держал» новое яйцо в гнезде. Одно яйцо на гнездо — одна цель у стража.
**Отброшено:** таймер роста запускать при возврате яйца (возврат и так кладёт яйцо обратно); сторожить новое яйцо, бросая погоню (вор уходит, просто дождавшись нового яйца).

### 038. Купол не пускает выпавшие яйца; удар по прицелу в конце замаха
**Дата:** 2026-11-04
**Решение:** выпавшее яйцо держится снаружи купола с запасом 4 studs (`EggConfig.DOME_MARGIN`): дрейфуя к станции, скользит по куполу, а выбитое внутри выталкивается наружу (`Bounds.pushOutside`). Удар ищет цель по прицелу в конце замаха (0,3 с), а не в момент нажатия; коридор удара — 8 + 14 studs вперёд и ±45° от прицела (было 8 + 9 и ±35°).
**Почему:** на плейтесте вдвоём бомба у самой станции выбила яйцо, оно доплыло до платформы и зависло над ней: под куполом ходят пешком, достать его было нельзя. Удар почти не попадал: за замах цель уходила из коридора, зафиксированного при нажатии, и сам коридор был узким.
**Отброшено:** яйцо под куполом падает на платформу (кто-то получает яйцо, не долетев с ним; доставка по сути без кражи); яйцо под куполом сразу в гнездо (удар у станции становится способом вернуть яйцо стражу).

### 039. Удар — выпад с ударом по касанию
**Дата:** 2026-11-04
**Решение:** удар — выпад по прицелу на 0,25 с со скоростью полёта плюс 40 studs/s, с анимацией удара рукой (`StrikePose`, загружается как анимация полёта) и вспышкой джетпака. Яйцо выбивается только в момент касания: первая цель ближе 6 studs перед атакующим (±70°) во время выпада; в точке касания вспышка, яйцо летит дальше по направлению удара. Выпад без касания — промах, без стана (вместо полсекунды без хода из 033). Выпад считает симуляция (предсказание, без задержки у атакующего), касание — сервер каждый кадр. С яйцом в руках удара нет; удержание ЛКМ бьёт снова, как только прошла перезарядка 1,5 с.
**Почему:** на плейтесте вдвоём удар выглядел как «пролетел, кликнул — у соседа само выпало»: замаха не было видно, яйцо падало через 0,3 с без всякого удара. Выпад и касание делают причину видимой. Запрет бить с яйцом закрывает выпад как способ убегать от стража: иначе это тот же рывок из 034.
**Отброшено:** оставить замах и проверку коридора, добавив только анимацию (яйцо всё равно выпадает не от касания); выпад по нажатию на сервере (у атакующего задержка на пинг).

### 040. Игра остаётся на личном аккаунте
**Дата:** 2026-11-04
**Решение:** игра и все её ассеты (анимации полёта и удара, дальше модели, звуки, картинки) принадлежат личному аккаунту разработчика, а не группе. Правило CONVENTIONS «ассеты — от группы игры» заменено на «ассеты — от владельца игры».
**Почему:** разработчик один, доходом делиться не с кем; доход с личной игры (продажи, выплаты за Premium, DevEx) идёт на аккаунт так же, как с групповой. Обе анимации уже загружены с аккаунта.
**Отброшено:** группа сейчас — нужна для команды, общей казны и имени студии, ничего из этого пока нет. Цена отказа известна: при переезде в группу ассеты придётся перезалить от неё (анимации играют только в играх своего владельца).

### 041. Скорость до 250, карта вдвое больше, захват на скорости, медленный режим
**Дата:** 2026-11-04
**Решение:** скорость полёта — 48 studs/s на ⚡ 10 и +18,4 за каждые ×10 (было +8,2): ⚡ 1 трлн летит на ~250. Зоны отодвинуты сильнее с удалением: Пояс 285–480, Кольца 775–1115, Туманность 1445–1940, Горизонт 2300–2900, граница карты 3100; астероидов 700, ориентиры растянуты; гнёзд по зонам 14 / 20 / 25 / 32 — от гнезда до гнезда везде около 2,2 с полёта на скорости зоны (после плейтеста при 12 в каждой зоне яйца приходилось долго искать). Захват «ловит» яйцо с расстояния 0,2 с полёта на текущей скорости (не меньше 9 studs) и подтягивает к нему со скоростью полёта; прогресс захвата набирается только в пределах 9 studs и не сбрасывается, пока подтягивает. Медленный режим (Q / L3 / кнопка на телефоне) ограничивает скорость полёта стартовыми 48; стражи считают погоню от фактической скорости вора (`Simulation/TopSpeed`). Стриминг: `StreamingMinRadius = 2048`, `StreamingTargetRadius = 4096` (вручную в плейсе, как в 032).
**Почему:** на плейтесте максимальная скорость не впечатляла; 250 выглядит хорошо. С новой формулой полёт на прежней карте стал бы на 40 % короче, а хотелось длиннее, поэтому карта выросла сильнее, чем скорость: до своей зоны на её скорости — ~5 с в Поясе, ~7 в Кольцах, ~9 в Туманности, ~11 на Горизонте. На 250 studs/s зону захвата в 9 studs пролетаешь за сотые секунды — яйцо было почти не схватить.
**Отброшено:** равномерное увеличение карты (начало с 48 studs/s стало бы тягучим); медленный режим, который замедляет только игрока, а не погоню (иначе он ловушка рядом со стражем).

### 042. Аналитика: одна служба, факты — сигналами, частое — суммами
**Дата:** 2026-11-04
**Решение:** `MetricsService` — единственный, кто вызывает `AnalyticsService`; остальные службы сообщают факты сигналами. Меряем: воронку новичка из 9 шагов (вошёл, вылетел, схватил яйцо, доставил, вылупил, первая покупка, кража у стража 4, у стража 6, в Ледяных кольцах) — каждый шаг один раз на аккаунт, маской в профиле; прогресс по стражам (первая доставка от поста дальше прежнего); экономику монет и ⚡; воронку каждой кражи (взял → граница станции → доставил); события потери яйца, поимки стражем, смерти от кислорода, способностей PvP и скрещивания. Частые факты суммируются и уходят раз в 5 минут и при выходе. Профиль v5: `onboardingSteps`, `bestPost`.
**Почему:** этап 7 должен показать, где уходят новички и не ломают ли награды темп; решение о магазине способностей (033) ждёт чисел с живых серверов; скрещивание — отдельная механика, и важно знать, пользуются ли ею. Сигналы вместо вызовов аналитики внутри служб держат игровой код чистым, а суммы — запросы в пределах лимита Roblox (120 + 20 × онлайн в минуту).
**Отброшено:** события на каждую выплату дохода и каждый удар (упрёмся в лимит при большом онлайне); имена игроков в полях (сочетания значений ограничены 8 000); отправка из Studio (Roblox её не принимает).

### 043. Доска монет: заработано за всё время, логарифм в хранилище
**Дата:** 2026-11-04
**Решение:** доска ранжирует по монетам, заработанным за всё время (`coinsEarned`, профиль v6), а не по балансу. Все источники монет начисляют через `Domain/Wallet.earn` (баланс и счётчик вместе); у игроков до v6 счёт начинается с баланса. На сервере — колонка `●` в стандартном списке игроков строкой формата игры; по всем серверам — топ-10 на табличке у спавна. Общее хранилище — `OrderedDataStore`, в нём очки: десятичный логарифм монет × 10⁶, округлённый до целого. Сервер пишет изменившиеся очки раз в 5 минут и при выходе, читает топ раз в 2 минуты; игроки на сервере показываются точными числами поверх прочитанного. Строки рисует клиент на своём языке. В Studio без хранилищ — хранилище в памяти.
**Почему:** баланс падает от каждой покупки — игрок, который вложился в капсулы, проваливался бы в таблице; доска должна радовать за прогресс. Монеты — `BigNum` далеко за пределами целых чисел хранилища, а логарифм сохраняет порядок мест и даёт ~6 знаков, больше, чем показывает `BigNum.format`. Единая точка начисления не даст будущим наградам (задания, подарок за вход) пройти мимо доски. Числовое значение в списке игроков Roblox показывает плохо (1.5e15 обрезается, огромные — `e+…`), строка выглядит как в HUD. Колонка — значок монеты, потому что её имя одно на всех игроков.
**Отброшено:** доска по текущему балансу (наказывает за покупки); хранить мантиссу и порядок в двух хранилищах (сортировка только по одному числу); место игрока вне топа (у `OrderedDataStore` его не узнать дёшево); скорость и кражи на доске (договорились — только монеты).

### 044. Задания дня: награда — минуты своей игры, одна замена в день
**Дата:** 2026-11-04
**Решение:** 3 задания в UTC-сутки из пула (доставь N яиц; доставь яйцо из зоны своего самого дальнего стража; вылупи N пришельцев; потренируйся 5 минут; скрести пришельцев — когда есть 3 одного стража; выбей яйцо у игрока — после защиты новичка). Награда задания — 7–10 минут дохода игрока (не меньше 200 монет) и скорости его тренажёра; все три вместе — в среднем 25 минут. Награда считается в момент «Забрать» и забирается кнопкой. Раз в день одно невыполненное задание можно заменить на другое. Профиль v7: `quests`. Прогресс тренажёра — секунды, поэтому сигнал `TrainingService.trained` теперь несёт и время.
**Почему:** награда от собственного темпа одинаково ценна новичку и ветерану и не ломает экономику: калькулятор даёт +10 % ⚡ к 30-му дню и на 5–8 % более ранних дальних стражей — в пределах 10–15 % этапа 7. Кнопка «Забрать» — маленький праздник и видимая награда. Замена нужна прежде всего для PvP-задания на пустом сервере. Задания хранятся в профиле, поэтому перезаход их не меняет.
**Отброшено:** фиксированные суммы наград (на поздних стражах ничего не стоят, на ранних ломают темп); авто-выдача награды без кнопки; убрать PvP-задание из пула (тогда задания не подталкивают к PvP).

### 045. До 30 капсул в два яруса
**Дата:** 2026-11-04
**Решение:** максимум капсул — 30 (было 12). Цена прежняя: каждая следующая втрое дороже, 30-я стоит ~2,5·10¹⁴. В отсеке они стоят двумя ярусами по 3 ряда × 5: нижний на полу заполняется первым, верхний висит над ним (стойки верхнего яруса без столкновений); табличка капсул поднята над верхним ярусом. Отсек, тренажёр и места пришельцев на полу не сдвинулись.
**Почему:** 12 капсул набирались в первый же день, и улучшать ферму дальше было нечем. Улучшение фермы должно мотивировать всё время игры. По `lune run balance` (без покупок) капсулы теперь покупаются постоянно: 15 к первому дню, 21 к седьмому, 25 к 30-му, 27 к 60-му; последние — далёкая цель. Темп стражей почти не изменился (дальние — в пределах дня-двух), доход к 60-му дню выше (179M/с против 107M/с).
**Отброшено:** расширять платформу и отсеки под 30 капсул на полу (8 отсеков по кругу уже занимают почти всё место); мельче капсулы в один ярус (10 в ряд не влезает в ширину отсека).

### 046. Подарок за вход: 7 дней, минуты своей игры, яйцо на седьмой
**Дата:** 2026-11-04
**Решение:** подарок раз в UTC-сутки, серия из 7 дней подряд; пропуск — серия заново, после седьмого — новый круг. Подарок дня — 3, 4, 5, 6, 8, 10, 15 минут дохода игрока (не меньше 200 монет) и скорости его тренажёра; на седьмой день ещё редкое среднее яйцо от самого дальнего стража, с которого игрок доставлял (новичку — от первого). Подарок забирается кнопкой на экране, который открывается сам при входе после «С возвращением!»; кнопка «Подарок» с бейджем — если экран закрыли. Профиль v8: `loginGift`. Формула «минуты своей игры» вынесена в `Domain/PlayReward` — общая для заданий, подарка и будущего индекса.
**Почему:** награда от темпа одинаково ценна на любом этапе. Седьмой день должен ощущаться особым, а яйцо детям понятнее и радостнее цифр; но не самое жирное: эпическое или легендарное яйцо последнего стража раз в неделю — слишком много (пользователь). По `lune run balance` задания и подарок вместе ускоряют стражей на 6–8 % (дальние — на 2–3,5 дня из 44–52), ⚡ к 30-му дню выше на ~16 %.
**Отброшено:** фиксированные суммы (то ничего не стоят, то ломают темп); прощать один пропуск (серия перестаёт быть серией); выдавать подарок без кнопки.

### 047. Индекс пришельцев и единый реестр
**Дата:** 2026-11-04
**Решение:** индекс — список всех 120 пришельцев (24 стража × 5 ступеней). Пришелец найден, когда впервые пришёл к игроку (вылупился, скрещен, выдан командой); награда за него забирается в окне индекса нажатием на светящегося пришельца: минуты дохода по ступени — 1, 2, 3, 5, 10 (только монеты); за полный набор стража — разово 15 минут. Пришельцы, которые у игрока были до индекса, найдены сразу, без награды. Профиль v9: `index`. **Единый реестр:** все места кода (индекс, вылупление, скрещивание, калькулятор баланса, тексты) берут пришельцев только из `AlienConfig`; калькулятор больше не придумывает «синтетических» пришельцев для стражей за пределами конфига. Правило записано в CONVENTIONS (раздел 3) вместе с остальными точками правды: `Wallet`, `PlayReward`, `Bay.addEgg`, `UtcDay`, типы из `remotes.zap`, `UI/Window`, `Layout.placeInMenu`.
**Почему:** коллекция — сильный повод возвращаться, а награда «забрать» заставляет заглядывать в индекс. Монеты, а не ⚡: индекс про коллекцию, не про тренировку; на баланс почти не влияет (+~1 % к темпу сверх заданий и подарка). Единый реестр — требование пользователя: чтобы в будущем (ивентовые пришельцы, новые стражи) нигде не было расхождений. Пока делали шаг, нашли и убрали другие копии: начисление наград в трёх службах, расчёт наград на трёх экранах, создание яйца в трёх местах, ручные копии сетевых типов на клиенте, шапки окон.
**Отброшено:** награда сразу при открытии (в индекс не заходят); ⚡ за открытия (пересекается с заданиями и подарком); отдельный список пришельцев у индекса (расходился бы с реестром).

### 048. Каркас ивентов: часы на сервере, состояние в атрибутах
**Дата:** 2026-11-04
**Решение:** у каждого ивента свои часы на каждом сервере (`Domain/EventClock`: тишина → предупреждение → ивент); расписание, длительности и названия — `EventConfig`. Состояние публикуется атрибутами папки `ReplicatedStorage.Events`, клиент показывает строку с таймером сверху, большой анонс (с зоной, если ивент где-то) и метку к месту ивента. Игровые эффекты подключаются к сигналу `EventService.changed`, место ивента задаёт служба ивента. Солнечная буря — первый ивент в конфиге (5 мин тишины с 10-секундным предупреждением в конце, 15 с бури), но в расписании выключена до своего шага: таймер бури, после которой ничего не происходит, только запутал бы. Метка станции и метка ивента — один компонент `UI/ScreenPin` (маяк станции переведён на него).
**Почему:** атрибуты на реплицируемой папке видны и тем, кто зашёл посреди ивента, без отдельных сетевых событий и снимков; анонс — только своему серверу, как договорились. Каркас не знает, что делает ивент, — буря, метеоритный дождь и существо подключаются к нему, не меняя его.
**Отброшено:** сетевые события Zap для фаз (нужен ещё снимок для входящих посреди ивента); общее расписание на все сервера (анонс должен быть «на свой сервер»).

### 049. Солнечная буря и размер станции от одного числа
**Дата:** 2026-11-05
**Решение:** буря — 15 секунд после 5 минут тишины (последние 10 секунд — предупреждение). Её край — граница станции, та же, где останавливаются стражи (одно число). Кто в космосе в момент начала, переносится на платформу перерождением на спавне (`LoadCharacterAsync`), яйцо из рук сразу возвращается в гнездо, тост «Буря! Тебя вернуло на станцию». Кто на станции — может вылететь из купола, но не дальше границы: полёт упирается в неё, как в край карты. Инкубаторы всех игроков в бурю — ×30. Буря включена в расписание. **Размер станции** — одно число `StationSize.PLATFORM_RADIUS`; купол, граница, спавн, кольцо отсеков, кольца зон, поле астероидов, край карты, чёрная дыра, место киоска и доски — цепочкой от него. Сейчас все значения те же (90 / 150 / 285 / 2900 / 3100).
**Почему:** граница стражей и край бури — одна линия (пользователь); раз пользователь будет менять размер станции, все радиусы должны идти от него, иначе граница уедет внутрь купола или на гнёзда. Перерождение вместо длинного `PivotTo`: тот рвёт суставы персонажа. По `lune run balance` буря почти не меняет темп стражей (прогресс упирается в ⚡, а не в вылупление).
**Отброшено:** отдельный радиус «второго кольца» между границей и гнёздами (две линии, которые разъедутся); выпускать в бурю только до купола.

### 050. Метеоритный дождь: варианты пришельцев и яйца под охраной стража
**Дата:** 2026-11-05
**Решение:** раз в 15–25 минут (предупреждение 30 с) на 2 минуты у гнезда случайного стража идёт метеоритный дождь: падает 2 яйца на игрока сервера, не меньше 4 и не больше 16, по одному, равномерно за первые 75 % дождя, до 40 studs от гнезда. **Яйца охраняет страж этого гнезда** — так же, как выбитое яйцо (решение пользователя), грейд яйца — его грейд, редкость и размер — из лута его зоны. Гнездо яйцо не трогает: доставка не растит новое, потерянное исчезает; неподобранные гаснут в конце дождя, яйцо в руках остаётся. Из метеоритного яйца вылупляется **метеоритный вариант** пришельца того же стража и ступени с доходом ×2. Варианты — часть единого реестра `AlienConfig` (`VARIANTS`, `grade.variants`); id обычных не изменились, метеоритные — с суффиксом `.Meteor`. Скрещиваются только пришельцы одного грейда и одного варианта, результат — того же варианта. В индексе — отдельный раздел «Метеоритные» со своими наградами и наборами (вкладки в окне). Профиль v10: у яйца в инкубаторе `variant`, наборы индекса — по id (`"3"`, `"3.Meteor"`) вместо грейда.
**Почему:** без стража дождь в дальней зоне давал бы новичку яйца, до которых он по силе ещё не дорос; страж сохраняет темп прогресса и делает дождь общим испытанием (толпа против одного стража). Яйца от числа игроков — на пустом сервере есть что ловить, на полном — гонка. Варианты в общем реестре, а не отдельные «ивентовые пришельцы», — индекс, вылупление, скрещивание, калькулятор и тексты берут их оттуда же, без расхождений (решение 047). Скрещивание внутри варианта не даёт «размножать» метеоритных из обычных. По `lune run balance` (одно яйцо с дождя, если его страж по силам) темп стражей меняется в пределах шума — это приятный бонус, а не ускорение.
**Отброшено:** яйца без стража — гонка только между игроками (пускает новичков к старшим яйцам); грейд по ближайшему посту без охраны; смешанное скрещивание с метеоритным результатом; метеоритные пришельцы в общем разделе индекса (120 лишних ячеек в каждой строке).

### 051. Метеоритный дождь: кратеры полосой через все зоны, сразу после бури
**Дата:** 2026-11-05
**Решение:** меняет часть решения 050. Метеоры падают не у одного гнезда, а полосой от станции в случайном направлении, через все зоны поровну (по кругу от станции), до 150 studs вбок от линии и не ближе 60 studs к любому гнезду и другому кратеру. **Каждый метеор оставляет кратер** — временное гнездо с одним метеоритным яйцом и своим стражем; грейд и пост стража — как у ближайшего обычного гнезда зоны. Кратер — обычное гнездо для всей механики (кража, выбитое яйцо, возврат в гнездо), но новое яйцо в нём не растёт: после доставки он исчезает вместе со стражем; в конце дождя исчезает сразу, если яйцо на месте, а если яйцо в пути — когда его доставят или оно вернётся. Число метеоров прежнее: 2 на игрока, от 4 до 16. **Дождь начинается только сразу после бури**: прошёл его промежуток — ждёт конца ближайшей бури (поле `after` ивента в `EventConfig`), его предупреждение и сам дождь (2,5 мин) целиком помещаются в 5 минут тишины. Стражи держатся за одного вора, пока тот не пойман и не в безопасности, затем берут ближайшего.
**Почему:** один страж на много яиц не работает (пользователь): сильный игрок уводит стража и держит его на себе, а остальные, в том числе новички, растаскивают яйца старших зон и слишком быстро растут. С кратерами у каждого яйца свой страж, и вся проверенная механика гнёзд работает как есть. Полоса через все зоны даёт каждому яйца своего уровня в каждый дождь, а не раз из четырёх. Буря посреди дождя сжигала бы яйцо в руках (перенос на станцию) и закрывала бы космос на 15 секунд из 120. По `lune run balance` метеоритные яйца ускоряют дальних стражей на 5–10 % — в пределах 10–15 % этапа 7.
**Отброшено:** яйца у одного гнезда под его стражем (решение 050: увести стража — и яйца свободны); яйцо со стражем без гнезда (своя механика вместо проверенной); одна зона за дождь (новичку чаще всего нечего ловить); пропускать бурю во время дождя (таймер бури, видный всегда, прыгал бы).

### 052. Активность игроков: кто отошёл от клавиатуры
**Дата:** 2026-11-05
**Решение:** отдельная механика `ActivityService` (`Domain/Activity`, `ActivityConfig`). Игрок активен, пока за последние 3 минуты сдвинулся больше чем на 10 studs от прошлой точки или прислал любую команду (через `NetService`); перерождение движением не считается. Наружу — `isActive`, `activeCount`, `idleSeconds` и сигнал `changed`. Первое применение: метеоров в дожде — 2 на **активного** игрока (от 4 до 16). Ограничения на сам АФК (кик без геймпасса и т. п.) пока нет — идея записана на этап 8 (GAME_DESIGN, «Монетизация»).
**Почему:** АФК-кач на тренажёре — часть игры, поэтому на сервере может стоять 7 отошедших и 1 активный; считать их всех — значит отдать одному игроку 16 яиц (пользователь). Механика отдельная, потому что пригодится и дальше (пользователь): ограничение АФК без пропуска, награды «за присутствие», аналитика. Сервер судит по движению и командам, а не по вводу клиента: так меньше доверия клиенту, а `Player.Idled` есть только на клиенте.
**Отброшено:** лимит метеоритных яиц на игрока за дождь (не решает «один активный забирает всё», только откладывает); просто меньше яиц (на полном сервере активных тогда не хватит); `Player.Idled` с клиента (подделывается, и Roblox сам кикает через 20 минут простоя).

### 053. Метки дождя по зонам, метеор каждые 3 секунды, анонс каждого кратера
**Дата:** 2026-11-05
**Решение:** меняет часть решения 051. **Метеоры падают по одному каждые 3 секунды** (`MeteorConfig.FALL_STEP_SECONDS`), первый — через 3 секунды после старта, а не равномерно по 90 секундам: при 4 метеорах все кратеры есть через 13 секунд, при 16 — меньше чем через минуту; остальное время дождя — на кражу (тест: падение занимает не больше половины дождя). Во время дождя на экране не одна метка к середине первой зоны, а **по метке на каждую зону**, где есть кратер с яйцом на месте: к ближайшему к игроку такому кратеру зоны, с названием зоны и расстоянием. Яйцо унесли — метка зоны переходит к следующему кратеру; в зоне не осталось яиц — метка пропадает. **О каждом новом кратере — анонс** «Новый кратер в зоне …» (один раз за кратер: вернувшееся яйцо не объявляется). Сервер публикует такие места ивента как «споты» (`EventService.showSpot`/`hideSpot`, папка `Spots` у ивента в `ReplicatedStorage.Events`), клиент выбирает по ближайшему в зоне (`Domain/EventSpots`) и объявляет новые (`EventConfig.spotAnnounceKey`). Метки, которые налезли бы друг на друга (вдоль полосы и у края экрана — почти всегда), раздвигаются по вертикали: ближняя стоит на месте, дальние отходят к середине экрана (`ScreenMarker.separate`). Метка ивента (середина первой зоны) — в предупреждение и до первого кратера.
**Почему:** игрок видел только ближний кратер и не знал, что дальше по полосе есть кратеры старших зон; при одном игроке кратер дальней зоны появлялся через 90 секунд — пауза в 30 секунд между метеорами слишком большая (пользователь). С коротким шагом метки всех зон появляются почти сразу, а анонс говорит, где новый кратер. Метка на каждый кратер — до 16 штук — загромождает экран, а по зоне игрок и так выбирает, куда лететь. Число яиц не изменилось — баланс тоже.
**Отброшено:** метка на каждый кратер; BillboardGui над кратерами (дальние не подгружены стримингом); одна метка «ещё N» (не видно, в какой зоне); отмечать места падения заранее, до метеора (с шагом 3 секунды не нужно — решение пользователя); все метеоры одним залпом (16 разом сливаются, и тесно у ближних кратеров).

### 054. Звёздный змей: охота дальше первой зоны, удача яиц в награду
**Дата:** 2026-11-05
**Решение:** третий ивент этапа 7 — Звёздный змей (вместо кита; решения пользователя от 2026-11-05). Раз в 15–25 минут сразу после бури, как метеоритный дождь, и может совпасть с ним; предупреждение 30 секунд, охота 3 минуты. Змей выходит из Горизонта событий и охотится на **всех в космосе дальше Пояса обломков** (у станции и в первой зоне безопасно, новичков не трогает), держится за одного, как страж. Скорость — **как у стража**: у змея своя ⚡, как у среднего (3-го из 6) стража той зоны, где летит цель, и гонится он по формуле стражей (`Speed.chaseSpeed`: ⚡ цели с учётом веса яйца против ⚡ змея). Кто прокачан до середины своей зоны, уходит от змея и с обычным яйцом, кто слабее — теряет яйцо. (Сначала было 95 % скорости цели без яйца, но так ⚡ ничего не решала: с яйцом змей ловил всегда, налегке — никогда; исправлено по замечанию пользователя.) **Поимка — как у стража:** отброс и оглушение, яйцо выпадает и потом возвращается в гнездо; пойманного змей 20 секунд не трогает. **Награда — удача:** яйца, доставленные во время охоты, вылупляются с удачей +0,35 сверх своей (между редким и необычным яйцом). Удача хранится в яйце (`EggRecord.luck`, профиль v11) и идёт клиенту по сети; формула удачи одна — `EggConfig.luckOf`. Удар стража вынесен в `Character/Prey` и общий со змеем. Тело змея рисует клиент по следу головы (`Domain/SerpentBody`). По `lune run balance` дальние стражи наступают на 1–4 % раньше (в пределах 10–15 % этапа 7).
**Почему:** опасность, которая меняет обычную игру на 3 минуты, а не новая механика: поимка и погоня уже знакомы игроку по стражам. Скорость от цели — как у стражей (отношение скоростей, а не числа). Награда тянет игроков наружу именно в охоту; совпадение с дождём — «метеоритное яйцо с удачей» (пользователь).
**Отброшено:** змей кусает кислород (можно не долететь домой); уносит на станцию, как буря (выбивает из охоты целиком); охота на всех за границей станции (достаётся новичкам) или только на тех, кто с яйцом; монеты за побег (новая награда в балансе); без награды; своё расписание вне бури (буря посреди охоты переносит всех на станцию); тело змея из серверных деталей (рывки при репликации и трафик на каждый сегмент).

### 055. Звёздный змей, версия 2: выбей звёздное яйцо
**Дата:** 2026-11-05
**Решение:** заменяет механику решения 054 (расписание, тело змея, `Character/Prey`, удача в яйце — остаются). Змей больше не охотится на игроков: он **несёт звёздное яйцо**, одно за ивент на сервер. **Зона змея:** он выходит в одной случайной зоне за Поясом обломков (её называет анонс) и остаётся змеем этой зоны до конца охоты, куда бы его ни загнали: его ⚡ — ⚡ среднего стража этой зоны (`SerpentConfig.powerIn`), яйцо — грейда этого стража, бродит он по кольцу этой зоны (решение пользователя от 2026-11-05: скорость не меняется во время ивента). **Фаза 1:** змей бродит и убегает от ближайшего игрока со скоростью игрока со своей ⚡ — догонит тот, кто прокачан для зоны. **3 попадания по голове** на весь сервер (удар, гарпун, гравибомба; счётчик на метке) — яйцо вылетает. Правила PvP (новичок, перевес ⚡, щит) — про игроков, на змея не действуют. **Звёздное яйцо:** грейд среднего (3-го) стража зоны змея; редкость — по добыче зоны, но не ниже Редкой; удача +0,7 сверх своей. **Фаза 2:** змей сторожит яйцо, как страж: висит над выпавшим, гонится за носителем по формуле стражей и ловит (яйцо выпадает); метка ведёт к яйцу, другие игроки могут отбить его PvP. **Конец:** яйцо доставлено — анонс, змей уходит, ивент кончается досрочно; время вышло — змей уходит, яйцо в нём уходит с ним, выпавшее ещё 30 секунд лежит без охраны (`STAR_EGG_LINGER_SECONDS`; кто успел — тот и взял, решение пользователя после плейтеста: выбивание в последнюю секунду не пропадает), потом исчезает, яйцо в руках остаётся у игрока. Удачи всем яйцам, доставленным в охоту, больше нет. Своё «место» звёздного яйца — дом яйца `StarSerpent` (`Domain/EggHomes`) рядом с гнёздами: по нему `CarryService` узнаёт грейд, куда вернуть и кому сказать о доставке. План — [plans/STAR_SERPENT.md](plans/STAR_SERPENT.md).
**Почему:** на плейтесте версия 1 оказалась странной (пользователь): только наказание, непонятно, куда лететь, один змей на огромной карте почти не встречается, и это повтор стража. Охота на змея — одна цель на весь сервер, PvP вокруг неё, и награда видна сразу. Змей-сторож нужен, чтобы на сервере с одним игроком яйцо не было подарком без риска (решение пользователя).
**Отброшено:** змей кружит у Пояса обломков и стережёт дорогу домой; змей сам несётся к тому, кто взял яйцо; несколько змеев; змей разоряет гнёзда; один удар на выбивание (слишком просто); змей исчезает сразу после выбивания (на сервере с одним игроком — подарок); новый вариант пришельцев «звёздные» (большая отдельная работа, можно позже).

### 056. Джетпак: две модели у каждого, 21 уровень до ×2048
**Дата:** 2026-11-05
**Решение:** у джетпаков 1–10 по две модели (I, II): модель I удваивает множитель модели I предыдущего джетпака, модель II — ×1,5 к ней, так что множители читаются ×2, ×3, ×4, ×6, ×8, ×12 … ×1536; последний джетпак — Бесконечность ×2048, одна модель, выше уровней нет. После Антиматерии — четыре новых джетпака: Сингулярность, Гиперпривод, Червоточина, Бесконечность (названия — решение пользователя). Всего 21 покупка вместо 7 названных уровней и бесконечных «Антиматерия +1, +2» за ними. Цена — по множителю, а не по номеру уровня: каждое удвоение дороже в 10 раз, как раньше каждый уровень (×2 — 2000, ×4 — 20K, ×8 — 200K), промежуточная модель — пропорционально (×3 — 7,7K); цены округлены до двух значащих цифр (`Domain/Upgrades`: `jetpackModel`, `jetpackMultiplier`, `jetpackPrice`, `jetpackMaxLevel`). Покупка выше потолка — отказ `JetpackTop`. Профиль v12: старый уровень L (×2^L) — новый 2L−1, не выше 21. Вид меняется с джетпаком (обе модели одного джетпака выглядят одинаково; новые четыре — заготовки цветом).
**Почему:** на плейтесте за 10 минут было куплено 3 уровня из 7 названных — «маловато до конца игры»; ×1,26 за уровень плохо читается, а ряд ×2, ×3, ×4, ×6 — понятные числа (пользователь). Потолок ×128 (последний названный уровень) резал позднюю игру: баланс всегда считался с бесконечными «+N», и к 60-му дню калькулятор доходил до ×2048 (старый уровень 11) — его и сделали честным финалом.
**Баланс:** по `lune run balance` 24-й страж бесплатному игроку — на 48-й день (было ~48), игроку с геймпассом и набором — на 22-й (было 22); стражи 21–23 — на 5–15 % раньше (модели ×1,5 покупаются до полного удвоения), в пределах 10–15 % этапа 7.
**Отброшено:** ×1,26 за уровень (три модели на джетпак, та же кривая) — тяжело читается; потолок ×128 — поздняя игра встаёт (24-й страж не достижим за 60 дней), а компенсация тренажёром сдвигает середину игры; бесконечные «+N» без названий.

### 057. Гнёзда: у каждого стража зоны своё кольцо
**Дата:** 2026-11-05
**Решение:** кольцо зоны делится на 6 узких колец, по одному на пост: первый страж зоны — внутреннее, шестой — внешнее. Гнёзда поста стоят на своём кольце через равные углы с небольшим разбросом, кольца повёрнуты друг относительно друга на золотой угол, чтобы гнёзда соседних постов не выстраивались лучом (`Domain/NestLayout`). Пост гнезда задаёт раскладка (`NestSite.post`), а не ранг расстояния (`Domain/Posts` удалён). Гнёзд больше: на пост 4 / 5 / 6 / 7 по зонам — 24 / 30 / 36 / 42 вместо 14 / 20 / 25 / 32 (у каждого гнезда свой страж). Таблички стражей по-прежнему видны издалека (`ZoneLooks.GUARDIAN_SIGN_DISTANCE`, решение пользователя).
**Почему:** раньше расстояние гнезда от станции было случайным во всей ширине кольца, а пост — по рангу расстояния, так что соседние по кругу гнёзда оказывались первым и шестым постом зоны (разница в силе до 243 раз): «в одном месте гнёзда от невообразимо далёких по уровню до самых бесполезных» (пользователь). Теперь рядом с игроком гнёзда одного уровня, а дальше от станции — сильнее, шаг за шагом. 2–5 гнёзд на пост — мало (пользователь).
**Отброшено:** пост по сектору круга (сила зависела бы от направления, а не от расстояния); таблички ближе.

### 058. Места в инкубаторе и очередь яиц
**Дата:** 2026-11-06
**Решение:** в инкубаторе ограниченное число мест: у нового игрока 2, остальные покупаются за монеты, до 12 (робуксы — на этапе 8). Яйцо, доставленное в полный инкубатор, ложится на платформу отсека рядом с инкубатором и ждёт в очереди (не греется); освободилось место — первое из ждущих само переходит в инкубатор и начинает греться с момента освобождения (так и вне игры). Ничего не пропадает. Солнечная буря ускоряет только яйца на местах. Цена места растёт с каждым; первые дешёвые (подбор — `lune run balance`). Профиль v13: `incubatorSlots`, очередь `waiting` (яйцо с выпавшей длительностью `hatchSeconds` вместо `hatchAt`); старые профили не переносятся бережно — игра не в продакшене (пользователь), миграция только заводит поля. План — [plans/INCUBATOR.md](plans/INCUBATOR.md).

**Отброшено:** лишние яйца пропадают или не принимаются при доставке; очередь, которая греется (места теряют смысл); выбор игроком, какое яйцо греть первым (позже, если попросят).

### 059. Яйцо вылупляет игрок
**Дата:** 2026-11-06
**Решение:** меняет решение 058 в одном: яйцо, у которого вышло время, само не вылупляется. Оно становится **готовым** — над ним «Готово!» вместо таймера — и держит своё место, пока игрок его не вылупит. Вылупить можно только подсказкой «Вылупить» у самого яйца, в своём отсеке (сервер проверяет хозяина и расстояние, как у «Подобрать»); кнопки «Вылупить все» и вылупления из окна отсека нет (решения пользователя). Вылупил — пришелец идёт как раньше (капсула, инвентарь, пол), а на место сразу встаёт первое яйцо из очереди и греется **с этой минуты**. Вне игры яйца на местах дозревают и ждут игрока, очередь стоит. Солнечная буря ускоряет только недозревшие. На экране «С возвращением!» — сколько яиц готово. `HatchNow` делает яйца готовыми, а не вылупляет. План — [plans/INCUBATOR.md](plans/INCUBATOR.md).
**Почему:** вылупление — отдельное действие и маленький праздник, а не тост где-то в космосе (пользователь). Места начинают ощущаться: вне игры каждое место — ещё одно готовое яйцо к возвращению, а в игре готовое яйцо, которое не вылупили, задерживает очередь. Калькулятор показал, что при вылуплении само собой места почти не влияют на темп: очередь вылуплялась за ночь.
**Цены мест:** каждое следующее в 30 раз дороже (150, 4,5K, 135K, 4M, 121M, 3,6B, 109B, 3,3T, 98T, 2,95Qa) вместо ×3: доход растёт быстрее любой цены, и при ×3 к 7-му дню место стоило секунды дохода (решение пользователя — «круче геометрия»). По `lune run balance` бесплатный игрок берёт 3-е и 4-е место в первый час, 5-е и 6-е — в первую неделю, 7-е и 8-е — к третьей; дальше места модели не нужны, а стоят часы и дни дохода — для тех, кто крадёт быстрее модели, и для робуксов (этап 8). Темп не изменился: 24-й страж на 49-й день (было 48). Калькулятор вылупляет готовые яйца только в отсеке: в начале сессии и при каждой доставке.
**Отброшено:** цена в минутах текущего дохода (дорожает от каждого нового пришельца); вылупление само собой с остановкой очереди вне игры (тот же эффект без действия игрока); «Вылупить все» и вылупление из окна отсека из любой точки карты (отсек нужен реже).

### 060. Щита нет
**Дата:** 2026-11-06
**Решение:** способность «щит» (6 с неуязвимости, перезарядка 30 с, решение 033) убрана из игры: из правил PvP (`Domain/Pvp`, отказ `VictimShielded`), ввода (клавиша R / L2), HUD, тостов, сети и эффектов. Защита от атак — только скорость (вор с яйцом тяжелее) и правила честности: новичок, 10 с после респауна, перевес ⚡ в 10 раз, купол. Щит не продаётся и за робуксы.
**Почему:** щит делает PvP бессмысленным (пользователь): вор включает его, когда к нему подлетают, и любая атака уходит в пустоту. Продавать его за робуксы — тем более покупка неуязвимости.
**Отброшено:** щит за робуксы (перезарядка сейчас, защита на N минут); щит слабее или с долгой перезарядкой.

### 061. Каталог покупок за робуксы
**Дата:** 2026-11-06
**Решение:** покупки за робуксы только ускоряют то, что есть в игре и так; ничего случайного, цена и награда видны до покупки. **Пропуски:** «Двойная тренировка» — ×2 к прибавке тренажёра, вне игры тоже (299 R$); «Ночная смена» — вне игры доход 12 ч вместо 4, тренировка 24 ч вместо 8 (149 R$; потолки изменены решением 062: 8 ч и 16 ч). **Покупки:** час / 8 часов / сутки тренировки — ⚡ = прибавка тренажёра × время, число видно до покупки (25 / 99 / 249 R$, решение 024); «Яйцо готово сейчас» — одно яйцо на месте сразу готово, вылупляет игрок (3–20 R$: ступень = номер зоны стража яйца 0–3 + номер редкости 0–4, 8 ступеней 3 / 4 / 5 / 7 / 9 / 12 / 16 / 20); место в инкубаторе за робуксы по одному, вместо монет (3–6-е — 19, 7–9-е — 49, 10–12-е — 99 R$); «Забрать ×2» на экране возвращения — ещё раз столько же монет и ⚡ (29 R$). У покупки в Roblox одна цена, поэтому ступени — отдельные покупки с одним названием; какую показать, решает игра. Цены задаются в Creator Hub, игра показывает те, что вернёт Roblox. ID — по игре (`game.GameId`): у Dev и Prod (решение 011) свои; в неизвестной игре покупки выключены. Список с текстами — [plans/STAGE_8.md](plans/STAGE_8.md). **Покупка не теряется:** у покупки Roblox нет параметров, а чек может прийти и после перезахода, поэтому «Яйцо готово сейчас» применяется к выбранному яйцу, а если его уже нет — к греющемуся яйцу той же ступени или ниже, у которого дольше всего осталось; место за робуксы — следующее; если применить не к чему (яйца вылупились, все места уже куплены), игрок получает 30 минут своего дохода монетами (не меньше 100). Пакет тренировки считается по прибавке тренажёра с пропусками.
**Почему:** решения пользователя от 2026-11-06: каталог из четырёх групп; места — по одному; «готово сейчас» — по грейду и редкости, недорого (от 3 до 20); цены пропусков и пакетов — как предложено. Ступени вместо формулы: Roblox не даёт менять цену покупки из игры.
**Отброшено:** пропуск «Большой инкубатор» (+2 места или последние места только за робуксы); щит (решение 060); «готово сейчас» для всех яиц разом (цена зависит от яйца); VIP-скафандр сейчас (это внешний вид — к полировке).

### 062. «Ночная смена» удваивает потолки, а не утраивает
**Дата:** 2026-11-06
**Решение:** с «Ночной сменой» вне игры капсулы приносят монеты 8 часов вместо 4, тренажёр качает 16 часов вместо 8 (было в решении 061: 12 и 24). Цены пропусков прежние: «Ночная смена» 149 R$, «Двойная тренировка» 299 R$.
**Почему:** калькулятор баланса с пропусками (`lune run balance`, профили по пропускам): с потолками 12 / 24 «Ночная смена» за 149 R$ ускоряла путь до Кита в 2 раза, сильнее «Двойной тренировки» за 299 R$ (в 1,5 раза), а оба пропуска вместе — в 2,8 раза при цели GAME_DESIGN 1,5–2. С 8 / 16 каждый пропуск ускоряет примерно в 1,5 раза (49 дней → 33 и 32), оба — в 2,3 (22 дня). Решение пользователя от 2026-11-06.
**Отброшено:** оставить 12 / 24 и принять 2,8 раза; 8 / 12 (тренировка вне игры почти не растёт, пропуск ощущается слабо); поменять цены пропусков местами.

### 063. «Яйцо готово сейчас» — у самого яйца, и оно сразу вылупляется
**Дата:** 2026-11-06
**Решение:** пока яйцо греется, на нём подсказка «Вылупить за 6 R$» (только для хозяина отсека) с ценой ступени именно этого яйца; нажал — окно покупки Roblox для этого яйца. Это единственное место, где «готово сейчас» продаётся: кнопки «Готово за … R$» в окне отсека и строки в магазине нет (решение пользователя). Покупка для выбранного яйца вылупляет его сразу; чек, пришедший позже (после перезахода), или покупка без выбранного яйца по-прежнему только делают яйцо готовым (решение 061). Цены за робуксы клиент спрашивает у Roblox заново, когда они появляются на экране (окно отсека, магазин, экран возвращения, подсказка у яйца), не чаще раза в 30 с.
**Почему:** пользователь: строка «Готово за 3 R$» не говорит, за что именно платишь; покупка должна быть на самом яйце, с его ценой. Managed Pricing меняет цены во время игры: цена места, прочитанная при входе (14), разошлась с окном покупки (19) — игрок видит обман.
**Отброшено:** только «готово» после покупки и ещё одно нажатие E (покупка «вылупить» должна вылуплять); оставить и кнопки в окне отсека, и строку в магазине (там снова неясно, какое яйцо покупаешь).

### 064. «Забрать ×2» — цена по размеру награды, от 1 до 20 R$
**Дата:** 2026-11-06
**Решение:** у «Забрать ×2» 8 ступеней по монетам, которые принесло время без тебя (доход × время, уже с потолком): до 1M — 1 R$, до 10M — 2, до 100M — 3, до 1B — 5, до 10B — 7, до 100B — 10, до 1T — 15, от 1T — 20 (`MonetizationConfig.DOUBLE_TIER_LIMITS`, `Purchases.doubleTier`). Ступень считает сервер при расчёте награды и шлёт с ней (`OfflineReward.doubleTier`); пока экран открыт, цена не меняется. Чек ступени ниже, чем у награды (старый экран или покупка не с экрана), платит только до предела своей ступени, и ⚡ — в той же доле. По калькулятору после 4 часов без игры: первые часы — 1–2 R$, день 1 — 3–5 R$, неделя — 10 R$, месяц и дальше — 15–20 R$ (`lune run balance`, колонка `x2 tier`). Заменяет одну цену 29 R$ из решения 061.
**Почему:** пользователь: в начале ×2 должно стоить копейки, к концу — дороже; цена — по доходу × время, от 1 до 20 R$ («пусть детишки радуются»). Только по доходу короткое отсутствие на позднем этапе стоило бы дорого за маленькую добавку.
**Отброшено:** цена по времени отсутствия (не растёт с игрой); только по доходу в секунду; одна цена для всех.

### 065. Туториал: пять шагов основного цикла, без кнопки «Пропустить»
**Дата:** 2026-11-06
**Решение:** новичка ведёт одна строка подсказки внизу экрана и метка на цели (как маяк станции): укради яйцо у стража 1 → неси на станцию → вылупи → накачай ⚡ на тренажёре до рекомендации стража 2 → укради у стража 2 (или дальше) → «Дальше сам» с указанием на цель в HUD. Сначала кража: стартовой ⚡ 10 хватает на стража 1. Первое доставленное в туториале яйцо готово за 10 с (`TutorialConfig.FIRST_EGG_SECONDS`). Профиль хранит пройденные вехи (`tutorialStep`, v15: доставил, вылупил, натренировал, украл у сильного), подсказка выводится из вех и того, несёт ли игрок яйцо (`Domain/Tutorial`): выбили яйцо, кончился кислород, буря — подсказка сама возвращается к «укради». Шаг, уже сделанный раньше, пропускается. Ничего не блокируется, кнопки «Пропустить» нет; шага «купи улучшение» нет (первое улучшение — минуты ожидания дохода); буря и метеоры идут как обычно. Воронка `Tutorial` в аналитике. Профили, уже доставлявшие от стража 2 и дальше, считаются прошедшими. Вид панели и меток — грейбокс до полировки.
**Почему:** решения пользователя от 2026-11-06 («все по предложению»): обучать действием, а не текстом; первые минуты — самое интересное (кража), а не ожидание.
**Отброшено:** сначала тренажёр; кнопка или крестик «Пропустить»; шаг «купи улучшение»; пауза бури для новичков; шаги по нажатым кнопкам вместо состояния игрока.
**Дополнение (2026-11-10, плейтест):** первое доставленное в туториале яйцо готово **сразу** (`FIRST_EGG_SECONDS = 0`), а не за 10 с: подсказка вела игрока к яйцу, которое ещё приходилось ждать. Подсказка шага — «Яйцо готово! Беги к инкубатору и вылупи его».

### 066. Интерфейс: неоновое стекло и брифы экранов до кода
**Дата:** 2026-11-07
**Решение:** стиль интерфейса — «Б1 спокойный»: полупрозрачное тёмное стекло, у каждой кнопки свой цвет с мягким свечением, двухцветные иконки без подписей, шрифт Nunito Heavy, редкость — цвет обводки. Общие правила (цвета, шрифт, размеры, компоненты, раскладка экрана) — в `docs/design/DESIGN.md`. Каждый экран сначала описывается брифом `docs/design/screens/<экран>.md`: раскладка на телефоне, планшете и ПК, все состояния (обычное, пустое, загрузка, ошибка, закрыто), поведение, тексты, открытые вопросы. Код экрана пишется только по брифу со статусом `approved` (после слова пользователя). HTML-макеты лежат рядом, в `docs/design/mockups/`. Порядок экранов: HUD → окно отсека → магазин джетпаков → задания и подарок → индекс → магазин и экран возвращения → туториал.
**Почему:** пользователь выбрал стиль по HTML-макетам: полупрозрачность меньше мешает искать яйца на телефоне, яркий неон напрягал глаза. Порядок «бриф → утверждение → код» и обязательные состояния взяты из скилла `roblox-ui-implementation` (AshExplained/roblox-skills) по просьбе пользователя: без брифа экраны делаются только в счастливом состоянии и разъезжаются по стилю.
**Отброшено:** «Конфетный» (светлые окна сильнее закрывают космос), «Мультяшный sci-fi», яркий Б1 (напрягает глаза), Б2 «Цветное стекло»; Fredoka One (нет кириллицы в Roblox, буквы подменяются); код экранов без брифа.

### 067. Монеты и ⚡ — иконкой везде, и в текстах
**Дата:** 2026-11-07
**Решение:** сумма монет или ⚡ всегда показывается иконкой перед числом — в HUD, окнах, тостах, табличках в мире, на кнопках и на доске монет. В строках локализации знак `●` (монеты) или `⚡` стоит прямо перед числом («Награда: ●+12K и ⚡+3.4K»); `Locale/Marks.split` режет строку на слова и знаки, `UI/IconText` рисует знаки иконками `Coin` и `Bolt` в цвете ресурса. Его используют `ActionButton`, `Button`, `Toasts`, `WorldLabel`, `CoinBoard`, `WelcomeBack`, магазин джетпаков. Строка со знаками не переносится; предложение на экране возвращения больше не повторяет суммы (они крупно над ним). Слово «монеты» осталось только там, где нет числа. Иконки монеты и молнии перерисованы потолще (на монете — крупный знак $, пользователь), чтобы читаться мелко у числа. Исключение — колонка `●` в списке игроков Roblox: там картинку не поставить.
**Почему:** пользователь: монеты везде должны быть одной иконкой, а в текстах они были словом («монет») или знаком ● шрифта; молния в тексте тоже была знаком шрифта, а рядом с числами в окнах — иконкой.
**Дополнено (2026-11-07, бриф магазина):** цена в робуксах — так же, знак `R$` перед числом рисуется иконкой `Robux` (решение пользователя).
**Отброшено:** слово «монет» в тостах; знак ● шрифта; разметка вида `{coin}` (это переменная, а знак в строке понятен и переводчику, и проверке длины).

### 068. Отсеки — острова вокруг станции, пришельцы растут, места вместо капсул
**Дата:** 2026-11-08
**Решение:** личный отсек становится **островом**: 8 островов по кругу вокруг центральной станции, у каждого игрока свой, под своим куполом и внутри границы станции; центральная станция (спавн для новых, киоск джетпаков, доска монет) остаётся небольшой, граница станции отодвигается так, чтобы острова были целиком внутри (зоны карты считаются от неё, баланс погони не меняется, дорога до первой зоны длиннее примерно на 200 studs). **Пришельцы растут** по стражу и ступени: обычный пришелец стража 1 — 2 studs, с каждым стражем ≈ +11 %, у стража 24 обычный ≈ ×4 роста игрока, легендарный ≈ ×8 (около 40 studs). Пришельцы **стоят на площадке** острова, их место — **«место»** (было «капсула», до 30 мест, цены прежние); **капсулы** теперь у **инкубатора**: в них греются яйца. Яйцо засчитывается, когда игрок с ним приземлился на свой остров или на центральную станцию; спавн и возвращение бурей — на свой остров; на чужие острова можно прилетать и смотреть, ничего не трогая. Вместо табличек над тренажёром, инкубатором и местами — терминалы рядом с ними. План по шагам — `docs/plans/BAY_REWORK.md`.
**Почему:** пользователь: в похожих играх самые редкие питомцы огромны, во много раз выше игрока, — для начала ×8 в конце, дальше посмотрим. 30 таких пришельцев не помещаются в отсеки на общей платформе (нужна платформа радиусом ~220 вместо 60); острова дают место гигантам и видны издалека — есть чем хвастаться. Пришельцев не хочется держать в капсулах, а яйца в капсулах инкубатора — логично.
**Отброшено:** одна огромная станция (далеко лететь, соседей не видно); меньше мест, но крупнее (меняет экономику); пришельцы прежнего размера.
**Дополнено (2026-11-08, бриф острова `docs/design/screens/island.md`):** остров — **радиусом 95** (купол 142,5, граница станции 581): 30 гигантов конца игры на 55 не помещаются. Места стоят подковой 300° вокруг инкубатора, открытой ко входу, и расставляются по размеру пришельцев (`Domain/PlaceLayout`): мелкие внутри, гиганты у края; не помещаются — сдвигаются теснее, не меньше ×0,5. Пришельцы без места на полу — маленькие, в росте стража 1. **Отброшено:** средний остров (70) с плотной толпой гигантов; гиганты на площадках снаружи купола (к ним пришлось бы подлетать); рост ×5 вместо ×8; места постоянного размера (под самого большого — не помещаются).
**Дополнено (2026-11-08, шаг 5 переработки отсека):** место в инкубаторе тоже называется **«капсула»** / pod («+1 капсула», «Ждёт капсулы»): каждое место инкубатора и так выглядит капсулой, а «место» остаётся только у пришельцев — одно слово не значит две вещи. О месте в мире — «остров» («Остров {name}», «Твой остров», буря возвращает на остров); «отсек» — окно и его содержимое. **Отброшено:** «место в инкубаторе» рядом с «местом» пришельца.

### 069. Метка своего острова вместо маяка станции
**Дата:** 2026-11-08
**Решение:** экранная метка «Твой остров» с расстоянием до его купола (`HomeBeaconController`, та же `ScreenPin`) видна всегда, пока игрок не на своём острове: в космосе, у центральной станции, на чужом острове; остров за краем экрана — метка у края со стрелкой. Пока туториал сам ведёт домой (несёшь яйцо), его метка говорит то же самое, и эта уступает ей. Маяк станции (решение 035) убран.
**Почему:** пользователь на плейтесте долетел до станции с магазином и потерял свой остров: маяк станции прятался внутри её границы, а острова — внутри неё. Станцию со своего острова и так видно, а её саму ещё будем перерабатывать, чтобы были видны доска монет и магазины.
**Отброшено:** обе метки сразу (станция лишняя); столб света над островом (пока не нужен, можно на переработке станции).

### 070. Захват яйца — кнопкой «Схватить» и одним нажатием
**Дата:** 2026-11-08
**Решение:** рядом с яйцом (не дальше 50 studs — после плейтеста с телефона вместо 30, у быстрого — дальше, `Grab.lockRange`) появляется большая кнопка «Схватить» в цвете редкости яйца: на телефоне — над кнопками полёта, на ПК — первой в ряду действий (E). **Одно нажатие** цепляет захват за это яйцо: магнит сам подтягивает к нему, в досягаемости заполняется прогресс (время прежнее, 2–4 с). Держать не надо. Отмена — второе нажатие или джойстик прочь от яйца; захват отпускает и сам, если яйцо пропало, улетело дальше полутора дальностей кнопки, игрока ударили или руки заняты. Подсказка на яйце остаётся — та же кнопка, только с полоской. Работает и короткое нажатие, и удержание: удержание — то же нажатие. На телефоне «вверх» стоит на месте кнопки прыжка Roblox, «вниз» — слева от него (раньше там был «вниз», это сбивало). В туториале у яйца строка — «Жми кнопку с яйцом». Бриф — `docs/design/screens/grab-button.md`.
**Почему:** пользователь дал поиграть сыну — тот не справился с захватом: маленькую подсказку на яйце нужно заметить, попасть в неё пальцем и держать 2–4 с, а магнит тянул только при удержании. Одна большая кнопка под пальцем и одно нажатие убирают все три трудности. Закрывает идею авто-примагничивания (2026-11-07) тем же магнитом, но по нажатию: без нажатия никуда не тянет, пролёт мимо и бегство не страдают.
**Отброшено:** удержание кнопки (то же, что было, только крупнее); короче время захвата (меняет баланс краж); магнит сам, без нажатия (мешает пролетать мимо); кнопка вместо удара (у гнезда нельзя ударить соседа-вора).

### 071. Язык — язык аккаунта игрока; автоперевод Roblox у нашего интерфейса выключен
**Дата:** 2026-11-08
**Решение:** всё, что читает игрок, берёт язык из одного места — `Text.localeOf(player)`: в игре это `Player.LocaleId` (язык аккаунта; по документации Roblox — для контента игр), в Studio — `LocalizationService.RobloxLocaleId` (туда приходит язык эмулятора игрока). Строки по-прежнему свои (`Locale/Strings.luau`, русский и английский). Автоперевод Roblox (`AutoLocalize`) у всех наших GUI выключен одним клиентским контроллером `AutoLocalizeGuard`: он гасит его у каждого корневого GUI в `PlayerGui` и в мире, так что новый экран не может забыть.
**Почему:** на телефоне окна были на английском (они читали `RobloxLocaleId` — язык интерфейса Roblox), а подсказка с сервера — на русском (`Player.LocaleId`). Автоперевод Roblox переводит текст GUI у игроков с включённым «Automatic Translations», считая его написанным на исходном языке игры, — он мог бы испортить наши уже переведённые строки.
**Отложено:** смена языка прямо в игре (меню Roblox предлагает только языки, включённые в настройках локализации игры — у нас их нет) и остальные языки (испанский, португальский и др.) — через выгрузку `Strings.luau` в облачную таблицу локализации Roblox; тогда же — `GetTranslatorForPlayerAsync` и перерисовка текстов при смене языка. Решить до запуска.
**Отброшено:** `RobloxLocaleId` как язык игры (язык интерфейса Roblox, не контента); перейти целиком на облачную таблицу сейчас (теряем проверки ключей, длины и стоп-слов в `lune run check` ради языков, которые пока не нужны).

### 072. Арт: свои пришельцы и яйца, мультяшный стиль из Blender
**Дата:** 2026-11-08
**Решение:** пришельцы и яйца — свои модели, а не из Toolbox. Пришелец — **детёныш своего стража**: шесть основ (слизень, краб, червь, скат, рой, кит) и из них параметрами 24 вида. Ступень видна по кольцу её цвета под пришельцем и по **наряду, который растёт со ступенью**: пятна → антенна → кристаллы → корона с искрами; метеоритный вариант — тёмный, с горящими трещинами и огоньками. Пришельцы двигаются **кодом** (дыхание, покачивание, подпрыгивание), без скелетных анимаций. Яйцо — одно на игру, по редкостям наряд растёт так же (пятна, пояс со звёздами, кристаллы, корона), поверхность **глянцевая** (лаковый слой), обводка — мультяшная, только по силуэту. Модели строят скрипты Blender в `assets/blender/` (концепты — `docs/design/concepts/`, сравнение — `docs/design/mockups/aliens-compare.html`).
**Почему:** пользователь сравнил наши концепты с бесплатными моделями Toolbox: готового набора на 24 вида там нет (только отдельные слизни), а наш стиль один на всё и параметрический. Яйцам добавить глянца — его просьба.
**Отброшено:** слизни и яйца из Toolbox; пришельцы, не похожие на стражей; ступень только цветом и свечением; скелетные анимации (тяжело для телефонов: до 30 гигантов на острове × 8 островов). Модели, копирующие чужие игры, не рассматривались.

### 073. Пришельцы: реалистичнее, свой стиль у каждой зоны, сильный рост ступеней
**Дата:** 2026-11-08
**Решение:** меняет стиль решения 072 (основа остаётся: детёныши стражей, шесть семейств, модели из скриптов Blender). Мультяшность уходит: без обводки, румянца и улыбок, глаза — тёмные влажные инопланетные со светящейся радужкой; тела **органические** — из сливающихся форм (метаболы), а не из отдельных сфер. **У каждой зоны свой стиль:** Пояс обломков — био-техно (живое с бронёй, панелями, антеннами), Ледяные кольца — кристалл и лёд (хрустальный червь — прозрачный кристалл), Красная туманность — живые инопланетяне (желе, хитин, свечение), Горизонт событий — космическая материя (тела из туманности со звёздами). **Ступени растут заметно:** узоры → светящиеся прожилки → наросты и аура с огоньками → у легендарного особая «шкура» зоны, гребень или нимб и кольцо частиц. **Метеоритный** — расплавленный камень с лавовыми трещинами, искрами и дымом. Эффекты в игре — частицы и свет Roblox на модели. Порядок: «лестница ступеней» (по виду из зоны, все ступени и метеоритный) на утверждение, потом все 24 вида; просмотрщик 3D показывает все ступени и метеоритный.
**Почему:** пользователь посмотрел мультяшные модели в 3D (2026-11-08): «всё слишком мультяшно — реалистичнее и ближе к космосу», «хрустальный червь розовый — пусть будет хрустальным»; после вариантов стиля — «нужно больше деталей и разнообразия, легендарные не выглядят сильно круче, не хватает эффектов». Свой стиль по зонам даёт разнообразие и ощущение, что чем дальше зона, тем удивительнее существа.
**Отброшено:** один стиль на все зоны; формы из примитивов; генерация нейросетью через MCP (генератор Roblox требует сервер, через MCP не запускается — можно позже вручную через Assistant).

### 074. Пришельцы — питомцы-роботы в гладком sci-fi
**Дата:** 2026-11-08
**Решение:** уточняет решение 073. Из трёх подходов (мультфильм-реализм, гладкий sci-fi, глубокий космос; снимки — `docs/design/concepts/variants/`) выбран **гладкий sci-fi**: пришелец — питомец-робот с керамическим корпусом, тёмным визором со светящимися глазами, светящимися швами и живым ядром (например, слизь под стеклянным куполом). Шесть семейств остаются (слизень, краб, червь, скат, рой, кит) — каждое в своём корпусе. **Зона задаёт отделку и начинку:** Пояс обломков — потёртая оранжевая керамика, Ледяные кольца — матовое стекло и кристаллы внутри, Красная туманность — живая слизь под стеклом и красные акценты, Горизонт событий — чёрная керамика и туманность в стекле. Ступени растут, как в 073: акцентные панели → яркие швы и антенна → голографическая аура и огоньки → у легендарного золотой корпус, нимб и кольцо частиц. Метеоритный — оплавленный корпус с лавой в швах.
**Почему:** пользователь сравнил три подхода крупными снимками: «мне нравится второй вариант». Робот с живым ядром одновременно космический и понятный детям; корпус из гладких деталей хорошо собирается скриптами и легко ложится в Roblox (меши и SurfaceAppearance).
**Отброшено:** мультфильм-реализм и глубокий космос как основа (их находки — живое ядро, полупрозрачность — используются внутри корпусов).

### 075. Три вида у каждого стража
**Дата:** 2026-11-08
**Решение:** у каждого из 24 стражей — **три вида** пришельцев, всего 72 (коллекция: 72 вида × 5 ступеней × 2 варианта = 720). **Основной** вид — детёныш стража (как в 072), **второй** и **редкий** — из других семейств, но в стиле стража: его цвета и его отличительная деталь (у Ржавого краба — ржавый краб, ржавый рой и редкий ржавый кит). Вид выбирается при вылуплении: основной ≈60 %, второй ≈30 %, редкий ≈10 %; ступень и вариант выбираются как раньше. **Доход у видов одного стража одинаковый** — вид отвечает за коллекцию и внешний вид, а не за экономику; баланс не меняется. Модели — по правилам 074: 72 тела, наряд ступеней и метеоритный вариант общие (`assets/blender/aliens/robo_kinds.py`). Код (вид в id пришельца и в сохранении, вылупление, скрещивание, индекс, имена на двух языках) — после утверждения концептов.
**Почему:** пользователь: «что-то мало у нас существ». В зоне жили только 2–3 семейства, и виды выглядели одинаково; при трёх видах из одного семейства в Поясе обломков было бы 9 слизней и 9 крабов, поэтому второй и редкий — из других семейств, и в каждой зоне есть все шесть форм. Редкий вид даёт охоту за коллекцией, не трогая доход.
**Отброшено:** все три вида — детёныши стража (однообразно); новые семейства (больше работы — можно позже); больше стражей (меняет баланс и карту); разный доход у видов.

### 076. Освещение — Realistic, приоритет у дальности
**Дата:** 2026-11-08
**Решение:** `Lighting.LightingStyle = Realistic`, `PrioritizeLightingQuality = false` (в `default.project.json`; в открытом плейсе ставится в режиме редактирования — из MCP получилось, из обычных скриптов нет). Старое `Technology = Voxel` устарело: Roblox заменил его «единым освещением», Voxel соответствует Soft без приоритета. Realistic считает свет в каждом пикселе: блики и тени от наших ламп, объём корпусов; без приоритета качества на слабом устройстве Roblox сначала упрощает свет вдали, а не сокращает дальность прорисовки.
**Почему:** пользователь сравнил тех же питомцев с одной точки в Soft и Realistic и выбрал Realistic. Свечение перестало растекаться белым пятном, космос стал чёрным, корпуса получили светотень — ближе к рендерам Blender (решение 074). Дальность в космосе важнее качества света на горизонте: игрок летит к далёким гнёздам.
**Отброшено:** Soft (бывший Voxel) — плоско, глянец и золото невозможны при любом материале; Realistic с приоритетом качества — жертвует дальностью прорисовки. Проверить на телефоне — до запуска.

### 077. Космическое небо и солнце над станцией
**Дата:** 2026-11-09
**Решение:** своё небо — skybox из шести граней, рендер Blender (`assets/blender/sky/space_sky.py`): тёмный космос, полоса туманности (фиолетовый, пурпурный, бирюзовый), тёплое облако, звёзды разной величины и далёкие планеты (с кольцом, луна, бирюзовая). Звёзды Roblox выключены, они нарисованы в небе. Мир освещает **солнце**: `ClockTime = 10`, видимый диск в небе; планеты в рендере освещены с той же стороны. Тени ещё синевато-фиолетовые, под цвет неба; небо отражается в металле. Все значения — `Config/SkyLooks`, ставит `WorldService`.
**Почему:** в Realistic (решение 076) свет дают только настоящие источники, и ночью питомцы, золото и станция были тусклыми. Пользователь: «фон неба должен быть космическим», а не дневным небом Roblox. Идея из POLISH «Красивый космос вокруг» — её первая часть.
**Отброшено:** ночь с яркими лампами над островами (освещает только станцию, а не гнёзда и стражей); дневное небо Roblox. Позже: цвет неба по зонам и далёкие объекты в мире (POLISH).
*(2026-11-10, пользователь: «в небе надо добавить симпатичные объекты для ориентации», «туманность везде одного цвета — бывают разноцветные», «добавь чёрную дыру», «объекты должны отличаться, слишком мелкие не нужны»: в небе четыре туманности своих цветов и восемь непохожих ориентиров по всему небу — планета с кольцом, луна, ледяная планета, галактика, газовый гигант, комета, красная планета, чёрная дыра с диском.)*

### 078. Знания для агента — на английском
**Дата:** 2026-11-09
**Решение:** база знаний, которую читает в первую очередь Claude (черновики скиллов, сводки вроде `docs/design/BLENDER_ROBLOX.md`), пишется на английском. Остальная документация — по-прежнему на русском.
**Почему:** пользователь: так она занимает меньше токенов и понятнее агенту. Скиллы в `.claude/skills/` уже на английском.
**Отброшено:** весь `docs/` на английском — его читает и пользователь.

### 079. Вид пришельца в игре: id, вылупление, скрещивание, индекс
**Дата:** 2026-11-10
**Решение:** вид из решения 075 — часть пришельца. Id: `<зона><пост>.<вид>.<ступень>[.Meteor]` (`DebrisBelt2.droneRay.Rare`), id вида — как у модели (`robo_kinds.py`, тест держит их в согласии). Вид выпадает при вылуплении 60/30/10 (основной, второй, редкий); удача яйца поднимает только ступень — вид отвечает за коллекцию, а не за доход. Скрещивать можно разные виды одного стража; вид результата — случайный из видов родителей (каждый родитель равновероятен). Набор индекса — 3 вида × 5 ступеней; за пришельца — вдвое меньше минут дохода (0,5–5), за полный набор — 30 минут вместо 15. Имя пришельца — «<ступень> · <вид>»; основной вид носит имя стража, 48 имён второго и редкого видов — в глоссарии. Миграция профиля v15 → v16 делает пришельцев из старых сохранений основным видом стража. Дальше (план `docs/plans/ALIEN_MODELS.md`): рост со ступенью остаётся одним — в `AlienConfig.sizeFactor`, в моделях Blender ступени станут одного размера; модели хранятся в репозитории файлами `.rbxm`, которые Rojo подгружает в игру.
**Почему:** ответы пользователя на вопросы плана — «да на все пункты» (2026-11-09).
**Отброшено:** удача, поднимающая шанс редкого вида (вид стал бы вторым источником дохода от удачи); скрещивание только одного вида (три вида дробили бы и без того редкие тройки); награда за каждую клетку как раньше (индекс втрое дороже по монетам).

### 080. Сколько угодно видов у стража
**Дата:** 2026-11-10
**Решение:** число видов у стража — данные, а не правило. В `AlienConfig` у каждого вида свой **вес вылупления** (`weight`) и место в списке стража (`position`); первый — основной (детёныш стража, его имя). Три нынешних вида — 60/30/10, как в решениях 075 и 079; новый вид (праздничный, ивентовый) добавляется строкой в конец списка своего стража со своим весом — шансы остальных пересчитываются от суммы весов. Набор индекса — все виды стража × 5 ступеней (сейчас 15); награды — те же за пришельца и набор. В окне индекса три строки видов заполняют панель, больше — прокручиваются (бриф `index-kinds.md`). Команда `GiveAlien` принимает вид номером (1 — основной) или id. Слоты «основной/второй/редкий» как тип убраны.
**Почему:** пользователь будет добавлять пришельцев и менять внешний вид (2026-11-10): архитектура не должна держаться за «ровно три».
**Отброшено:** оставить три слота и добавлять новые виды только новыми стражами (меняет карту и баланс); вес по слоту (четвёртому виду некуда встать).

### 081. Модели пришельцев: голые модели в репозитории, одевание кодом, в плейс — вставкой
**Дата:** 2026-11-10
**Решение:** модели видов лежат в репозитории голыми — `assets/aliens/<вид>.rbxm` (10 питомцев вида, только детали из Blender с краской и данными в атрибутах); их пишет `lune run aliens <файл из Studio>` (распаковывает пачку экспорта или срезает одевание), он же — отпечатки `src/server/World/AlienModels.json` и общий файл `out/Aliens.rbxm`. Одевание (краски, металл, лава, свет, частицы, крылья, кометы, руна, медаль) — код игры `World/AlienDress`, перенос принятой галереи; `World/AlienModel` одевает вид и вариант один раз и клонирует. В плейс модели попадают **вставкой** (File → Import Roblox Model, папка `ServerStorage.Aliens`), не через Rojo; в Studio сервер предупреждает о недостающих и устаревших видах; вид без модели стоит шариком. Металл и лавовая кожа — в `default.project.json` (`MaterialService.PetMetal`, `ServerStorage.AlienSkins.Lava`). Рост ступени из Blender игра делит обратно (`AlienLooks.MODELS.TIER_GROWTH`, тест сверяет с `robo.py`), рост — только `alien.scale` (решение 068); Blender не переделывается. Ширина места — по настоящей модели; на полу пришелец уменьшается, пока не влезет в клетку.
**Почему:** живая синхронизация Rojo теряет сетки MeshPart (rojo-rbx/rojo#1221); сервер игры не может задавать карты текстур (`SurfaceAppearance`, `MaterialVariant`) — только Studio; одевание кодом позволяет менять вид без перевыгрузки сеток; без данных столкновений файлы в 12 раз меньше (4,7 МБ на 72 вида). Деление роста в коде вместо правки Blender даёт тот же итог (решение 079) без перевыгрузки 72 видов.
**Отброшено:** модели только в файле плейса (не в git); живая синхронизация моделей через Rojo (теряет сетки); `InsertService:LoadAsset` в игре (запросы при старте сервера); одетые модели в репозитории (вид не поменять без перевыгрузки); переэкспорт Blender с одним размером ступеней.

### 082. Скамья питомцев для замера на телефоне — первый инструмент разработчика вне Studio
**Дата:** 2026-11-10
**Решение:** `BenchService` по кнопке «/bench» докупает игроку места до 30 и ставит на пустые места тяжёлый набор пришельцев (все семейства, много легендарных и эпических, каждый четвёртый — метеоритный, стражи по всей карте — от малышей до гигантов); «/bench clear» убирает их и добавленные пустые места, свои пришельцы игрока не трогаются. Работает в Studio и в живом сервере **только в Dev-игре** (`DevConfig.BENCH_GAME_IDS`) и **только у создателя игры**; атрибут игрока `BenchAllowed` показывает клиенту две кнопки справа (`BenchController`), сервер проверяет право ещё раз. Что сделала скамья (сколько было мест и uid её пришельцев), сохраняется в профиле — поле `bench` (`Domain/Bench`, схема v17): «/bench clear» работает и после перезахода, находит её пришельцев и в инвентаре, и на полу; пока скамья стоит, «/bench» ничего не делает. *(Сначала помнил только сервер: после перезахода остров оставался полным, а очищать было нечего — пользователь, 2026-11-10.)* Кнопки — инструмент разработчика, не экран игрока: без брифа и без перевода.
**Почему:** шаг 4 плана моделей — замер на телефоне с 30 питомцами; команды разработчика работают только в Studio, а их хранилище в Studio не сохраняется; чат у аккаунта пользователя недоступен в регионе, так что команды чата не подходят.
**Отброшено:** все команды разработчика в живом Dev-сервере (шире, чем нужно); команды чата (чат недоступен); замер в эмуляторе Studio (не телефон).

### 083. Пришельцы растут мягче: ×1,074 за стража
**Дата:** 2026-11-10
**Решение:** рост пришельца от стража к стражу — ×1,074 вместо ×1,108 (`AlienConfig.SIZE_GROWTH`; рост ступени ×1–×1,8 прежний). Пришельцы первых стражей — как были, к стражу 24 рост в ≈5 раз вместо ≈10,6: легендарный последнего стража ≈ 30 studs в ширину и ≈ 6 ростов игрока (решение 068 обещало ≈ ×8). Доход и экономика от размера не зависят.
**Почему:** настоящие модели (решение 081) при том же размере вдвое шире заглушки — крылья, клешни, плавники; остров рассчитан под ширины заглушек. На скамье (решение 082, iPhone 16 Pro, пользователь) 30 пришельцев со всей карты слиплись в месиво: раскладка сжала расстояния до ×0,58. При ×1,074 тот же набор встаёт без сжатия (проверено `PlaceLayout` на ширинах скамьи). 30 гигантов только последних стражей по-прежнему встанут плотной кучей — это принято (2026-11-10).
**Отброшено:** все модели вдвое меньше (первые пришельцы ≈ 1 stud — не видно рядом с игроком); острова больше (меняет карту); прежний рост.

### 084. Яйца заметно разного размера: 0,65 / 1 / 1,5
**Дата:** 2026-11-10
**Решение:** видимый размер яиц (`EggConfig.SIZES[…].scale`) — маленькое ×0,65, среднее ×1, большое ×1,5 (было 0,8 / 1 / 1,25): большое теперь вдвое выше маленького, а не в 1,6 раза. Вес и удача размеров не меняются — это только вид. Яйцо любого размера стоит дном там же, где среднее (`EggLooks.liftOf`): в гнезде, в капсуле, в очереди на полу; таймер над яйцом и подсказка «Вылупить» под ним считаются от его настоящей высоты; в руках яйцо отодвинуто от груди на свою толщину. Стекло капсулы выше — 4 studs вместо 3,6, чтобы большое яйцо помещалось. Капсулы и инкубатор ещё будут перерисовываться — тогда их размеры подгоняются под большое яйцо.
**Почему:** пользователь (2026-11-10): «во всех похожих играх яйца ощутимо отличаются размерами»; при 0,8 / 1,25 размер почти не читался, особенно издали и на телефоне.
**Отброшено:** большое ×2 (не влезает в капсулу и гнездо без их переделки); размер яйца от редкости (редкость уже показывает цвет и свечение).

### 085. Набор моделей зон: формы из Blender, вид — кодом
**Дата:** 2026-11-10
**Решение:** камни, кристаллы и кольца зон — один набор форм (`assets/blender/zones/zone_kit.py` → `zone-kit.glb`, 15 форм, ≈30 тыс. треугольников), по одной `MeshPart` на форму в `ServerStorage.ZoneKit` плейса. Как модели пришельцев (решение 081), набор попадает в плейс вставкой, не через Rojo: ассет Open Cloud `137199388945832` вставляется в `ServerStorage`, его детали складываются в папку `ZoneKit`; камням ставится `CollisionFidelity = Hull` (это можно только в Studio), кристаллам и кольцу — `Box`. Тени кратеров запечены в цвета вершин (серые), игра задаёт каждой копии размер, поворот, материал Roblox и цвет (`World/ZoneKit`, `ZoneLooks`): одна форма служит всем зонам. Без набора мир стоит заглушками (шары). Первое применение — гнёзда (план `docs/plans/ZONES.md`, шаг 2): камень с плоским верхом, столб, площадка радиусом 7 вместо чаши 4,5, бортик и ложе — в цвет стража гнезда.
**Почему:** концепты зон приняты (пользователь, 2026-11-10); площадку для кражи просили шире (2026-11-08); бортик в цвет стража выбрал пользователь, чтобы издали было видно, чьё гнездо. Одна форма на все зоны — меньше сеток для загрузки на телефоне; вершинные цвета вместо текстур работают с любым материалом Roblox.
**Отброшено:** свой набор форм на каждую зону (вчетверо больше сеток при том же виде); текстуры `SurfaceAppearance` (игра не задаёт их кодом, решение 081); столкновение по шару для сеточных камней (у сплющенного камня гнезда шар торчал бы над площадкой).

### 086. Терминалы острова — голо-проекторы над низкой консолью
**Дата:** 2026-11-10
**Решение:** терминал у тренажёра, инкубатора и мест (бриф `docs/design/screens/terminals.md`, версия 2) — низкая консоль на круглом основании, на её скошенной к игроку крышке излучатель (кольцо и линза); над ней в воздухе висит экран 6 × 4 прежнего размера и на прежнем месте, в тонкой светящейся рамке с огоньками по углам; от линзы к нижнему краю экрана — веер света (`Beam`, закреплённый в плоскости экрана). Корпус — серо-синяя сталь станции, свет — цвет зоны. Фон экрана — полупрозрачное стекло (0.25) поверх тусклой стеклянной детали: сзади и издалека, где надписи погасли, видно стекло в рамке. «Живой» голограммы (развёртка, искорки) нет. Терминал — две сетки из Blender по одной на материал (`assets/blender/terminals/terminal_kit.py`, `ServerStorage.TerminalKit`, как набор зон — решение 085): `Console` (основание, корпус, крышка; оттенки запечены в цвета вершин, цвет крышки и `Metal` даёт код) и `Glow` (полоса, излучатель, линза, рамка, огоньки; цвет зоны и `Neon` даёт код); обе смоделированы на своих местах, их опора — точка терминала на полу, код ставит их одним `PivotTo`. Плюс деталь стекла экрана с двумя точками крепления луча; сам луч делает каждый клиент (`UI/TerminalScreen`). Итого 3 детали на терминал вместо 15 (9 на остров вместо 45). Поиск формы в плейсе у обоих наборов общий — `World/MeshKit`. Без набора терминал стоит грейбоксом тех же форм.
**Почему:** пользователь выбрал голо-проектор из трёх концептов (стойка-киоск, голо-проектор, робот-помощник): взгляд проходит над консолью, и объект за терминалом виден — прежняя стойка заслоняла инкубатор. Цвет корпуса доверен агенту: сталь станции, чтобы терминал был частью её техники. Луч, повёрнутый к камере, сверху ложился поперёк экрана (пользователь после просмотра в Studio).
**Отброшено:** стойка-киоск (заслоняет больше всех из простых), робот-помощник (крупный, спорит с питомцами за внимание); тёмно-синий корпус первого концепта; луч, повёрнутый к камере; анимация голограммы.

### 087. Центральная станция — кольцо с бегущей строкой, киоски-капсулы и доска-«корона»
**Дата:** 2026-11-10
**Решение:** над куполом центральной станции — кольцо (радиус 94, на высоте ≈ 92) из 8 одинаковых сегментов, в каждом экран снаружи (к своему острову) и изнутри (над платформой); по всем экранам бежит строка киосков — иконка и название, кольцо читается как крутящийся баннер «здесь магазины». Кольцо держат 4 наклонные опоры от края платформы. Корпус под платформой — конус с полосами света и двигателями вместо ступеней; купол станции — своего оттенка. На платформе кругом, лицом к центру (через 90°, радиус 36), — четыре киоска-капсулы (джетпаки, магазин, задания, подарок): перламутровая скорлупа как у питомцев, тёмная внутренность как у голо-терминалов, свой цвет у каждого, сверху значок с иконкой интерфейса и названием; подсказка у стойки открывает то же окно, что плитка меню. В центре — доска монет «корона»: столб, четыре экрана 36 × 26 на высоте ≈ 38 (с решения 111 — 43 × 31 на высоте ≈ 46) на четыре стороны, наклонены вниз к игрокам, над ними золотое кольцо и вращающаяся монета, у столба — голограмма монеты; вблизи экраны показывают топ-10, дальше 110 studs — топ-3 крупно, до 1000 studs. Формы — набор из Blender `StationKit` (`assets/blender/station/station_kit.py`), в плейс вставкой, через общий `World/MeshKit` (решения 085, 086); без набора — грейбокс. Модели — под медленные устройства: одна форма на много копий, треугольников на станцию ≤ 30 тыс., простые столкновения, без текстур, ≤ 4 лампы без теней, без частиц, движение только на клиенте. На телефоне не мерили (пользователь, 2026-11-10: «давай без теста на телефоне»). План — `docs/plans/STATION.md`.
**Почему:** пользователь просил, чтобы станция сама звала к себе и со своего острова были видны доска монет и магазины (решение 069); прежняя доска 12 × 12 с острова — точка. Пользователь выбрал «Кольцо» из трёх направлений (арена с табло, кольцо, шпиль-маяк), капсулу из трёх видов киоска (капсула, робот-продавец, тележка под колпаком) и «корону» из трёх видов доски (башня, пьедестал, корона) — «увеличь в размерах и сделай повыше, это космос, тут большие расстояния». Посмотрев в Studio: киоски, стоявшие наружу, из центра видны спинами — «магазины поверни внутрь»; топ на кольце «не читается» — на его место «подсказку про магазин большими буквами вокруг шара»; топ-10 у края своего острова пропадал (рисовался до 300 studs) — издалека топ-3 крупно. Топ-10 с острова не прочитать ни при каком разумном размере экрана.
**Отброшено:** арена с табло под куполом (силуэт не выходит за купол), шпиль-маяк с лучами; столб света над своим островом («лишнее»); робот-продавец и тележка; киоски кругом наружу (спины из центра) и прежняя доска-стойка («топорно»); топ монет на экранах кольца; доска-башня и пьедестал; надпись с лидером постоянного размера над доской (`BillboardGui`); кольцо одной сеткой (сегменты — одна загрузка на 8 копий и простое столкновение).

### 088. Яйца — керамические капсулы из набора сеток
**Дата:** 2026-11-10
**Решение:** яйцо — капсула в стиле питомцев-роботов и киосков-капсул станции: перламутровая керамика снизу, верх в цвет редкости, шов между ними, иллюминатор спереди. С редкостью наряд растёт так, чтобы редкость читалась издалека и по силуэту, а не только по цвету: **обычное** — вся капсула матово-серая, ничего не светится; **необычное** — перламутр, цветной верх, светится шов; **редкое** — + пояс-обод «летающей тарелки» с огоньками, светящиеся окно и кольцо-ножка; **эпическое** — + светящиеся полосы по куполу, антенна с огоньком и орбита вокруг, как гироскоп; **легендарное** — + золотой верх с короной (металл `PetMetal`, как золото питомцев), вторая орбита и нимб. **Метеоритное** яйцо любой редкости носит ту же лесенку на опалённой капсуле: верх в обгоревшем оттенке цвета редкости, всё светящееся — лава, плюс лавовые трещины и огонь. Набор сеток `assets/blender/eggs/egg_kit.py` → `egg-kit.glb`, по приёмам пришельцев для телефона (BLENDER_ROBLOX.md): **одна деталь на класс материала** — на каждый вид яйца (5 редкостей и каждая из них метеоритной, `Meteor<редкость>`) пластиковый корпус `Body<вид>` с цветами, запечёнными в вершины (перламутр, верх в цвет редкости, тёмные ножка, ободок окна, неосвещённые шов и окно, стержень антенны), и всё светящееся одной деталью `Glow<вид>` (шов, окно, огонёк, орбита, нимб — `Neon` в цвет редкости из `EggLooks`); у легендарного ещё золотой верх `CapGold`; метка `Centre` — центр яйца. Детали лежат там, где их носит среднее яйцо, так что сам набор задаёт, где что сидит (`World/EggKit`). Одна форма — копии на все яйца своего вида (21 форма на игру). В плейсе — папка `ServerStorage.EggKit` (вставка, не Rojo — как набор зон, решение 085). Яйцо в игре — невидимая деталь размером с яйцо (её ставят и двигают сервисы, на ней свет, огонь, след, атрибуты), детали капсулы приварены к ней `Weld` (`World/EggModel`). Яйцо целиком больше не `Neon`; свет `PointLight` — только у эпического (слабый) и легендарного, остальные видны по неону. Бюджет: 1–3 детали и 1,1–2,8 тыс. треугольников на яйцо (метеоритное легендарное — 3,4 тыс., их мало; было 1 деталь-шар, но целиком в неоне и со светом у всех от необычного). Без набора в плейсе яйцо — прежний вытянутый шар. **Маяки над гнёздами:** над гнездом с яйцом от необычного и выше — сквозной столб света цвета редкости через яйцо (вверх и вниз, виден и над гнездом, и под ним), тем длиннее, чем реже яйцо, виден только в радиусе 500 studs (`EggBeaconController`, `EggLooks.BEACON`); у обычного — нет. Столб — `BillboardGui` с шириной в studs плюс пикселях (`Beam` вдали истончался в ноль), строится на клиенте по атрибутам гнезда. Концепты — `docs/design/concepts/eggs/`.
**Почему:** пользователь (2026-11-10) сравнил наши направления (глянец, капсула, стеклянное с ядром) с бесплатными яйцами Toolbox, потом звёздную скорлупу (тёмные звёздные яйца T3–T5 ему нравились) и яйца в капсулах-киосках, и выбрал: «мне нравятся больше капсулы, которые ты ранее показывал» — чтобы было в одном стиле со станцией. Поиграв, сказал, что яйца «слабо отражают уровень редкости», и попросил отделить необычное от редкого не только цветом; у метеоритного редкость не была видна вовсе. Целиком светящееся яйцо выгорало в белый под Bloom (BLENDER_ROBLOX.md, раздел 2), а наряд читается и по силуэту (антенна, орбита, нимб), не только по цвету — важно на телефоне.
**Отброшено:** яйца из Toolbox (решение 072); звёздная скорлупа с туманностью (была в игре недолго: сделана и вставлена, пользователь предпочёл капсулу); яйцо внутри капсулы-киоска с окном и яйцо в чаше-капсуле (`egg-capsules.png`); у редкого — плавники ракеты («выглядит супер странно») и боковые фонари (`egg-rare-marks.png`, выбран пояс); маяки на всю карту со значками сквозь камни («слишком имба» — в `docs/IDEAS.md`, «Радар яиц»); стеклянная скорлупа с ядром (прозрачность дорогая на телефоне, частицы за стеклом не видны); текстуры через `SurfaceAppearance` (игра не красит их кодом).

### 089. Джетпаки: свой корпус у каждого грейда, реактивное пламя из лучей
**Дата:** 2026-11-10
**Решение:** у каждого из 12 джетпаков своя модель из Blender (`assets/blender/jetpacks/jetpacks.py`, концепт `docs/design/concepts/jetpacks.png`), четыре ступени по три: баллоны (Стартовый, Искра, Комета) → двигатель (Плазма, Ион, Пульсар) → крылья (Квазар, Антиматерия, Сингулярность) → легендарные с четырьмя соплами (Гиперпривод, Червоточина, Бесконечность). Пламя — **лучи (`Beam`) из сопла**, не частицы: белое ядро и сужающаяся струя в цвете грейда с прокручиваемой текстурой, `LightInfluence = 0` и `Brightness > 1`, чтобы под Realistic-светом (решение 076) его было видно днём; вид струи меняется по ступеням (огонь → плазма → ударные диски → экзотика), внутри ступени растут длина и яркость. Модели — в `ServerStorage.Jetpacks` плейса вставкой, не через Rojo (как 081, 085); сервер приваривает голый корпус с точками сопел, лучи и свет добавляет каждый клиент у себя. Бюджет (ориентир — телефон, 8 игроков на сервере): ≤ 4 `MeshPart` (детали склеены по классу материала, цвета запечены в вершины) и ≤ 5 тыс. треугольников на джетпак (режим `LOW_POLY`), сопла — `Attachment`; два луча на сопло, без частиц; один свет без теней; свойства эффектов пишутся только при изменении, вдали и при «уменьшить движение» ядро не рисуется. План — `docs/plans/JETPACKS.md`.
**Почему:** пользователь: «пламя с освещением совсем не видно — сделаем настоящее реактивное пламя из сопла; джетпаки и пламя должны меняться с каждым грейдом»; концепт корпусов принят как есть, пламя — ступенями, «с упором на оптимизацию». Частицы `fire_main` под Bloom выжигаются в белый, а слабые теряются на светлом фоне; лучи у пришельцев (`AlienDress.jets`) читаются. Джетпак есть у каждого персонажа, поэтому сетки лёгкие, а эффекты не ходят по сети.
**Отброшено:** корпус из примитивов Roblox (грубее, конусов и колец нет, деталей в 5–8 раз больше — а на телефоне каждая деталь на движущемся персонаже стоит процессора; треугольники — не узкое место, пользователь: «оставляем треугольники»); пламя частицами или светящимся конусом Neon (спайк, решение уроков BLENDER_ROBLOX); новая модель только раз в ступень (пользователь хочет смену с каждым грейдом); крылья вниз вдоль рук (пересекаются с руками) и большие детали за спиной, закрывающие вид камере.

### 090. Стражи — взрослые своих пришельцев; модель видит только клиент
**Дата:** 2026-11-10
**Решение:** страж — **взрослая особь основного вида своего поста** (решение 072: пришельцы — детёныши стражей): та же основа, цвета поста, отделка зоны, формы и фишка, что у детёныша (`robo_kinds.py`), но взрослая и грозная — крупнее и длиннее, броня, шипы (в Ледяных кольцах ледяные, в остальных зонах металлические), хмурый визор с глазами-щелями под «бровями». Модели строит `assets/blender/guardians/adults.py`, концепты всех 24 — `docs/design/concepts/guardians/`. **Сервер** оставляет стража серым телом с двигателями (`World/GuardianModel`): по нему ловит, гонится, на нём табличка. **Модель видит только клиент** (`World/GuardianVisual`): модель поста из `ReplicatedStorage.Guardians` (вставка в плейс, как у пришельцев, — `lune run guardians`, отпечатки `GuardianModels.json`) красится один раз кодом пришельцев (`AlienDress.paintModel`), копия — размером поста (длинная сторона = длина ящика основы × масштаб поста), каждый кадр несётся на теле; ближе 300 studs её части двигаются (`World/RigMotion`, общий с питомцами), темп, челюсть и глотка — по состоянию стража (сон / погоня / возвращение), глаза — в цвет состояния, при поимке — рывок и щелчок пастью. **Эффекты** — только фишка вида, те же, что у питомца (`AlienDress.adornSignature`: пламя, пузыри, фонтан, дым, выхлоп, молнии, звёздная пыль — у 7 постов), сделаны на шаблоне в масштабе одевания питомцев и растут с моделью; играют только ближе 300 studs, вместе с движением; ауры, света, комет и руны, как у питомцев, у стражей нет. Светящееся ядро (желе слизня) притушено вдвое (`GuardianLooks.MODELS.CORE_DIM`): большая неоновая деталь в яркости питомца под Bloom выгорала в белый. Поста без модели в плейсе — серый страж, как раньше. **Бюджет телефона:** ≤ 40 MeshPart и ≤ 8 тыс. треугольников на стража (сейчас 16–37 деталей, до 7,5 тыс.), стая охотников роя — одна роль; 24 набора сеток на 132 стража; по сети — одна деталь на стража. Замер — скамья «/bench guardians» (42 стража Горизонта событий вокруг игрока); на телефоне пока не мерили. Посмотреть всех — «/gallery guardians» (по одному стражу каждого поста). Пользователь посмотрел в Studio: «всё нравится» (2026-11-10).
**Почему:** пользователь выбрал направление из концептов (2026-11-10): «направление нравится», кит — «страшнее», все 24 — «подходят»; план (вид на клиенте, формы детёныша, размеры по постам) — «да на все три». Модель на сервере пришлось бы реплицировать и стримить на 132 стража (~5 тыс. деталей), а части, приваренные к физическому телу под Server Authority, клиент двигать не может.
**Отброшено:** увеличенный легендарный детёныш (выглядит большим питомцем, а не угрозой); модель на сервере, приваренная к телу; модели в `ServerStorage` с клонированием клиенту по запросу; копия логики движения питомцев для стражей (вынесена общая — `RigMotion`).

### 091. Стенд тренажёра растёт с уровнем: шесть моделей и шкала уровней
**Дата:** 2026-11-10
**Решение:** стенд джетпака меняет вид с уровнем тренажёра ступенями: новая модель с уровней 0, 3, 6, 9, 12 и 15 — «Рама» (две стойки и перекладина), «Стенд» (толстые стойки с перламутровыми плечами, топливные баллоны, выхлопное сопло), «Испытательный стенд» (арка над спиной с огнями, баки охлаждения, пульты по бокам), «Ускоритель» (кольцо вокруг игрока со светящимися катушками, столбики с огнями), «Гироскоп» (парящая площадка, кольцо и пояс из перламутра, кристаллы), «Звёздный стенд» — вершина (золото, три кольца, нимб, корона из кристаллов); дальше 15-го вид не меняется. Между моделями по краю площадки — шкала из 15 ламп, с каждым уровнем загорается ещё одна. Стиль — сталь станции (как терминалы, решение 086), перламутр питомцев, свет — жёлтый цвет тренажёра; золото только на вершине. **За стендом нет ничего высокого:** игровая камера смотрит из-за спины игрока, поэтому решётка, куда бьёт пламя (джетпак стреляет вниз), — в самой площадке за пятками, а сзади только низкие выхлопные сопла; кольца стоят в плоскости плеч, камера смотрит сквозь них. Модели — набор сеток `assets/blender/trainer/stand_kit.py` (формы в `stand.py`, концепты `concept_stand.py`, `docs/design/concepts/trainer/`) в `ServerStorage.StandKit` плейса, вставкой, как наборы зон, терминалов и яиц (решения 085, 086, 088); на ступень 4–5 деталей по классу материала — корпус `Body<n>` с оттенками в вершинах (в игре — металл с тёмно-синим оттенком `BayLooks.STAND_BODY_TINT`: свет и цветокоррекция острова красят светлую серо-голубую сталь на пластике в розовый; Studio, 2026-11-10), свет `Glow<n>`, решётка `Grate<n>` (греется на клиенте, как прежняя), дежурные огни `Pilot<n>`, у вершины золото `Gold6` — и 2,8–8,6 тыс. треугольников; метка `Origin` задаёт, где что стоит. Твёрдая только площадка: невидимый диск радиусом ступени, рисуют её детали набора. Ступень по уровню — `Domain/Stand.tier`, лампы — `Stand.dialLit`, ступени и шкала — `BayLooks.STAND_TIERS`, `STAND_DIAL`; одевает стенд `BayModel.dressStand` при каждом изменении уровня (`TrainingService`). Без набора в плейсе стенд — прежний грейбокс. Пользователь посмотрел все ступени в Studio: «все устраивает» (2026-11-10).
**Почему:** пользователь (2026-11-08): каждое улучшение тренажёра должно быть видно на самом стенде, он становится всё круче; уровни не ограничены, поэтому ступени и вершина. Концепты приняты как есть («нормально, делай», 2026-11-10). По калькулятору баланса бесплатный игрок к концу первого дня на 7-м уровне, через неделю — на 11-м, через месяц — на 14-м, к 60-му дню — на 15–16-м: первые ступени сменяются быстро, вершина — долгая цель; лампы показывают каждый уровень между моделями.
**Отброшено:** чаша-отражатель за стендом (в первом рендере закрывала игрока от камеры); модель на каждый уровень (уровней без конца, а 15 моделей на 8 островов — много сеток); вершина с 12-го уровня (её видели бы почти все за неделю, дальше рост не виден).

### 092. Пришельцы без места — на стеллаже с нишами
**Дата:** 2026-11-10
**Решение:** пришельцы, которым не хватило ни места, ни инвентаря (поле профиля `floor`), стоят не в лотке на полу, а на **стеллаже** (бриф `docs/design/screens/storage-shelf.md`): дуга из 8 ниш в 3 яруса (24 ниши — сколько остров и раньше показывал; лишние — только в окне отсека), ≈ 20 × 8 studs, справа от спавна, лицом к спавну, дуга вогнута к проходу. Ниши заполняются со среднего яруса (уровень глаз) от середины к краям, потом нижний, потом верхний (`Domain/Shelf`, тесты); пришелец в нише — маленький, в росте стража 1, уменьшен по ширине **и высоте** ниши (`AlienModel.heightOf`), лицом из ниши. Вид — техника станции: перламутровые стойки, стальные полки и венец, тёмно-синие задние стенки, светлые панели в потолке ниш (запечены в цвета вершин), светящиеся кромки полок и полоса венца — свой цвет хранилища, сине-фиолетовый (85, 70, 255), как и дуга зоны на полу. Набор сеток `assets/blender/bay/storage_kit.py` → `ServerStorage.StorageKit` плейса (ассет Open Cloud 123243423747227; `Body` 3,4 тыс. треугольников, `Glow` 384, метка `Origin`) через общий `World/MeshKit`, как наборы зон, терминалов и стенда (решения 085, 086, 091); числа формы — `Config/ShelfShape`, тест сверяет их со скриптом Blender. Сетки ни с чем не сталкиваются; сквозь стеллаж не пройти из-за 8 невидимых блоков по нишам. Без набора — грейбокс. Фишки дохода над пришельцами на стеллаже видны только ближе 12 studs и висят ниже обычного. В текстах «пол» стал «стеллажом» («На стеллаже: N», «→ на стеллаж»), термин — в глоссарии; ключи и поле профиля прежние. Пользователь посмотрел в Studio: «всё устраивает» (2026-11-10).
**Почему:** пользователь: «выглядит стрёмно — просто модельки на полу валяются». Из трёх концептов (`docs/design/concepts/storage/`: стеллаж с нишами, док-соты, пьедесталы под стеклом) выбран стеллаж: сразу видно, что это запас, компактно, две детали на весь стеллаж. Светлый фиолетовый (176, 128, 255) под Bloom выгорал в белый, насыщенный (120, 60, 255) в цветокоррекции острова уходил в мадженту.
**Отброшено:** док-соты (издали всё та же толпа на платформе); пьедесталы под стеклом (24 прозрачных колпака дороже на телефоне и похожи на капсулы инкубатора); фишки на прежней дальности (24 фишки над стеллажом — каша).

### 093. Звёздный змей — робо-змей в стиле стражей со звёздами; вид на клиенте
**Дата:** 2026-11-10
**Решение:** змей — **робо-змей** в стиле питомцев и стражей (решения 074, 090): перламутровая керамика с фиолетовыми пластинами, голубые неоновые кольца между сегментами, металлические плавники-шипы по спине; голова — шлем с визором и глазами-щелями под V-бровями (хмурый взгляд стражей), челюсть с клыками, рога-антенны со звёздами на концах. От «созвездия» — золотые звёзды: по одной на спине каждого сегмента, на каждом третьем ещё по звезде на боках, и **линия созвездия** лучами (`Beam`) от звезды к звезде по спине. **Звёздное яйцо едет в «короне» на шее**: его видно сверху и сзади, откуда смотрит погоня; выбили — корона пустеет. Глаза говорят о фазе охоты: золотые, пока змей несёт яйцо и убегает, красные, когда он сторожит выбитое. На хвосте — сопло с реактивной струёй из лучей. Модель — набор сеток `assets/blender/serpent/serpent_kit.py` → `serpent-kit.glb`: голова (корпус с запечёнными цветами, глаза, швы, звёзды), яйцо в короне, один сегмент тела (корпус, кольцо, звезда; вариант со звёздами на боках), хвост, метки для отсчёта (`Origin`, `SegmentOrigin`, `TailOrigin`, `JetPoint`). В плейсе — папка **`ReplicatedStorage.SerpentKit`** (вставка, не Rojo, как 081/085). **Сервер** держит прежнюю серую голову с двигателями (`World/SerpentModel`: по ней бьют и ловят); **вид — только на клиенте** (`World/SerpentVisual`): голова набора на серверной голове (серая скрыта у клиента), сегменты — копии одной формы по пути головы, тоньше к хвосту (вдоль — меньше, чтобы хвост не рассыпался на бусины), всё якорное и двигается одной `BulkMoveTo` в кадр. Бюджет: 62 детали и ~25 тыс. треугольников на змея (он один на сервер); эффекты — только лучи (17 линий созвездия и две струи), без частиц и света, кроме прежнего `PointLight` головы. Без набора в плейсе — прежний серый змей из шаров. Чтобы длинное тело не дёргалось на резких поворотах при бегстве, скорость серверной головы догоняет каждое новое направление плавно (`Pursuit.ease`, `SerpentConfig.STEER_RESPONSE` = 6 в секунду), а нарисованная голова поворачивается за серверной с постоянной 0,12 с (`SerpentLooks.MODEL.TURN_SECONDS`); место головы, по которому бьют, не сдвигается. Пользователь посмотрел вживую, ударил и погонялся: «да, всё нравится» (2026-11-10). На телефоне не мерили.
**Почему:** пользователь выбрал из трёх концептов (созвездие, робо-змей, комета-угорь; `docs/design/concepts/serpent/`) «Б + звёзды из А»: стиль игры один, светлое тело видно на тёмном небе и на телефоне, звёзды говорят, что змей звёздный. Змей убегает, и игрок видит его сзади: яйцо в пасти (угорь) оттуда не видно. Вид на клиенте — по тем же причинам, что у стражей (решение 090): по сети идёт одна деталь, а сегменты и так рисует клиент.
**Отброшено:** тёмный звёздный дракон целиком (теряется на тёмном небе, читаются только звёзды); комета-угорь с яйцом в пасти; яйцо под стеклянным куполом (стекло на телефоне дорогое, яйцо за ним не читается); модель на сервере.

### 094. Капсулы инкубатора — «бутоны» из лепестков, некупленные места — закрытые бутоны
**Дата:** 2026-11-10
**Решение:** инкубатор острова (бриф `docs/design/screens/incubator.md`) — подставка радиусом 11,4 со стальным верхом, перламутровым бортиком и светящейся полосой цвета инкубатора, в центре низкий перламутровый нагреватель; от него труба к каждому из 12 гнёзд по кругу радиусом 9 (первое — напротив входа, порядок прежний: `Domain/Incubator.slotAngle`). **Купленное место — раскрытая капсула-«бутон»:** перламутровое гнездо, тёмная плита с кольцом нагревателя, три изогнутых лепестка (перед окном яйца лепестка нет) со светящимися полосами и огоньками на концах; яйцо **парит** над плитой (дно на одной высоте у всех размеров), под ним кольцо света. Стекла нет. **Некупленное место — закрытый бутон** без света: инкубатор с начала выглядит машиной на 12 мест, покупка сменяет бутон капсулой. Свет капсулы — одна деталь, цвет задаёт сервер по состоянию: яйцо греется — оранжевый цвет инкубатора, готово — зелёный, как «Вылупить» (и свет готового яйца — зелёный), пустая — тусклый пластик. Цвета насыщенные: оранжевый (255, 80, 10) — и у терминала, и у линии зоны инкубатора (прежний 255, 170, 60 на островах читался жёлтым, рядом с тренажёром), зелёный (20, 200, 60) — светлый выгорал в белый; пользователь посмотрел в Studio: «да» (2026-11-10). Фишка таймера — ровным рядом над кончиками лепестков, у большого яйца — над ним самим (`Incubator.chipAbove`); «Вылупить» — по-прежнему под яйцом; вспышка вылупления теперь видна (частицы за стеклом Roblox не рисует). Очередь яиц — кольцом за краем подставки (радиус 13). Набор сеток `assets/blender/bay/incubator_kit.py` → `ServerStorage.IncubatorKit` плейса через общий `World/MeshKit` (как решения 085, 086, 091, 092): `DaisBody`/`DaisGlow` (2,3 и 2 тыс. треугольников), `PodBody`/`PodGlow` (1,4 и 1,9 тыс.), `BudBody` (1 тыс.), метка `Origin`; пять сеток на всю игру, остров ≤ 40 тыс. треугольников, без прозрачности и новых ламп. Числа формы — `Config/IncubatorShape`, тест сверяет их со скриптом. Сетки ни с чем не сталкиваются; твёрдые — невидимые диск подставки (атрибуты инкубатора на нём, как прежде), нагреватель и цилиндр на гнездо (`CanQuery = false`: подсказкам и камере не мешают). Без набора — грейбокс: шайба под стеклом, шайба с крышкой.
**Почему:** пользователь (2026-11-09): капсулы «смотрятся слабо», переделать после яиц. Из трёх концептов (`docs/design/concepts/incubator/`: «Колба», «Бутон», «Оранжерея») выбран «Бутон» и закрытые гнёзда на некупленных местах (2026-11-10). Без стекла легче телефону, вспышка вылупления видна, а орбиты и нимб большого легендарного яйца ни во что не упираются.
**Отброшено:** «Колба» — стеклянный колпак на подставке (12 прозрачных деталей на остров, вспышка за стеклом не видна, близко к прежней банке); «Оранжерея» — один стеклянный купол над всем инкубатором (всё сквозь стекло, купол бликует перед пришельцами за ним); показывать только купленные капсулы (инкубатор новичка — две капсулы на голом диске).
**Дополнено (2026-11-11, Prod v1.0.3 на iPhone):** инкубатор весь сквозной — ни подставка, ни нагреватель, ни капсулы с игроком не сталкиваются (пользователь: «сквозь инкубатор нужно проходить»). Невидимые диск подставки и цилиндры гнёзд остаются только как носители атрибутов и главные детали моделей, `CanCollide = false`; невидимый нагреватель убран.

### 095. Гарпун на тросе и гравибомба-гироскоп; эффекты способностей рисует клиент
**Дата:** 2026-11-10
**Решение:** вид гарпуна и гравибомбы — по брифу `docs/design/screens/pvp-abilities.md`, механика прежняя (решения 033, 037). **Гарпун:** на правом запястье стрелка на время выстрела появляется пускач, из него на тросе (два `Beam`: яркая нить и голубой ореол) летит крюк ≈ 3 studs — перламутровое древко, стальной воротник, голубой магнит, три когтя; за крюком короткий `Trail`. Попал — когти смыкаются, расходится кольцо-вспышка; выбитое яйцо дрейфует к стрелку, как раньше (`EggConfig.DROP_SPEED`), и крюк едет на нём, пока оно почти не остановится (не дольше 0,8 с), потом сматывается. Промах — крюк повисает на конце дальности, трос провисает, пустой крюк сматывается. **Бомба:** тёмно-синее ядро со светящимся поясом и огоньком в двух фиолетовых кольцах-орбитах, за ней `Trail`; к концу запала кольца крутятся и огонёк мигает быстрее, последние 0,2 с кольца сжимаются к ядру; взрыв — вспышка и плоское кольцо-волна ровно до радиуса удара (25 studs), без сферы на весь радиус. **Рисует каждый клиент** (CONVENTIONS, раздел 6): сервер больше не строит детали эффектов, а шлёт всем события Zap `HarpoonShot`, `BombThrown`, `BombExploded` (`PvpService` → `NetService`); полёт бомбы на сервере — точка без детали (`World/BombFlight`), клиент ведёт её по той же прямой и ставит в центр взрыва по событию; крюк находит выбитое яйцо по тегу `LooseEgg`, иначе едет по расчётному дрейфу. Чужие эффекты дальше 400 studs не рисуются. Модели — набор сеток `assets/blender/pvp/pvp_kit.py` в `ReplicatedStorage.PvpKit` плейса (вставкой, как набор змея, решение 093): крюк (тело, магнит, когти раскрытые и сомкнутые), пускач и его кольцо, ядро бомбы, пояс, огонёк, одно общее кольцо радиуса 1 (орбиты, волна, вспышка захвата); точки `HookBack`, `Muzzle`; ≈ 4 тыс. треугольников на весь набор. Свой «перед» набор измеряет сам (крюк смотрит от `HookBack`), поворот при вставке не важен. Без набора — грейбокс тех же форм (`World/PvpKit`). Числа вида — `Config/PvpLooks`, формы движения — `Domain/PvpFx` (тесты). Удар (`PvpEffects.strikeImpact`) остался серверным грейбоксом. Концепты — `docs/design/concepts/pvp/`. Набор в плейсе — ассет Open Cloud 102305810487584. Пользователь проверил в Studio по боту-вору и змею: «проверил все ок» (2026-11-10).
**Почему:** пользователь: «надо переделать гарпун и бомбу» (2026-11-10); из трёх концептов на каждую выбрал «гарпун A, бомба A». Прежний грейбокс не показывал ни захвата, ни притяжения, промах выглядел как попадание, а взрыв — плоской сферой, которая на телефоне закрывала экран. Гарпун — предмет на тросе: так называется способность и так нарисована её кнопка, и летящий крюк читается на телефоне; кольцо-волна показывает, кого задело. Эффекты на сервере шли по сети деталями и отставали.
**Отброшено:** луч-тягач (широкий конус света) и магнит на молнии; чёрная дыра (тёмный шар теряется в космосе) и плазменная граната с тремя кольцами (каша на экране); полупрозрачная сфера на весь радиус взрыва; задержка взрыва ради анимации сжатия (механика не ждёт вида: сжатие идёт в конце запала, ранний взрыв его пропускает).

### 096. Полёт на джетпаке под куполом — двойным прыжком
**Дата:** 2026-11-10
**Решение:** уточняет решение 020. Под куполом (центральная станция, острова) джетпак включается **двойным прыжком**: два нажатия прыжка подряд не дальше 0,4 с (пробел, на геймпаде A, на телефоне кнопка прыжка Roblox). В полёте прыжок — это «вверх» (пробел; на геймпаде R1 и теперь ещё A; на телефоне ▲ на месте прыжка), и двойное «вверх» выключает джетпак; ещё он гаснет сам при посадке — держишь «вниз», а пол не пускает. В космосе джетпак всегда включён, как раньше; прилетевший из космоса под купол **продолжает лететь**, вылетевший из-под купола летит дальше. Скорость под куполом — та же ⚡-скорость, что в космосе, с медленным режимом (Q). Под куполом по-прежнему не тратится кислород, нет PvP, нельзя хватать яйца; нести яйцо в полёте можно (доставка — при входе под свой купол или купол центра, как раньше). Тренажёр берёт только пешего: подлетел — сядь, потом встань на стенд. Киоски, терминалы и подсказки «Вылупить» работают и в полёте. HUD: в полёте под куполом кнопка прыжка спрятана, видны вверх, вниз и медленный режим, без атак и прицела (бриф `docs/design/screens/hud.md`). Подсказка: игроку, прошедшему туториал, но не летавшему под куполом, через 4 с после появления — тост «Прыгни дважды — и лети на джетпаке!» (раз за заход); первый полёт под куполом отмечается в профиле (`domeFlightLearned`, схема v18), и подсказки больше нет.
**Как устроено:** `InSpace` по-прежнему значит «вне купола» (кислород, PvP, стражи, буря, доставка). Новое — атрибут персонажа `JetpackOn`: по нему летит симуляция (`SpaceSimulation`), играет поза полёта, горит пламя (`JetpackEffectsController`) и показываются кнопки полёта. Переключатель — `Domain/JetpackSwitch` (тесты): нажатие считается, только если прыжок был отпущен ≥ 0,05 с — Roblox на шаг отпускает прыжок, когда персонаж прыгает, и зажатый прыжок иначе читался бы как двойной. Прыжок симуляция читает и из действия «вверх», и из `Humanoid.Jump` (кнопка прыжка Roblox на телефоне — не наше действие ввода). Посадка — без лучей: «вниз» нажат, джетпак толкает вниз быстрее 4 studs/с, а тело падает медленнее 1 studs/с.
**Почему:** пользователь (2026-11-08, 2026-11-10): «нужна возможность летать даже на станции» — остров и станция большие, пешком долго. Двойной прыжок выбран пользователем вместо отдельной кнопки; скорость — та же, раз есть медленный режим; посадка — чтобы на телефоне не жать дважды «вверх», которое сначала поднимает.
**Отброшено:** отдельная кнопка «Джетпак» (R / L2 / круглая кнопка над прыжком); своя скорость под куполом (как медленный режим или постоянная); при влёте под купол сразу ходьба, как раньше; тренажёр, сам выключающий джетпак подлетевшему.
**Дополнено (2026-11-11, Prod v1.0.3 на iPhone):** посадка — по касанию: ноги у пола (≤ 0,75 studs) под куполом, игрок не поднимается и не держит «вверх» — джетпак гаснет сам, «вниз» держать не нужно (пользователь: долетел до пола, а персонаж летит дальше). Пол ищет луч вниз из симуляции (`WorldRoot:Raycast` разрешён в `BindToSimulation`); рядом с полом спуск ограничен так, чтобы за шаг не уйти ниже пола (`JetpackSwitch.limitDescent`, луч смотрит на два шага падения вперёд). Раньше сила джетпака (1e6) проталкивала быстрого летуна сквозь плиту острова в сплошной корпус под ней, и там «вверх» упирался в корпус — казалось, что кнопка не работает. Было: посадка только с зажатым «вниз», когда пол держит тело. **Кнопка прыжка поверх «вверх»** (скрин пользователя, Prod v1.0.3, iPhone: в космосе на месте ▲ — тёмный круг кнопки прыжка Roblox, нажатия уходили в неё): симуляция выключала прыжок один раз, на переходе «пешком → полёт», и клиент, откатившись мимо этого шага, оставался с включённым прыжком — Roblox свою кнопку не прятал. Теперь три страховки: симуляция каждый шаг сверяет «прыжок включён ⇔ джетпак выключен» (одно чтение `GetStateEnabled`, запись — только при расхождении; без тротла: дёшево, а окно в секунду вернуло бы баг; пользователь: «давай без тротла»); в полёте нажатие прыжка Roblox (`Humanoid.Jump`) тоже «вверх»; клиент (`TouchJumpController`) прячет кнопку прыжка Roblox, пока джетпак включён, и возвращает её после посадки. Отброшено: одна своя кнопка вместо прыжка Roblox (больше кода, свой прыжок вместо стандартного), «вверх» не на месте прыжка (против брифа HUD).

### 097. Звук игры: синтез своим скриптом, стиль «мягкий мультяшный», проигрыватель с лимитом голосов
**Дата:** 2026-11-10
**Решение:** звуки игры — по брифу `docs/design/SOUND.md` (утверждён пользователем): стиль A «мягкий мультяшный» из трёх концептов, тревога стража — вариант «hilo_beeps», 35 звуков. **Синтез своим скриптом** `assets/audio/sfx.py` (библиотека `assets/audio/synth.py`): Python 3.13 с **numpy и scipy** (ставятся в свой venv `pip install numpy scipy`; новые зависимости инструментов — только для этого скрипта, в игру не попадают). Запуск даёт `out/audio/<Name>.wav` и страницу прослушивания; случайность с зерном от имени звука, поэтому файлы одинаковые при каждом запуске и правка одного звука не меняет другие. Громкость файлов выровнена так, как её слышит динамик телефона (без баса ниже 200 Гц), удары и взрывы держатся на середине. Петли (тревога погони, джетпак) бесшовные. Звуки загружаются в Roblox от владельца игры (Open Cloud), id — в `Config/SoundLooks.GAMES` по играм (`game.GameId`: Dev сейчас, у Prod сообщества могут быть свои; звуки аккаунта нужно расшарить на её игру), там же громкость, группа, важность, «слышно до» (одна правда). Клик кнопок — прежний звук Roblox.
**Как играет:** клиентский `Audio/SoundPlayer` — не больше 8 голосов сразу, один звук не чаще раза в 0,08 с и не больше трёх копий; при полном наборе важный звук вытесняет самый неважный (`Domain/SoundVoices`, тесты). Звук «мира» — на `Attachment` или части с `InverseTapered`, дальше «слышно до» не запускается. Общая `SoundGroup` с группами «Мир», «Интерфейс», «Тревога»; своего ползунка громкости и кнопки «без звука» нет (пользователь) — громкость в меню Roblox. Чтобы клиент знал, за кем гонится страж, сервер пишет на модель стража атрибут `Target` (UserId); выпавшее яйцо несёт `DroppedAt` (свежая потеря — звук, пришедшее стримингом — нет); удар (`StrikeImpact`) и метеор (`Meteor`, с атрибутом `Target`) помечены тегами.
**Почему:** пользователь просил свои звуки, без чужих с неясной лицензией, и послушать концепты прямо в сессии; синтез даёт единый стиль и правку любого звука числом. Ориентир — телефон: мало голосов, громкость по расстоянию.
**Отброшено:** концепты B «игрушечная электроника» (8 бит) и C «глянцевый неон»; звуки Creator Store (стиль не собрать воедино); ffmpeg/sox (не установлены, numpy+scipy хватает).

### 098. Подарок за вступление в сообщество: +10 000 натренированной скорости после туториала
**Дата:** 2026-11-10
**Решение:** игрок, состоящий в Roblox-сообществе игры «Fly & Steal Space Eggs» (ID `1096766348`, по играм в `CommunityConfig`, как каталоги `MonetizationConfig`), один раз на профиль получает **+10 000 к натренированной скорости**; видит он её с множителем джетпака (со стартовым — ⚡+10K, с ×32 — ⚡+320K), и с новым джетпаком подарок растёт вместе со всей скоростью. Предлагается и выдаётся только **после туториала** (веха 4): плитка меню «Сообщество» (шестая, клавиша K) с окном «Вступить» → встроенное окно Roblox `GroupService:PromptJoinAsync`; когда туториал кончился — тост-приглашение. Членство проверяет только сервер (`GroupService:GetGroupsAsync`, с повтором) — при входе, в конце туториала и по запросу клиента после окна Roblox (раз в 5 с); вступивший, пока был не в игре, получает подарок при следующем входе. Флаг `communityGiftTaken` в профиле (схема v19): выход из сообщества и новое вступление второй раз не дают. Награда только за вступление — ничего за лайк и «в избранное», ссылок на Discord и соцсети в игре нет. Бриф — `docs/design/screens/community.md`.
**Почему:** пользователь (2026-11-10) сначала выбрал разово 100 000 ⚡, но по `lune run balance` это рекомендация стража 8 (121K, ~45 мин игры): новичок перескочил бы 7 стражей. Тогда — как в игре-ориентире: 10 000 × множитель джетпака, «неважно, когда он взял награду — она будет полезной». Новичку сразу после туториала это ~страж 6 (обычно ~18 мин), к концу первого дня — около 1 % скорости. После туториала — чтобы первые минуты ничего не отвлекало от подсказок и шаг «Тренируйся» не проскакивал. `GetGroupsAsync` вместо `Player:IsInGroupAsync`: тот кэширует ответ на сервере (окно Roblox сбрасывает кэш только на клиенте), и вступивший в игре до перезахода не получил бы подарок.
**Отброшено:** 100 000 ⚡ ровно (ломает начало); подарок с первой секунды (проскакивает туториал); постоянный бонус, пока в сообществе (вариант Б плана, — пользователь выбрал разовый); окно, открывающееся само (хватает тоста и бейджа).

**Дата:** 2026-11-11

Текста на картинках нет, чужих картинок и шрифтов нет.

**Отброшено:** направления «Погоня от пасти кита», «Яйцо в клешнях краба», «Домой к станции» (первые наброски); самодельный пилот в скафандре и блочный «под Roblox» с волосами; варианты иконки для теста (эпическое яйцо, Красный рой, бирюзовый и закатный фон).

### 100. Выпуск: Studio → Dev-игра → метка версии → Prod
**Дата:** 2026-11-11
**Решение:** две игры (решение 011). Dev — `10774871729`, Prod — «Fly & Steal Space Eggs», universe `10775754016`, плейс `113469823655044`, владелец — сообщество. Порядок такой:

Prod создан копией Dev-плейса (File → Publish As, 2026-11-11): наборы, вставленные руками, и ручные настройки плейса пришли с ним. Звуки и анимации остались у аккаунта пользователя, Prod получил на них право `Use`. Порядок и чек-лист — `docs/RELEASE.md`.
**Почему:** пользователь хочет тестировать всё в Dev, а в Prod отдавать только готовое. Публикация из Studio сохраняет вставленные руками наборы, а `rojo upload` заменил бы плейс целиком. Метка показывает, какой код сейчас у игроков, и даёт базу для срочных исправлений.
**Отброшено:** `rojo upload` (стирает наборы); один плейс с переключателем окружения (решение 011: общие DataStore); отдельная ветка `release` (метки проще для одного разработчика).

### 101. Производительность: питомцы и камни без теней, модель стража — только вблизи
**Дата:** 2026-11-11
**Решение:** пачка А плана `docs/plans/OPTIMIZATION.md` (варианты 1, 2, 7). Условие пользователя на всю пачку: менять только то, что в обычной игре практически не видно; исключение — тени, они пользователю важны меньше всего.
- **Питомцы не отбрасывают теней** (вариант 1): `AlienDress` при подготовке ставит `CastShadow = false` всем деталям питомца (раньше — всем, кроме неоновых, ~16 на питомца). Тень только от корпуса не делали: выигрыш почти тот же, а логика выбора деталей лишняя. Так же без теней камни астероидов и все детали гнёзд и кратеров (`WorldService`, ~1 360 деталей; кристаллы и кольца астероидов теней не отбрасывали и раньше): в космосе их тень ни на что видимое не падает.
- **Модель стража — только вблизи** (вариант 2): `GuardianViewController` надевает модель поста, когда тело стража ближе к камере, чем `max(ATTACH_DISTANCE, ATTACH_LENGTHS × длина) + половина длины` (`GuardianLooks.MODELS`: 700 studs и 60 длин; `GuardianPose.wearReach`), и снимает на `ATTACH_MARGIN` = 100 studs дальше (`GuardianPose.wears`, тесты). 60 длин — чтобы в момент смены страж занимал не больше 1/60 радиана (< 1°) экрана: обычный страж (6–13 studs) меняется на 700–800 studs, кит (24 studs) — на ~1 450. Дальше виден серый страж сервера — тело в цвете поста и глаза цвета состояния, как у поста без модели; табличка с именем висит на теле в обоих случаях. Серое тело прячется у клиента `LocalTransparencyModifier` (обратимо, без запоминания прозрачности). Расстояния — 4 раза в секунду (`ATTACH_CHECK_SECONDS`), за кадр надевается не больше одной модели, ближние первыми; `PreloadAsync` сеток — при надевании. Стражи скамьи стоят рядом с игроком и получают модели сразу.
- **Мелочи** (вариант 7), все без изменения вида: строки доски монет уходят клиентам, только когда меняется то, что доска показывает (порядок, имена, монеты в `BigNum.format` — три знака), а не каждую секунду дохода; руна и свечение под питомцем рисуются ближе 120 своих ширин (`AlienLooks.MODELS.RUNE_MAX_WIDTHS`, там они < 0,5°; раньше — без предела); ближайшее яйцо для кнопки захвата ищется 10 раз в секунду, пока ни одного нет в `Grab.watchRange` (дальность кнопки плюс путь за 0,1 с на двойной предельной скорости и дрейф яйца), рядом — каждый кадр, так что кнопка появляется так же сразу; лампы стендов пишутся при изменении; монеты доски крутятся, только пока камера ближе 1 000 studs; всплывающие цифры тренажёра — из запаса. Не сделано: таймеры яиц только у видимых — фишка, вошедшая в свои 35 studs, до секунды показывала бы старое время; выключать руну вместе с дальней детализацией (160 studs) — там её видно; Bloom с силой 0 — настройка плейса, на этап проверки в Studio.
- **Bloom** (2026-11-12): выключать Bloom с силой 0 нельзя — без включённого `BloomEffect` Roblox рисует своё свечение неона, гораздо сильнее; после такой «оптимизации» неон стал слепить (пользователь). Bloom ставит сервер (`WorldService`, числа — `SkyLooks.BLOOM`), всегда включённым, с силой 0,15: неон светится мягко (сила 0 — без свечения совсем, как было до оптимизации; 0,5 — ярче свечения Roblox). Так Dev и Prod одинаковы без ручной настройки плейса.
**Почему:** замер 2026-11-11 (свой остров, скамья 30 питомцев, `docs/plans/optimization/measurements-2026-11-11.md`): питомцы двигаются каждый кадр, и движок каждый кадр заново рисует тени всех их деталей — ~967 из 2 717 вызовов отрисовки за кадр (36 %). Все тени питомцев выключены: вызовы теней 997 → 26, треугольники теней 454 тыс. → 19 тыс., GPU 4,4 → 2,7 мс (настольный компьютер). Модели всех 132 стражей карты (3 293 детали, 617 разных сеток — 86 % сеток входа) стояли у каждого клиента сразу: без них с острова 678 → 234 вызова отрисовки, сверху над станцией 864 → 216, в Горизонте событий 1 507 → 450; с острова ближе 1 000 studs всего 17 стражей из 132. Телефон греется, а время CPU на отрисовку там почти прямо зависит от числа вызовов.
**Отброшено:** тень только от одной-двух крупных деталей корпуса (сложнее, а тень на полу купола и так почти не видна); проредить частицы питомцев (пользователь любит их такими); одна граница 700 studs для всех стражей (кит там — почти 2° экрана, смена была бы заметна).

### 102. Порядок загрузки на клиенте: сначала свой джетпак, остальное — очередью за ним
**Дата:** 2026-11-11
**Решение:** все `ContentProvider:PreloadAsync` клиента идут через `Loading/AssetQueue` (порядок — `Domain/LoadOrder`, числа — `LoadConfig`). Свой джетпак (сетки корпуса и текстуры огня и следа) запрашивается сразу, как модель появилась на персонаже, и снова после каждой смены модели (`JetpackLoadController`, `AssetQueue.now`). Остальные предзагрузки (`AssetQueue.later`) ждут, пока на персонаже не будет загружен джетпак уровня игрока (атрибут `JetpackLevel`; Стартовый, надетый до загрузки профиля, не в счёт) или не пройдут 20 с, и идут по одной по приоритету: чужие джетпаки → звуки → змей и стражи рядом → питомцы своего острова → чужие питомцы → листы иконок. Одна задача держит следующую не дольше 8 с. Новая предзагрузка — только через `AssetQueue`, не прямым `PreloadAsync`.
**Почему:** в Dev-игре на iPhone корпус джетпака появился через 30–40 с после его следа (2026-11-11). Каждый `PreloadAsync` ставит свои ассеты в начало очереди загрузки клиента (так пишут на DevForum; справка Roblox о приоритете молчит), а на входе их шло много (по вызову на каждого питомца каждого острова, 36 звуков, 24 листа иконок, сетки стражей), джетпак же не запрашивался вовсе — его сетки ждали за всем этим; след — `Trail` без ассетов (у первых джетпаков без текстуры) — был виден сразу. Studio, 2026-11-11 (кэш тёплый, скорость не ограничить): свой джетпак запрошен на 0,4 с, очередь открыта на 0,7 с, за ней 7 стражей у острова, звуки, иконки; смена джетпака (`SetJetpack` 0, 5, 11) и респаун запрашивают новую модель сразу; сетки и текстуры огня — `Success`.
**Отброшено:** экран загрузки (дольше путь в игру); показ старой модели, пока грузится новая (сервер уничтожает старую при смене, у клиента её копии нет, а на входе Стартовый к моменту смены обычно ещё не загружен сам); загрузка сеток джетпака следующего уровня заранее (шаблоны в `ServerStorage`, клиенту их id не видны).

### 103. «Вниз» в полёте — Shift вместо Ctrl; shift lock Roblox выключен
**Дата:** 2026-11-12
**Решение:** уточняет решение 020. На ПК «вниз» — левый Shift (было Ctrl); на геймпаде по-прежнему L1. В уголке иконки «вниз» — «Shift» (`key.shift.hint`). В плейсе выключен shift lock Roblox: `StarterPlayer.EnableMouseLockOption = false` (в `default.project.json`, плагин Rojo пишет его в плейс) — пункт «Shift Lock Switch» пропадает из настроек игрока.
**Почему:** пользователь после плейтеста с друзьями (2026-11-12): держать Ctrl неудобно. Shift lock тоже берёт Shift: у игрока, включившего его в настройках, каждое нажатие «вниз» переключало бы блокировку мыши. Он не нужен: в полёте персонаж и так смотрит, куда камера.
**Отброшено:** оставить Ctrl вторым вариантом (подсказка показывает одну клавишу, а пользователь просил уйти от Ctrl); оставить shift lock (спорил бы со спуском).

### 104. Буря переносит только из-за границы станции; яйца в космосе в бурю уходят домой
**Дата:** 2026-11-12
**Решение:** уточняет решение 049. В начале бури на спавн переносятся только игроки в космосе **за границей станции** (`Domain/Storm.bringsHome`: `InSpace` и дальше `StormConfig.RANGE_RADIUS` от центра купола); их яйцо из рук, как раньше, возвращается домой. Кто внутри границы — под любым куполом или в полёте между островами и центром — остаётся на месте и с яйцом, граница бури просто держит его внутри. Пока буря идёт, в космосе нет выпавших яиц: лежащие возвращаются домой сразу в начале бури (гнездо, кратер, змей — по правилам `Domain/EggHomes`), выбитое в бурю (удар, гарпун, смерть) — сразу же, не повисая (`CarryService.setLooseEggSweep`). Яйца в руках буря не трогает.
**Почему:** пользователь (2026-11-12): летел от своего купола к центру, а буря вернула его на остров — внутри границы перенос не нужен, вылететь дальше всё равно нельзя. Выпавшие яйца буря «сметает», чтобы после неё никто не подбирал их в одиночку у пустой карты.
**Отброшено:** не переносить и тех, кто в куполах (они и так не в космосе, `InSpace = false`); выпавшие в бурю яйца оставить до конца бури.

### 105. Телефон: окно «Управление», один тост на вылупления подряд, заливка удара на весь экран
**Дата:** 2026-11-12
**Решение:** по замечаниям плейтеста с друзьями (брифы `controls.md`, `toasts-and-signs.md`, `store.md`, `hud.md`):
- **Окно «Управление»** (`ControlsController`, `UI/ControlsWindow`): что делает каждая кнопка полёта — 8 строк (лететь, вверх, вниз, медленный режим, схватить, удар, гарпун, гравибомба), кнопка как на экране и одна фраза; на ПК и геймпаде — клавиша в уголке из настоящих привязок (`UI/KeyNames`, им же пользуется ряд действий HUD). Открывается само один раз за вход у новичка (шаг туториала 1 — ещё ничего не доставил), снова — плиткой «?» в меню (слот `Controls`, клавиша H, после индекса). Галочка **«Больше не показывать»** (пользователь: «иначе лишняя нагрузка на HUD») убирает плитку навсегда и окно больше не открывается само: флаг `controlsHidden` в профиле (схема v20), команда `SetControlsHidden`, сервер (`ControlsService`) публикует его атрибутом `ControlsHidden` на игроке. Клавиша H открывает окно и со снятой плиткой — так можно передумать.
- **Вылупления подряд — один тост** (`ToastState`: у тоста может быть группа, новый тост той же группы заменяет старый на его месте), со счётчиком и лучшим по доходу; вторая строка тоста — доход пришельца и куда он попал (`alien.hatchedIncome.hint`). Так же — у скрещивания и у находок в индексе («В индексе 3 новых пришельца!»). Тостов на экране не больше 3 (было 4).
- **Заливка «Поймали!»** — свой `ScreenGui` без отступов и обрезки (`ScreenInsets = None`, `ClipToDeviceSafeArea = false`), под HUD.
- **Карточки магазина** раскладываются строками сверху вниз; цена — в строке с числом или названием, колонка пропусков 270 точек.
**Почему:** на iPhone четыре двухстрочных тоста закрывали середину экрана, а доход пришельца не было видно; в магазине цена налезала на «⚡+5.9M» (окно на телефоне ниже макета: 324 точки вместо 363, а части карточки стояли долями высоты); игроки не понимали кнопки полёта; красная заливка обрезалась по безопасной зоне — `ScreenGui` с отступами обрезает всех своих детей по ней, запас в 400 точек за краем не помогал. Галочка хранится в профиле, а не на устройстве: у Roblox нет клиентского хранилища, а на другом устройстве выбор игрока тот же.
**Отброшено:** подписи на самих кнопках полёта (DESIGN.md: иконки без подписей); кнопка «?» у кнопок полёта (тесно, случайное нажатие в погоне); окно при первом вылете в космос (там тратится кислород, пока читаешь); очередь тостов вылупления по одному (дольше и всё равно стопка).

### 106. Прицел PvP: доводка гарпуна, самонаведение бомбы, скорость стрелка
**Дата:** 2026-11-12
**Решение:** уточняет решения 033, 037 и 095. **Скорость стрелка.** Бомба вылетает со скоростью бросающего плюс 80 studs/с по прицелу (`Domain/Homing.launchVelocity`): на любой скорости полёта она уходит вперёд. Есть цель — бомба при броске ещё и разгоняется вдоль линии на неё так, чтобы сближаться с целью не медленнее 80 studs/с (`Homing.ensureClosing`): так попадаешь и по тому, кто летит быстрее тебя. Крюк гарпуна летит и сматывается относительно стрелка: путь от дула до цели — за одно и то же время, где бы стрелок ни был, конец дальности промаха едет вместе со стрелком (`World/HarpoonVisual`; событие `HarpoonShot` несёт направление выстрела `aim`). Своя бомба у себя рисуется от своего персонажа: персонаж игрока у себя впереди серверного на время пути по сети, и на скорости бомба появлялась бы далеко позади. **Доводка гарпуна.** Конус 18° и 70 studs (было 8° и 50); из носителей яйца в конусе, которых правила разрешают атаковать, берётся тот, на ком прицел лучше всего: меньше всех «угол / полуугол + расстояние / дальность» (`Abilities.bestInCone`). Были в конусе только защищённые правилами — отказ с тостом, как раньше; удар по-прежнему берёт ближайшего. **Самонаведение бомбы.** При броске она выбирает цель так же (любого, кого можно атаковать: игрока с яйцом и без, бота-вора, змея) в конусе 30° и 120 studs и летит к ней (`Domain/Homing.steer`): в системе цели гасит боковой снос и сближается не медленнее 80 studs/с, меняя скорость не больше чем на 180 studs/с² — прямо летящего догоняет, резкий поворот уводит. Цель ушла под купол, умерла или пропала — летит прямо. Запал 1,5 с (было 1; за него бомба покрывает все 120 studs наведения), касание 8 studs (было 6), и касание ищется по всему шагу с учётом движения цели (`Homing.closestApproach`): на скорости бомба проходит несколько studs за кадр. Радиус и перезарядка прежние. **Волна взрыва задевает.** В миг взрыва задеты все в радиусе 25 studs, как раньше; потом, пока кольцо-волна растёт (0,3 с) и держится (0,12 с), сервер каждый кадр проходит по нему тем же радиусом, что рисуется (`PvpFx.waveReach`, `Abilities.waveStep`), и задевает влетевших; каждого — один раз, итог броска считается, когда волна погасла. Тайминг волны один на механику и вид — `PvpConfig.BOMB_WAVE` (`PvpLooks.BOMB.wave` ссылается на него). Радиус не увеличен: бомба и так стала сильнее; он настраивается `PvpConfig.BOMB.radiusStuds`. **Кто решает.** Как раньше, сервер (`PvpService`, `World/BombFlight`); клиент повторяет тот же выбор для кольца захвата в прицеле (`World/AimTargets`: правила — насколько клиент их знает, без защиты после появления) и ведёт бомбу к цели из события `BombThrown.target` — центр взрыва всё равно от сервера. Числа — `PvpConfig.HARPOON`, `PvpConfig.BOMB`, тесты — `tests/Domain/Homing.spec.luau`, `Abilities.spec.luau`.
**Почему:** плейтест с друзьями (2026-11-12): «прицелиться почти невозможно, бомба почти бесполезна»; на быстром полёте гарпун и бомба улетали назад — бомба летела 40 studs/с, а игроки летают 30–250; на телефоне нет мыши, и узкий конус там не попасть. Пользователь (2026-11-12): «учти скорость убегающего тоже, надо чтобы я мог попасть по врагу быстрее меня». Он же: «При взрыве нужно чтобы волна задевала тоже» — влетевший в растущее кольцо видел касание, а удара не было. Конус и дальность шире ещё и потому, что клиент видит других игроков с отставанием, а сервер проверяет по своим позициям.
**Отброшено:** клиент присылает выбранную цель (лишнее событие и доверие клиенту); компенсация задержки на сервере (широкий конус её покрывает); поворот вектора скорости бомбы к цели с постоянной угловой скоростью (бомба, унаследовавшая скорость стрелка, отстаёт от цели, летящей параллельно); бомба, перевыбирающая цель в полёте.

### 107. Звёздный змей петляет по всему поясу стражей; голова шире
**Дата:** 2026-11-12
**Решение:** меняет маршрут из решения 055 и шар попадания головы, остальное прежнее. **Маршрут** (`Domain/SerpentRoute`, тесты): пока яйцо в змее, он летит не к случайным точкам кольца своей зоны и не прямо прочь от игрока, а по **извилистому пути через весь пояс стражей** — от `SerpentConfig.INNER_RADIUS` (граница станции + 40 studs) до края карты (`OUTER_RADIUS`), в пределах ±150 studs по высоте. Путь — от точки к точке вокруг станции: следующая лежит на 200–450 studs дальше по кругу, ближе или дальше от станции не больше чем на 450 studs, на случайной высоте; поворачивает змей не круче радиуса 100 studs (`ROUTE.turnRadius`), поэтому путь — плавные дуги; изредка (5 % на точку, ≈ раз в 3 мин) разворачивается в другую сторону. У краёв пояса он заранее отворачивает вдоль края, а сервер всё так же не пускает его внутрь (`Bounds.keepOutside`): **в купола змей не залетает** (все купола внутри границы станции). Скорость — как раньше: 60 studs/с без игроков рядом, скорость бегства своей зоны, когда кто-то ближе 150 studs. **Погоня:** змей не убегает от игрока прочь (так он упирался в край карты), а **продолжает кружить вокруг станции**, только быстрее: по кругу в сторону от игрока (игрок срезал и оказался впереди — разворот), и каждые 1,6 с виляет то дальше от станции и выше, то ближе и ниже (до 150 studs вбок, `swerveRadial`, `swerveSeconds`, `swerveClimb`), с медленным дрейфом внутрь или наружу — широкая S вдоль круга. Догоняющий срезает углы: по расчёту теста игрок с ⚡ змея догоняет его за 3–5 с, наравне со змеем (90 % скорости игрока с его ⚡) — за 15–20 с, на 15 % медленнее змея — никогда (раньше по прямой ловил только тот, кто быстрее змея). **Сторож:** выбитое яйцо змей охраняет, как страж, до границы станции (раньше — до Пояса обломков): вор в безопасности, когда влетел за границу. **Попадания** (удар, гарпун, бомба) засчитываются **только по голове**, как раньше, но шар шире: 12 studs от середины головы вместо 7 (`SerpentConfig.HIT_RADIUS`; нарисованная голова с плавниками и рогами — около 8). Тело не в счёт: догнать голову убегающего змея — это и есть вызов (пользователь). Чтобы было видно, куда бить, вокруг головы — **кольцо-прицел** (бриф `docs/design/screens/serpent-target.md`, `World/SerpentTarget`, `SerpentLooks.TARGET`): круг ровно по зоне попадания (24 studs) с четырьмя засечками, цвета кнопки удара, всегда к камере, «дышит»; попадание — белая вспышка и сжатие; только пока яйцо в змее; ближе 400 studs; одна `BillboardGui` из пяти рамок. `Pursuit.fleeVelocity` убран.
**Почему:** плейтест с друзьями (2026-11-12): змей «бегает всегда по прямой», «попадать очень сложно». Шар попадания (7 studs) едва доходил до края шлема, а гонятся за змеем сзади. Пользователь попросил, чтобы змей облетал всю зону стражей и не залетал в купола, а бить — только в голову («нужен челлендж»), но пошире, и явно показать, что бить надо в голову.
**Отброшено:** петлять только в кольце своей зоны (просили всю зону стражей); бегство прочь от игрока, по прямой или виражами (пользователь: змей «стремится к границе мира», нужно, чтобы он кружил по всей карте); частые развороты на прогулке (20 % на точку — в Studio змей ходил туда-обратно); попадания по всему телу (пользователь: «так нельзя», нужен челлендж); оставить вора в безопасности уже в Поясе обломков (яйцо, выбитое там, было бы без охраны).

### 108. Стражи: садятся за время, а не в радиусе; сила словом и значком; удар −10 % кислорода; сирена по сближению
**Дата:** 2026-11-12
**Решение:** по замечаниям после игры с друзьями.
- **Страж у гнезда и над выпавшим яйцом подлетает к точке за время** (`Pursuit.settleVelocity`, `GuardianConfig.SETTLE_SECONDS` = 0,25 с): вблизи скорость = расстояние / 0,25 с, не больше крейсерской. Каждый тик (1/15 с) он проходит одну и ту же долю остатка, какой бы быстрый ни был. Радиус подлёта в studs (`ARRIVE_RADIUS` = 6) убран.
- **Сила стража — ступенью, а не цветом имени** (`Speed.challenge`: Слабый / По силам / Сильный / Не уйти, бриф `docs/design/screens/guardian-labels.md`, вариант А): имя белое, под ним плашка со значком и словом в цвете ступени. Границы те же, что у прежнего цвета (`Speed.standing`): «Слабый» — на `CHALLENGE_WEAK_DECADES` = 1 порядок ниже тебя, «Не уйти» — где страж летит против тебя на `maxRatio`. Та же подпись — над головой Звёздного змея (сила стража его зоны на посту `POWER_POST`). Подпись задана в studs (`GuardianLooks.LABEL`): её плавно уменьшает перспектива камеры; ближе 50 studs она не растёт, дальше 320 не уменьшается — за границей она один раз переключается на постоянный размер в пикселях, равный размеру на границе (`GuardianPose.labelPixelsPerStud`); вблизи имя ≈ 6 % высоты экрана, вдали < 1 %; дальше 250 studs подпись бледнеет до 60 % прозрачности (`labelFade`); видна до 650–1450 studs по зонам. *(Уточнено 2026-11-12 после v1.1.0, пользователь одобрил: сначала подпись была в пикселях и уменьшалась `UIScale` от 100 % до 60 % — ближние и дальние были похожи, а ступеньки масштаба по 1 % с перестроением текста дёргались при подлёте; подгонка размера в studs ступеньками по 2 % за границами тоже пульсировала. Встроенные `DistanceLowerLimit`/`DistanceUpperLimit` у `BillboardGui` устарели, поэтому пределы держит скрипт.)*
- **Удар стража снимает 10 % баллона** (`OxygenConfig.GUARDIAN_HIT_SHARE`, `Oxygen.afterHit`); сервер пишет атрибут кислорода при поимке, симуляция продолжает с него, как после `RefillOxygen`. При меньше 10 % удар опустошает баллон, и вор задыхается обычным путём (`SpaceService`: смерть, `floatWhenDead`, появление на острове) — так решил пользователь. С `SetInfiniteOxygen` в Studio удар кислород не трогает.
- **Сирена погони растёт по мере сближения** («Приближается!»: пользователь хотел звук «от тихого к громкому»): громкость и скорость петли `AlarmLoop` — от того, через сколько секунд страж догонит при нынешней скорости сближения и как он близко (`SoundVoices.approachLevel`, `chaseMix`, `SoundLooks.CHASE`): тихо (25 %, обычная скорость) за 5 с / 150 studs, в полную силу и на 30 % быстрее за 1 с / 15 studs. Начальный сигнал `AlarmStart` — как раньше. Прежняя громкость «сначала громко, потом 60 %» убрана.
**Почему:** при радиусе подлёта 6 studs скорость вблизи точки росла с крейсерской: у стражей быстрее 90 studs/с (с середины Ледяных колец) шаг тика проскакивал точку, быстрее 180 studs/с (Красная туманность и Горизонт событий, кит ~240) — ни разу не садился: метался через точку ±8 studs 15 раз в секунду и каждый тик разворачивался (поворот — по скорости). Это и было «дёргается вверх-вниз». Цвет имени друзья читали по-разному, а у змея силы не было видно совсем. Без потери кислорода новичок таскал яйца с края карты, проигрывая каждую погоню, и проскакивал развитие.
**Отброшено:** сглаживать дрожь только на клиенте (сервер всё равно метался бы, а поимка считается по серверному телу); значок без слова и шкала делений (варианты Б и В макета); удар, оставляющий каплю кислорода.

### 109. Метки игроков и яиц на экране; позиции — атрибутами `Player`; свой остров в цвете дома
**Дата:** 2026-11-12
**Решение:** бриф `docs/design/screens/markers.md`. Клиент (`RadarController`, `UI/RadarMarker`) рисует в экранном пространстве метки всех других игроков по всей карте (под куполом тоже, кроме стоящих вплотную; имя Roblox над головой скрыто — сначала игроков под куполом и ближе 80 studs не отмечали, и в Prod v1.1.1 друзья не видели меток друг на друге), вора — таблеткой в цвете редкости яйца, вора с редким и реже — крупнее, с пульсом и именем у края экрана; выпавшие яйца — кружком с таймером возврата (до 4). Позиция и яйцо в руках каждого игрока — атрибуты `RadarAt` и `RadarEgg` на `Player`, их пишет `RadarService` 2 раза в секунду (позицию — после сдвига на 2 studs); персонаж, пришедший к клиенту, даёт свою позицию. Кто-то схватил эпическое или легендарное яйцо — остальным тост (по смене `RadarEgg`, без нового remote). Метки у края экрана держатся в безопасной зоне устройства и под кнопками Roblox и не заходят на HUD — отступают к прицелу по своему направлению (`ScreenMarker.placeIn`, `UI/PinArea`); так же теперь стоят метки дома, ивентов и туториала (`ScreenPin`). Метка дома — над полом острова, а не на макушке купола; свой остров — край и купол в цвете дома (`Theme.NEON.HOME`, только у себя): золотой, край толще, купол гладкий, а не ForceField — так его видно издалека (мятный в v1.1.1 сливался с голубым и пропадал вдали). Табличка хозяина — 28 × 6 studs, видна с 400 studs.
**Почему:** плейтест с друзьями (2026-11-12): на карте радиусом ~3 500 studs игроков и выпавшие яйца не найти — PvP не случается; метка дома висела в 250 studs над полом и ложилась на HUD; свою базу не отличить. Карта шире радиуса стриминга (2 048–4 096), поэтому дальнего персонажа у клиента может не быть, а атрибуты `Player` приходят всем всегда и дают сигналы; трафик — порядка 3 КБ/с на весь сервер.
**Отброшено:** позиции через remote каждый кадр (дорого); только по персонажам (дальних нет из-за стриминга); `Highlight` на ворах (лимит 31 на клиента, вдали не виден); столб света над своим островом (пользователь отказался от столбов для станции); метки игроков только в радиусе (пользователь просил видеть всех).

### 110. Пришельцы без инвентаря: стеллаж — единственный запас, у него предел; подсказки после туториала
**Дата:** 2026-11-12
**Решение:** бриф `docs/design/screens/aliens-and-hints.md`, макет `docs/design/mockups/alien-handling.html`.
- **Инвентаря нет.** Пришельцы без места стоят только на стеллаже (поле профиля `floor`). Подсказки «Подобрать» нет; у пришельца на стеллаже — «В отсек»: она открывает окно отсека, где он уже выбран. Профиль v20 (после v20 `phone-ui` — v21): инвентарь переезжает в конец стеллажа.
- **Предел стеллажа — 24**, по числу ниш (`BayConfig.SHELF_SLOTS`). Нет свободного места и стеллаж полный — готовое яйцо не вылупляется, а ждёт в капсуле. Это видно сразу: красная фишка «Стеллаж полный» над яйцом, красная подсказка у яйца (открывает отсек), счётчик «24/24» над стеллажом и его свет — красные, на плитке отсека — число таких яиц, тост в момент заполнения. «Вылупить за R$» при полном стеллаже не предлагается; пришедшая покупка делает яйцо готовым, и оно вылупится, когда освободится ниша. Старый профиль может держать больше 24 — тогда вылупление ждёт, пока их не станет меньше.
- **Места:** купленное место сразу занимает лучший со стеллажа (тост «… → на место»); у свободного места — «Свободное место» и подсказка «Лучшего сюда». Сами лучшие при вылуплении места не занимают (переставить — в окне, «Лучших на места»). «Убрать с места» стало «На стеллаж» (нельзя при полном). Перестановка на занятое место — обмен: стеллаж от неё не растёт.
- **Окно отсека:** колонка «Стеллаж 12/24» вместо инвентаря; блок «Можно скрестить» — по строке на каждую тройку одного стража и варианта со стеллажа и кнопка «Скрестить 3 → 1» (берёт трёх самых слабых, `Crossbreed.trios`); выбирать можно сколько угодно, «Продать N ●сумма» с подтверждением (команда `SellMany` — одной записью, а не очередью `Sell`, которую срезал бы лимит частоты); «Выбрать всех» у стеллажа.
- **Общий доход** (пользователь, 2026-11-12): «+21,9/с» под монетами в HUD и «Доход: ●21,9/с» на терминале мест — считаются только пришельцы на местах.
- **Подсказки после туториала** (`Domain/Coach`, `CoachService`, профиль `coachDone`): места заняты → купи место у терминала; хватает на первый джетпак → магазин джетпаков на станции; выполнено задание → станция; трое одинаковых → «Скрестить» (окно с выбранной тройкой); стеллаж полный → продай. По одной, в панели туториала с дорожкой и меткой; новая — не раньше 40 с после прошлой; пока игрок несёт яйцо — нет; крестика нет: подсказка уходит навсегда, когда дело сделано (место или джетпак куплены — и по состоянию профиля), а пропавшее условие только прячет её. Прощальная строка туториала ведёт на станцию. Аналитика — `CoachShown` и `CoachDone`.
**Почему:** пользователь, тест Prod на iPhone (2026-11-11): «подобрал — и они куда-то исчезли», игра не рассказывает про скрещивание и продажу, станцию не замечают; друзья на плейтесте (2026-11-12): скрещивать неудобно (ищешь одинаковых по списку), хочется продавать нескольких сразу. Инвентарь ничего не давал: у пришельца на стеллаже в окне были те же кнопки, а сам инвентарь в мире не виден. Без предела запас рос бы без конца, а окно и сеть шлют его целиком. Выбор пользователя (2026-11-12): вариант А (подсказки к тому, что есть), инвентарь убрать, предел 24 и не вылуплять при полном, все пять подсказок без крестика, «В отсек», тройки, «Продать все» и «Выбрать всех».
**Проверено:** в Studio через MCP (стеллаж 24/24 и блок вылупления, подсказки у яиц, мест и стеллажа, тройки, «Продать 5», подсказки по очереди, доход) и пользователем в игре: «да» (2026-11-12). Найдено при проверке: подсказку «Скрестить» вытесняла подсказка про джетпак, как только хватало монет — теперь показанная держится, пока нужна.
**Отброшено:** вариант Б — лучшие сами встают на места вместо слабых; вариант В — места только автоматически (нельзя поставить любимца); «Скрестить всех одинаковых» одной кнопкой (не видно, кого отдаёшь); автопродажа при переполнении (тоже «исчезли»); стеллаж без предела с меткой «+N»; крестик у подсказки.

### 111. Вид от первого лица прячет курсор; доска монет крупнее; бегущая строка без наездов
**Дата:** 2026-11-12
**Решение:** три замечания игрового теста с друзьями.
- **Первое лицо на компьютере** (вариант Б, пользователь): камера, приближенная до упора, остаётся видом от первого лица; `FirstPersonMouseController` каждый кадр после камеры держит мышь по центру (`MouseBehavior = LockCenter`) и прячет курсор, пока камера ближе 1 stud к своей `Focus` (порог самого Roblox; в упоре — 0,5, в любой позе, и в полёте). Открытое окно (`WindowState`) или экран «С возвращением!» освобождает мышь и показывает курсор, чтобы нажимались кнопки; закрыли — снова по центру. Отдалили камеру — всё возвращается, как было. Прицел гарпуна и бомбы и раньше шёл по центру экрана (`AimController`), его это не меняет. На телефоне ничего не происходит (`MouseEnabled`).
- **Доска монет** (решение 087): вся «корона» — тот же набор `StationKit`, увеличенный в коде в `StationShape.BOARD_SCALE` (×1,2 к остальной станции): экраны 43 × 31 на высоте ≈ 46, основание радиусом 16,8, монета на верхушке по-прежнему ниже кольца бегущей строки (тест). Экран всегда рисуется в 720 × 520 пикселей (`LeaderboardLooks.PIXELS_PER_STUD` — от ширины экрана), так что буквы растут вместе с ним. Дальний вид (топ-3) — в две строки: крупное место, справа имя (до 70 px) над монетами (до 60 px); раньше длинное имя Roblox сжималось в узкой колонке до ~33 px. По бокам экрана отступ шире (вблизи 70 px, издалека 44 px): снизу рамка и края задника заслоняли крайние пиксели, и монеты обрезались.
- **Бегущая строка кольца:** у пункта постоянный размер текста, ширина — по иконке и названию (не меньше `itemShare` экрана), между названиями зазор; строка едет на свою измеренную длину. Раньше у каждого пункта была одна ширина, а название растягивалось по высоте, и длинное русское («Подарок», «Джетпаки») уходило под иконку соседа.

**Почему:** игроки видели курсор при камере в упоре (Roblox сам держит мышь, но курсор не прячет). Доску «плохо видно»: с острова длинные имена в топ-3 мельче всего, а с платформы край строк срезала рамка. ×1,2 — предел, при котором монета остаётся ниже кольца строки; набор не меняется, нового ассета нет, для телефона ничего не добавилось.
**Отброшено:** убрать первое лицо (`CameraMinZoomDistance` 6–8, вариант А; пользователь выбрал Б); доска ×1,5 (с платформы экраны уходят высоко над голову, основание занимает центр, монету с острова закрывает кольцо строки); новая форма доски в Blender (новая выгрузка и вставка набора в Dev и Prod).

### 112. Поимка снимает кислород по силе стража для игрока: 5 / 10 / 35 / 90 %
**Дата:** 2026-11-12
**Решение:** удар стража и Звёздного змея снимает не плоские 10 % (решение 108), а долю баллона по той же ступени, что на плашке над ним для этого игрока (`Speed.challenge` и `Speed.standing` от ⚡ игрока и рекомендуемой ⚡ стража; `Oxygen.catchShare`, `OxygenConfig.CATCH_SHARES`, применяет `Prey.takeOxygen`):
- «Слабый» — 5 %;
- «По силам» — плавно от 5 % (на порядок сильнее стража) до 10 % (ровно рекомендуемая ⚡);
- «Сильный» — плавно от 10 % до 35 % у самой границы черепа;
- «Не уйти» (череп) — 90 %.
Ступень берётся та же, что у плашки, поэтому плашка честно говорит предел: «По силам» — не больше 10 %, «Сильный» — не больше 35 %. Змей теперь тоже снимает кислород (раньше — нет), по рекомендуемой ⚡ стража своей зоны на посту `POWER_POST` (`SerpentConfig.recommendedIn`, им же меряет плашка над змеем). Удар, после которого кислорода не осталось, — обычная смерть от удушья (`SpaceService`, `floatWhenDead`); с `SetInfiniteOxygen` в Studio кислород не тратится. Полоса кислорода показывает потерю (бриф `docs/design/screens/hud.md`, вариант А): потерянный кусок красным тает к новому краю за 0,8 с, рядом «-35%» гаснет за 1,5 с — при резкой потере от 2 % сразу.
**Почему:** пользователь после теста v1.1.0: 10 % почти не мешают новичку таскать яйца у самых дальних стражей, проигрывая каждую погоню. Выбор пользователя (2026-11-12): от прогресса игрока, а не по номеру стража на карте — сильный игрок у стражей, которых перерос, теряет мало, а плашка сразу говорит цену. Новичок (10 ⚡) теряет 10 % у первого стража и 90 % у всех остальных: второй страж для него уже «Не уйти».
**Отброшено:** потеря по номеру стража (1-й — 10 %, 24-й — 90 %, одинаково для всех); одна плавная кривая без скачка у черепа (у «Сильного» потеря доходила бы до 90 %, и плашка ничего бы не говорила); цена числом на плашке стража (больше текста над каждым стражем) и кусок полосы без числа.

### 113. «Лестница» вылупления: яйцо даёт свою ступень, изредка соседнюю; доход ×2
**Дата:** 2026-11-12
**Решение:** по анализу баланса яиц (сессия hatch-balance), пользователь принял предложение целиком. Меняет решения 047 (шансы вылупления), 055 (звёздное яйцо) и формулу удачи.
- **Вылупление** (`Domain/Hatch.ladder`, `EggConfig.hatchEntries`): яйцо редкости X даёт пришельца ступени X, иногда на ступень ниже или выше. Среднее яйцо — `hatchStep` редкости (вниз / вверх): Обычное — / 25 %, Необычное 20 / 20, Редкое 20 / 15, Эпическое 15 / 10, Легендарное 20 / —. Размер — множители `hatchDownFactor` / `hatchUpFactor`: большое ×0,5 / ×2, малое ×1,5 / ×0,5. Таблица 15 строк — в `GAME_DESIGN.md` и в тесте `Configs.spec`. Старая удача (`Hatch.shiftedWeights`, `luck` редкости и размера, `AlienConfig.HATCH_ENTRIES`, `hatchWeight`) убрана.
- **Добыча зон** (`ZoneConfig.rarityLoot`, О/Н/Р/Э/Л): Пояс 72 / 23 / 5 / 0 / 0, Кольца 52 / 33 / 13,5 / 1,5 / 0, Туманность 40 / 37 / 19 / 3,5 / 0,5, Горизонт 30 / 35 / 26 / 7,5 / 1,5. Размеры прежние.
- **Доход ×2:** `AlienConfig.INCOME_BASE` 1 → 2. От дохода считаются продажа (2 мин дохода), офлайн-доход и экран возвращения, награды заданий, подарка и индекса (`PlayReward`, минуты своей игры), доска монет — всё масштабируется само; цены (места, капсулы, тренажёр, джетпаки) не менялись.
- **Скрещивание** (`Domain/Crossbreed`): только 3 пришельца одного стража, **одной ступени** и варианта (новая причина отказа `MixedTiers`, тост «Скрещивай пришельцев одной ступени»). Итог — та же ступень или на одну выше: `BayConfig.CROSSBREED_UP_CHANCE` 43 / 39 / 33 / 27 % для О/Н/Р/Э, три легендарных → легендарный. Тройки окна отсека и подсказки (решение 110) и условие задания «Скрести» группируют по ступени; строка тройки — «<ступень> · <страж>».
- **Время:** легендарное яйцо 2–4 ч (было 1,5–5 ч), остальные как были.
- **Звёздное яйцо:** не ниже Эпического (`STAR_EGG_MIN_RARITY`) и «удачное»: любое `luck > 0` значит «вылупляется по шансам большого» (`EggConfig.oddsSize`). Поле профиля `EggRecord.luck` осталось — формат профиля не меняется, старые звёздные яйца (luck 0,7) работают так же. `GiveEgg` пятым аргументом — удача (`1`).
- **Метеоритные яйца** — по той же лестнице, вариант ×2 прежний.
- **Против прыжков по серверам:** первая засыпка гнёзд при старте сервера — не выше Редкого (`EggConfig.FIRST_FILL_MAX_RARITY`, `Loot.capped`: вес эпических и легендарных уходит в редкие). Эпические и легендарные растут только при отрастании гнезда после доставки и в кратерах дождя.
- **Сохранения:** пришельцы остаются как есть; яйца в инкубаторах вылупятся по новым шансам (шансы считаются при вылуплении). Миграции нет.
- **Подарок за вход, 7-й день** — эпическое среднее яйцо вместо редкого (`LoginGiftConfig.EGG_RARITY`; пользователь, 2026-11-12).
- **Индекс не меняется** (пользователь, 2026-11-12): набор стража с легендарными всех трёх видов — цель игроку, хоть для Пояса и Колец она теперь очень далёкая.
- **Шансы яйца — только в инкубаторе**, под подсказкой у яйца, где продаётся «Вылупить за … R$» (правило Roblox о случайных покупках): точки цвета ступени с процентом, бриф `docs/design/screens/egg-odds.md` (пользователь, 2026-11-12: «давай покажем шанс на яйце но только в инкубаторе»).
- `lune run balance` печатает и первую сессию: доход в секунду и заработанные монеты к 15 мин, 30 мин, 1 ч, 2 ч.

**Почему:** легендарные пришельцы шли в основном из дешёвых яиц (один на 48 яиц Пояса с вылуплением за минуту), а легендарное яйцо было в 50 раз хуже в пересчёте на час места в инкубаторе; из трёх обычных скрещивание давало 3,6 % легендарных. Свежий сервер каждый второй раз держал готовое легендарное яйцо на Горизонте — выгодно прыгать по серверам. Доход ×2 возвращает темп: по `lune run balance` бесплатный игрок проходит стражей 6 / 9 / 13 / 18 / 22 за то же время (18 мин / 1,2 ч / 1 д / 8 д / 26 д), Кита — за 43 дня вместо 49.
**Риски:** меньше долгих яиц — меньше давления на места инкубатора (бесплатный игрок к 60-му дню покупает 7 мест, а не 8); собрать набор индекса Пояса и Колец почти невозможно (нужны легендарные всех трёх видов) — оставлено как цель.
**Отброшено:** явная таблица 15 строк в конфиге (правило размера тогда не держится само, правка одного шанса — три правки); «строгая» добыча (Горизонт 5 / 0,75 % эп./лег.); без дохода ×2 (бесплатный игрок на ~15 % медленнее и в первые 2 ч зарабатывает в 3,5 раза меньше); скрещивание разных ступеней. Шансы в гнёздах, у яйца в руках и в HUD — пользователь (2026-11-12): в игре-референсе этого нет.

### 114. Потолок наград: задание и подарок — не больше 15 % накопленного; индекс скромнее
**Дата:** 2026-11-12
**Решение:** по анализу наград (сессия hatch-balance, заметка `hatch-balance.md`), выбор пользователя; всё считается с доходом ×2 из решения 113.
- **Задания дня и подарок за вход** платят не больше `MAX_SHARE_OF_EARNED` = 15 % (`QuestConfig`, `LoginGiftConfig`) того, что у игрока уже есть: очки скорости — не больше 15 % натренированных (`trained`), монеты — не больше 15 % заработанных за всё время (`coinsEarned`), но не меньше прежних 200 монет. Одна формула — `PlayReward.Limit` в `PlayReward.worth/of`: сервер платит, окна заданий и подарка показывают уже урезанную сумму, калькулятор считает так же. Задания, забранные подряд, урезаются каждое от уже выросших чисел (три подряд — не больше ×1,52 скорости).
- Клиенту «заработано всего» приходит атрибутами игрока `CoinsEarnedMantissa` / `CoinsEarnedExponent` (их пишет `LeaderboardService` вместе со столбцом списка игроков, раз в секунду), натренированное — из стата скорости делением на множитель джетпака.
- **Индекс:** набор стража — 15 минут дохода (было 30), находка — не меньше 25 монет (было 100); минуты за находку (0,5–5) прежние. Индексу потолок не нужен: он платит только монеты и забирается пачкой.
- **Не меняется:** подарок сообщества (+10 000 к натренированному — единственный осознанный рывок), пропуск «Двойная тренировка» в награды не входит (награда считается от прибавки тренажёра без него), пакеты за робуксы.
- `lune run balance`: задания платятся тремя наградами подряд, подарок и задания — с потолком; таблица «Rewards in minutes» — сколько минут своей игры стоят задания дня и подарок 7-го дня на 15 мин, 1 ч, 1, 7 и 59 день, с потолком и без.

**Почему:** награда — «минуты своей игры» по темпу в момент получения, а новичок натренировал меньше минут, чем в награде: три задания на 12-й минуте давали +1,3 ступени цели сразу и монеты в 5,6 раза больше всего заработанного, подарок 1-го дня — +0,8–1 ступени; к 15-й минуте 78 % скорости было из наград. Со второго дня награды и так 2–7 % ступени — потолок их не трогает. По калькулятору: задания дня на 15-й минуте — 2,9 мин ⚡ / 3,5 мин монет вместо 25, на 1-м часу — 9 / 11 вместо 25; с 1-го дня — полные 25.
**Отброшено:** потолок 10 % (слишком скупо в первый час) и 25 % (почти не режет); потолок для индекса (забирается пачкой — урезание копилось бы); считать награду индекса в момент находки (отложено); подарок сообщества 2 500.

### 117. Гарпун бьёт того, на ком захват у стрелка; без цели кнопка тусклая
**Дата:** 2026-11-13
**Решение:** уточняет решение 106. **Захват клиента.** Клиент сообщает серверу, на ком сейчас захват гарпуна — уголки на цели (событие `HarpoonLock`, при каждой смене; `AimMarkController`). При выстреле сервер сначала берёт эту цель, если она по-прежнему несёт яйцо, правила её не защищают и в его собственном виде она не дальше «отставания»: в пределах дальности плюс допуск и в конусе 18°, расширенном вбок на допуск (`Abilities.isInLaggedCone`). Допуск — путь стрелка и цели за 0,3 с (пинг телефона плюс сглаживание Roblox) плюс 6 studs на тела, не больше 40 studs (`Abilities.lockSlack`, `PvpConfig.HARPOON.lock*`). Не устоял захват или его нет — сервер выбирает сам, как раньше. Дальность гарпуна 90 studs (было 70). Крюк летит 450 studs/с, сматывается 300 (было 220 и 170): попадание засчитывается в миг нажатия, и крюк долетает почти сразу — на 90 studs за 0,2 с (пользователь: «скорость гарпуна должна быть тоже повыше»). **Без цели кнопка гарпуна тусклая** (и иконка F на ПК): серая, как удар с занятыми руками, но нажимается (`FlightButtons` — поле `dimmed`). Гарпун по-прежнему только для носителей яйца. В Studio Output печатает, принят ли захват, расстояние и допуск.
**Почему:** пользователь после выпуска 1.1.6: «гарпуном почти невозможно попасть все еще». Причины, по данным: (1) гарпун бьёт только носителей яйца, а без носителя в прицеле фиолетовые уголки бомбы стоят на игроке без яйца, кнопка гарпуна при этом выглядит готовой — выстрел в него всегда промах; (2) уголки ставит клиент по тому, что видит он, а попадание проверял сервер по своим позициям. Клиент видит чужих позади их серверного места на время сети и сглаживания (в Studio без сети замерено 0,03 с; на телефоне по пингу 0,1–0,25 с), а себя — впереди: на встречных и боковых курсах при 150 studs/с это 15–40 studs, при 40 studs до цели — десятки градусов, далеко за конусом 18°. Уголки горели, а сервер говорил «мимо». Пользователь выбрал оставить гарпун для носителей и потускнить кнопку без цели (2026-11-13).
**Отброшено:** гарпун по любому игроку (пользователь против); дальность, растущая со скоростью (захват клиента решает то же точнее); перемотка позиций на сервере (сложно, а захват клиента с допуском проще и проверяем); проверка прямой видимости (у гарпуна её не было и раньше, в космосе почти нечему заслонить, а ложные срабатывания на невидимых границах зон сломали бы попадания); безлимитное доверие клиенту (допуск ограничен 40 studs и конусом от серверного прицела).

### 118. Низкополигональные питомцы: тело вида и наряд из пула ступени (предложено, начато со слизней)
**Дата:** 2026-11-13
**Статус:** слизни (12 видов) одобрены вживую 2026-11-13 («Крылья нравятся», «Слаймы тоже нравятся»). Пользователь дал слово переделать сразу всё («я согласен переделать все»): все 72 вида переведены в стиль 2026-11-13, Dev-плейс сохранён, ждёт его просмотра. В Prod не выпускалось; права `Use` для Prod на 1 497 новых сеток — при выпуске.
**Решение:** питомцы переходят на низкополигональный стиль «А · Гранёный» (концепт `docs/design/concepts/lowpoly/`): плоское затенение, икосферы и фаски, крупные глаза с бликом. **Модель — только тело вида**: одни меши на все 10 вариантов (`assets/blender/lowpoly/export_lowpoly_roblox.py`, `lune run aliens` делает из тела 10 питомцев с теми же мешами: рост ступени — размером, золото легендарного и лава метеоритного — краской панциря). **Наряд надевает код** (`World/OutfitDress`): детали общего набора `ServerStorage.Aliens._Outfit` ставятся на точки тела (`anchor<Slot>`). Каждый питомец **бросает наряд из пула своей ступени** (`Domain/AlienOutfit`): голова (рожки, гребень, усики; у легендарного — корона), аура (нимб, осколки, кольца; у легендарного ещё звезда), спина (у редкого ранец или маленькие крылья, с эпического — крылья: бабочка-парусник, ангельские перья, драконьи, кристальная друза и крылья феи по первому референсу пользователя; полупрозрачная перепонка и светящиеся линии, как у первых крыльев; у редкого вместо них бывают маленькие пёрышки или бабочка.). Цвет деталей — цвет ступени. Бросок — хэш `UserId` владельца и `uid` пришельца: ничего не сохраняется, вид один и тот же после перезахода и у всех игроков; скрещивание (новый `uid`) — новый бросок. Иконки остаются вида × ступени. Другие семейства пока на старых моделях — игра держит оба вида моделей (атрибут `Outfit` у тела).
**Почему:** пользователь: «упростить модели питомцев», «на местах выглядят слишком одинаково из-за одинаковых крыльев», «на пета выпадает рандомный набор украшений из общего пула редкости» (2026-11-13). Сегодня питомец — в среднем 31 тыс. треугольников и 16 693 уникальных меша на 720 питомцев, около 300 МБ мешей на полном сервере; гранёный — около 1,5 тыс. треугольников и около 530 мешей на всю игру.
**Отброшено:** стили «Игрушка» (выглядит урезанной, тяжелее вдвое) и «Острый» (кубики съедают милоту); наряд, назначенный виду (все питомцы вида одинаковы); сохранение броска в профиле (не нужно, пока нет обмена питомцами).

### 119. Гранёный низкополигональный стиль — для всей игры (предложено)
**Дата:** 2026-11-13
**Статус:** предложено; шаги по одному, каждый — после живого просмотра пользователем: питомцы (решение 118, начато со слизней), потом змей, гнёзда и остальное.
**Решение:** все 3D-модели игры переходят на стиль «А · Гранёный»: видимые грани, плоское затенение, малое число граней как стиль, силуэт и цвет важнее мелочей, крупное и тонкое — полупрозрачной перепонкой со светящимися линиями. Правила стиля и ассетов (одна сетка на форму без запечённого размера, тело отдельно от общего набора деталей, без скрытых деталей, бюджеты треугольников, `RenderFidelity`, ничего тяжёлого для дальних объектов) — в одном месте, `docs/design/LOWPOLY.md`. Следующие шаги и другие сессии следуют ему, а изменения в нём записываются сюда.
**Почему:** пользователь: «вся сессия … будет про низкополигональные текстуры по всей игре. Позже будем переделывать и змея, и все под этот стиль заточим» (2026-11-13). Слизни в стиле дали в 16 раз меньше треугольников питомцев в кадре и в 3,4 раза меньше памяти сеток при том же наборе вещей на острове; анализ `asset-count` показал, что вес моделей и загрузка всей карты — главные причины памяти и лага при входе.
**Отброшено:** доводка нынешних моделей по отдельности (память и число сеток почти не уменьшаются); разные стили для разных частей игры (мир смотрелся бы разнородно).
**Сделано (2026-11-13, ждёт просмотра пользователем):** по поручению пользователя «перерисовывать сразу всё» (через сессию-координатора) — набор зон (гнёзда, астероиды, кольца; ассет 103312508143569; все копии на карте ~1,49 млн → ~173 тыс. треугольников), стражи (те же сборщики `adults.py` с гранёными примитивами `assets/blender/lowpoly/lowpoly_facets.py`, экспорт `export_guardians_lowpoly.py`, ассет 86278570561564; 24 модели 175 тыс. → 84 тыс. треугольников, число деталей прежнее) и Звёздный змей (`assets/blender/lowpoly/export_serpent_lowpoly.py` поверх `serpent_kit.py`, ассет 91648166328087; целый змей ~25,5 тыс. → ~7,9 тыс. треугольников, те же 62 детали). Дизайн, цвета, роли и шарниры прежние; игра берёт их без правок кода.
