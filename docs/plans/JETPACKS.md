# Джетпаки: корпус и реактивное пламя по грейдам

Задача из [POLISH.md](POLISH.md), раздел «Джетпаки». Слова пользователя (2026-11-10): «пламя с освещением совсем не видно — сделаем настоящее реактивное пламя из сопла; сами джетпаки и их пламя должны меняться с каждым грейдом; слегка улучшить вид джетпака». Концепт корпусов принят («всё нравится, бери как есть»), пламя — ступенями; упор на оптимизацию. Решение 089.

Концепт: [design/concepts/jetpacks.png](../design/concepts/jetpacks.png), скрипты — `assets/blender/jetpacks/` (`jetpacks.py` строит, `concept_jetpacks.py` рисует лист).

## Что получится

**Корпус** — 12 моделей (по одной на джетпак; обе модели I/II одного джетпака выглядят одинаково, решение 056), четыре ступени по три:

| Ступень | Джетпаки | Корпус | Пламя |
|---|---|---|---|
| Баллоны | 0 Стартовый, 1 Искра, 2 Комета | два баллона, сопла-конусы → раструбы, стабилизаторы, обтекатель | **огонь**: языки пламени, оранжевое → синее |
| Двигатель | 3 Плазма, 4 Ион, 5 Пульсар | блок между баллонами, колба с плазмой, катушки, корпус-капсула | **плазма**: ровная струя, бегущие кольца |
| Крылья | 6 Квазар, 7 Антиматерия, 8 Сингулярность | цельный корпус, крылья, гребень, шар антиматерии, диск чёрной дыры | **ударные диски**: яркие «бусины» по струе, длиннее |
| Легенды | 9 Гиперпривод, 10 Червоточина, 11 Бесконечность | четыре сопла, длинные крылья, кольцо-портал, знак ∞ | **экзотика**: спираль/вспышки, четыре струи |

Внутри ступени пламя растёт по длине и яркости с каждым грейдом и берёт цвет джетпака.

**Пламя** — лучи (`Beam`), а не частицы: на каждое сопло ядро (узкий белый луч) и струя (широкий сужающийся луч в цвете грейда, текстура ступени прокручивается). `LightInfluence = 0` и `Brightness > 1` — днём под Realistic не выжигается и не теряется. У сопла — светящийся «зев» (часть корпуса), один `PointLight` на джетпак без теней. Частиц нет совсем (искры не делаем: без них пламя читается).

Где горит: полёт (длина по тяге), выпад удара (вспышка на полную), стенд тренажёра (`Stand.flameScale` удлиняет), запуск после стана (вспышка). Стенд как модель не переделываем — отдельная задача.

## Оптимизация

Ориентир — телефон (iPhone), на сервере до 8 игроков, у каждого джетпак и пламя. Приёмы те же, что сработали на пришельцах (`BLENDER_ROBLOX.md`, разделы 3, 5a, 7).

- **Сетки лёгкие:** режим `LOW_POLY` в `jetpacks.py` — 1,3–4,4 тыс. треугольников на джетпак (рендер-режим был 9–54 тыс.). Детали склеены **по классу материала** (корпус, металл, свечение, стекло), цвета запечены в вершины (glTF COLOR_0): **3–4 `MeshPart`** на джетпак вместо ~20 деталей + 4 эмиттеров + 2 ламп. Проверка в `export_jetpacks.py` (≤ 4 части, ≤ 5000 треугольников) и при раскладке в плейсе (`prepare_in_studio.luau`).
- **Метки — не сетки:** сопла приходят маркерами и становятся `Attachment NozzleExit`; ни одной крошечной MeshPart.
- **Декор:** `CanCollide/CanQuery/CanTouch = false`, `Massless`, `CollisionFidelity = Box`, без теней у светящегося и стекла.
- **Эффекты только на клиенте:** сервер приваривает голый корпус с точками сопел; лучи и свет каждый клиент добавляет у себя (как одевание пришельцев, решение 081) — по сети не ходят.
- **Без частиц:** 2 луча на сопло (ядро и струя), ни одного `ParticleEmitter`. Свет — один слабый на джетпак, без теней.
- **Обновление по изменению:** контроллер пишет свойства лучей, только когда меняется состояние (горит/нет, ступень тяги по 0,1, стенд, вспышка), а не каждый кадр. Дальше 120 studs — только струя, без ядра; дальше 350 — и без света. При «уменьшить движение» (`GuiService.ReducedMotionEnabled`) ядро не рисуется: второй слой режется первым (`BLENDER_ROBLOX.md`, раздел 7).
- **Сеток мало:** 12 моделей × ≤ 4 части = 38 сеток на всю игру (GLB ~0,8 МБ); у игрока в игре одна модель.

**Итоговая нагрузка** (худший случай: 8 игроков, у всех легендарный джетпак с 4 соплами, все горят рядом с камерой):

| | На персонажа | 8 игроков |
|---|---|---|
| Корпус | 3 `MeshPart`, ≤ 4,4 тыс. треугольников | 24 части, ≤ 35 тыс. треугольников |
| Рукоятки (было и раньше) | 4 `Part`, 2 луча-шланга | 32 части, 16 лучей |
| Пламя | 8 лучей (4 сопла × ядро + струя) | 64 луча; дальше 120 studs — 32 |
| Свет | 1 `PointLight` без теней | 8; дальше 350 studs — гаснет |
| Частицы | 0 | 0 |
| Скрипт | запись свойств только при смене состояния | ~8 проверок атрибутов в кадр |

У младших джетпаков (2 сопла) — 4 луча пламени на персонажа. Для сравнения: прежний джетпак давал 4 эмиттера и 2 лампы на персонажа.

**Замер на телефоне** (шаг 5): после показа в Studio — опубликованная Dev-игра на iPhone, несколько персонажей с горящим пламенем в кадре; Developer Console (F9 → Memory / Render, MicroProfiler) — время кадра и память с пламенем и без, сравнить со старым джетпаком на master. Если тяжело — сначала ядро, потом свет, потом струя тоньше и короче.

**Состояние (2026-11-10):** шаги 1–5 в Studio сделаны, пользователь посмотрел пламя на стенде вживую — «всё нормально». Ассеты: модели — 129006372380471 (`ServerStorage.Jetpacks` плейса), текстуры — в `JetpackLooks.TEXTURES`. Осталось: замер на телефоне; полёт и выпад проверяет пользователь в игре.

**След в полёте** (пользователь, 2026-11-10: «при увеличении уровней добавить ещё эффект… чем выше грейд, тем длиннее… чтобы не конкурировать с лучом от яйца»): горизонтальная лента (`Trail`) в цвете пламени за летящим, только в полёте. У Стартового следа нет; дальше длина растёт с каждым уровнем (и I, и II; «коротковат в конце» — пользователь): 10 → 120 studs на максимальной скорости, к концу быстрее (`JetFlame.trailLength`, `JetpackConfig.TRAIL_*`; время жизни — `JetFlame.trailLifetime`). Ширина растёт с джетпаком; текстура по ступеням: гладкая лента → штрихи плазмы → бусины → две нити; у легендарных — две нити от крайних сопел. С Квазара — мягкое широкое сияние вокруг нитей (хвост кометы, а не «шнурок»), у Бесконечности след радужный. Нагрузка: 1–3 `Trail` на игрока (нити + сияние), без частиц, пишется только при смене состояния; при «уменьшить движение» — вдвое короче и без сияния. Вид по джетпакам — `JetpackLooks.TRAILS`. Статус: пользователь посмотрел вживую в полёте — «да» (2026-11-10).

## Шаги

1. **Экспорт** (без Studio): `assets/blender/jetpacks/export_jetpacks.py` → один GLB со всеми 12 джетпаками, детали склеены по роли/краске, точки сопел — крошечные маркеры. Проверка треугольников и числа частей в скрипте.
2. **Текстуры пламени** (без Studio): по одной на ступень, белые до прозрачности (`assets/fx/jet-*.svg`, генератор в `lune/fxsheets.luau` или свой), PNG через `lune run icons`.
3. **В плейс** (очередь Studio): загрузка GLB и текстур через Open Cloud, вставка в `ServerStorage.JetpacksIn`, затем `assets/blender/jetpacks/prepare_in_studio.luau` раскладывает её в `ServerStorage.Jetpacks` (12 моделей `Jetpack{n}`, опора — центр торса, маркеры сопел → `Attachment NozzleExit`), как набор зон (решение 085). Модели в плейсе, не через Rojo.
4. **Код:**
   - `JetpackLooks` — краски корпуса и пламя по уровням (ступень, цвета, длина, ширина, яркость, текстура, скорость прокрутки); чистая функция «вид пламени по тяге/стенду/выпаду» с тестами.
   - `JetpackModel` — клон модели грейда из `ServerStorage.Jetpacks`, масштаб под `UpperTorso`, сварка; без модели — нынешний грейбокс (запас на случай отставшего плейса). Смена грейда — замена модели. Рукоятки и шланги остаются.
   - `JetpackEffectsController` — лучи и свет у каждого джетпака на клиенте, обновление по изменению, дальность.
   - Магазин (`ShopController`) — цвета пламени из новых `JetpackLooks`.
5. **Вживую** (очередь Studio): пламя 2–3 грейдов разных ступеней в полёте, на стенде и в выпаде — смотрит пользователь, правим числа, потом остальные. Затем замер на телефоне (см. «Итоговая нагрузка»).
6. Уроки — в `docs/design/BLENDER_ROBLOX.md`; `lune run check`; коммиты; перебазирование на master и fast-forward.
