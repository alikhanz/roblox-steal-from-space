# Steal from Space

Roblox-игра (рабочее название «Укради у Космоса»): крадёшь космо-яйца у стражей, убегаешь на джетпаке, выращиваешь пришельцев. Разработчик один, весь код пишет Claude, пользователь тестирует в Studio.

Перед работой прочитай нужное:
- [docs/CONVENTIONS.md](docs/CONVENTIONS.md) — **обязательные правила кода**. Нарушать нельзя; менять — только через запись в журнале решений.
- [docs/ARCHITECTURE.md](docs/ARCHITECTURE.md) — слои, папки, запуск, данные, сеть.
- [docs/DECISIONS.md](docs/DECISIONS.md) — что уже решено и почему. Не переигрывай решения без обсуждения.
- [docs/GAME_DESIGN.md](docs/GAME_DESIGN.md) — геймдизайн и этапы.
- [docs/STYLE_TEXT.md](docs/STYLE_TEXT.md), [docs/GLOSSARY.md](docs/GLOSSARY.md) — тексты для игроков.

## Команды

```
lune run install      # после клонирования и после правки wally.toml / rokit.toml
lune run check        # перед КАЖДЫМ коммитом; должен быть зелёным
lune run format       # если check упал на форматировании
lune run test [фильтр]
lune run content      # только проверка строк локализации
lune run net          # после правки net/remotes.zap
lune run balance      # темп игры по конфигам; после правки экономических конфигов
rojo serve            # синхронизация в Studio
```

Если `lune` и другие инструменты не находятся в PATH, обнови его в той же команде:
`$env:Path = [Environment]::GetEnvironmentVariable('Path','Machine') + ';' + [Environment]::GetEnvironmentVariable('Path','User')`

## Как работать

- Качество важнее скорости. Пиши код так, чтобы его можно было поддерживать годами.
- Код, комментарии, коммиты — на английском. Документация и общение — на русском.
- Не торопись: крупные шаги сначала обсуждай с пользователем. Не начинай следующий этап без его слова.
- Новая доменная логика приходит с тестами в `tests/`.
- Любой текст для игрока — через скилл `game-copy`, на двух языках, только термины из глоссария.
- Новая зависимость или изменение правила — запись в `docs/DECISIONS.md`.
- Ветки `<тип>/<кратко>`, коммиты Conventional Commits. Перед `git push` покажи пользователю, что уйдёт.
- Не правь сгенерированное: `Packages/`, `ServerPackages/`, `src/*/Net/Remotes.luau`, `sourcemap.json`, `types/`, `build/`.
- Studio: при подключённом MCP-сервере `Roblox_Studio` можно запускать плейтесты, выполнять Luau и читать Output. Код всё равно правится только в файлах.

## Studio: что важно знать

- **Плейс** — файл `C:\Code\Roblox\StealFromSpace.rbxl` (вне репозитория): в Studio **File → Open from File**, потом `rojo serve` и **Connect** в плагине Rojo. Если файл потерян — `rojo build -o build/game.rbxl` и копия `build/game.rbxl` туда же: в собранном файле уже есть все настройки Workspace из `default.project.json`, включая `AuthorityMode = Server` и радиусы стриминга (проверено чтением файла через `@lune/roblox`). В самой `build/` не работать — `lune run check` её перезаписывает.
- **Server Authority** включается в плейсе вручную: Workspace → Properties → `AuthorityMode = Server`. Из скриптов, MCP и плагина Rojo это свойство недоступно. Так же вручную ставятся `StreamingMinRadius = 2048` и `StreamingTargetRadius = 4096` (значения в `default.project.json` — только документация: плагин свойства Workspace в открытый плейс не пишет, а `StreamingEnabled` под Server Authority выключить нельзя). Так же — `TextChatService → ChatVersion = TextChatService` (новый чат; старый `LegacyChatService` Roblox убирает) и `Lighting → Technology = Voxel` (Compatibility Roblox убрал; Studio переводит плейс сама при открытии). Под ним нет сетевого владения: `SetNetworkOwner` — ошибка; серверные объекты (стражи) просто симулирует сервер, а предсказание им выключается через `RunService:SetPredictionMode(model, Enum.PredictionMode.Off)`.
- **Размер станции — одно число** `StationSize.PLATFORM_RADIUS`: купол, граница (стражи, край бури), спавн, отсеки, зоны и край карты считаются от него. Новые расстояния около станции выражай через эту цепочку.
- **Солнечная буря идёт по расписанию** (каждые 5 мин 15 с): при тестах в Studio она может начаться сама и перенести персонажа на станцию. `StopEvent:Invoke("Storm")` её не отменяет навсегда — следующая придёт через 5 минут. Метеоритный дождь тоже по расписанию (раз в 15–25 мин, сразу после бури): кратеры — модели `MeteorCrater{n}` в `workspace.World.Nests`, их стражи — в `workspace.World.Guardians`; в Studio с одним игроком падает 4 метеора, раз в 3 с. Звёздный змей — тоже по расписанию (раз в 15–25 мин, после бури, 3 мин): модель `StarSerpent` в `workspace.World` (голова; тело — клиентская папка `workspace.SerpentBody`); он несёт звёздное яйцо и убегает, а выбитое яйцо сторожит, как страж (гонится за носителем) — для тестов вдали от станции его можно убрать `StopEvent:Invoke("Serpent")`. Звёздное яйцо (выпавшее или в руках) принадлежит дому `StarSerpent`, а не гнезду (`Domain/EggHomes`).
- **Пришельцы — только из реестра `AlienConfig`**, общие формулы и списки — в одном модуле каждый (CONVENTIONS, раздел 3, «Одна правда — одно место»). Перед тем как написать расчёт или список, поищи, нет ли его уже.
- **`rojo serve` падает**, если в `src/` файл создаётся и сразу удаляется. Так делают `sed -i`, `perl -pi` и временные пробные файлы. **Пока работает `rojo serve`, файлы в `src/` правь только редактором (Edit/Write), без `sed -i`/`perl -pi`**; пробные файлы клади вне `src/`. Признак падения — новые файлы не появляются в Studio, во вкладке терминала `Rojo crashed`. Лечится перезапуском `rojo serve` и повторным Connect в плагине.
- **Атрибуты персонажа, записанные сервером вне симуляции** (`CarriedEgg`, `HitVelocity`), на клиенте **не вызывают** `GetAttributeChangedSignal`: персонаж — предсказываемый инстанс, и такие изменения приходят через откат, а не обычной репликацией. Клиент читает их опросом (`RenderStepped`/`Heartbeat`). Атрибуты, которые пишет сама симуляция (`Oxygen`, `InSpace`), и атрибуты на `Player` сигналы дают.
- Перед плейтестом после правок проверь, что изменения дошли до Studio (например, наличие нового модуля через `execute_luau` в Edit).
- **Код в запущенном плейтесте не обновляется** — после правок перезапускай Play. Перед Play дай Rojo секунду-две на синхронизацию: если запустить сразу после правки, в игру попадёт старый код.
- В Studio всё работает на mock-хранилище ProfileStore (плейс не опубликован) — это ожидаемо.
- Доска монет в Studio работает на хранилище в памяти (в Output `[LeaderboardService] No data stores…`): на ней только игроки текущего плейтеста. Табличка — у спавна слева, колонка `●` — в списке игроков.
- Строковые атрибуты инстансов здесь ограничены 50 символами: длинные данные для клиента клади в `StringValue`.
- Аналитика в Studio не отправляется: события печатаются в Output с префиксом `[Metrics]` (суммы — раз в 30 с).
- Плейтест через MCP: `start_stop_play`, ввод — `user_keyboard_input`, проверки — `execute_luau` в `Server`/`Client`, вывод — `get_console_output`.
- **Поток MCP урезан в правах** (Studio 0.746+): у него нет `Network`, поэтому из `execute_luau` нельзя ни `Invoke` наших `BindableFunction`, ни `require` наших модулей (ошибка «…has an additional value for the Capabilities property: Network»). `Sandboxed` у наших объектов уже `false` — это не лечится. Команды разработчика из MCP — через почтовый ящик: запиши JSON `{"id": "<guid>", "command": "GiveEgg", "args": ["Rare", "Large", 1]}` в `ServerStorage.DevCommands.Request` (StringValue) и жди в `DevCommands.Result` JSON `{"id", "ok", "result"}` с тем же `id`. Пользователю команды давай как прежде — через `Invoke` в Command Bar.
- **Команды разработчика** (только Studio, `src/server/Services/DevService.luau`) — `BindableFunction` в `ServerStorage.DevCommands`, вызываются из серверного `execute_luau`:
  - `SetInfiniteOxygen:Invoke(true/false)` — кислород не тратится в этом плейтесте (по умолчанию — из `DevConfig.STUDIO_INFINITE_OXYGEN`, в коммитах `false`);
  - `SpawnEggNearPlayer:Invoke("Rare", "Large")` — выпавшее яйцо перед игроком (размер: Small / Medium / Large; под куполом его вытолкнет за купол — выпавшим яйцам туда нельзя); третий и четвёртый аргументы — гнездо, чей страж его охраняет (туда же оно вернётся, если яйцо гнезда в пути), и вариант (`"Meteor"` — метеоритное);
  - `RefillOxygen:Invoke()` — полный баллон;
  - `SetSpeed:Invoke(2500)` — скорость ⚡ первого игрока (пишется в профиль; HUD и скорость полёта обновляются сразу);
  - `GiveAlien:Invoke(2, "Rare")` — пришелец грейда 2 ступени Rare в отсек первого игрока (в свободную капсулу, иначе на пол); как вылупившийся — появляется в индексе; третьим аргументом `"Meteor"` — метеоритный;
  - `GiveEgg:Invoke("Uncommon", "Large", 1)` — яйцо в инкубатор первого игрока, как будто доставлено от стража 1; четвёртым аргументом `"Meteor"` — метеоритное, пятым — добавочная удача (`0.7` — как у звёздного яйца);
  - `HatchNow:Invoke()` — все яйца на местах инкубатора первого игрока становятся готовыми; вылупляет их сам игрок — подсказкой «Вылупить» у яйца в своём отсеке (решение 059), тогда ждущее в очереди переходит на освободившееся место;
  - `SetIncubatorSlots:Invoke(6)` — сколько мест в инкубаторе первого игрока (1–12), как будто куплены; ждущие яйца сразу переходят на новые места. У новичка 2 места: лишние яйца (и из `GiveEgg`) встают в очередь на платформе;
  - `DumpProfile:Invoke()` — строка с монетами, ⚡, капсулами, инвентарём, полом и числом яиц первого игрока;
  - `SimulateAway:Invoke(3600)` — как будто первый игрок отсутствовал N секунд: начисляет офлайн-доход и показывает экран «С возвращением!»;
  - `GiveCoins:Invoke(5000)` — монеты первому игроку (проверять покупки, не зарабатывая); считаются заработанными, так что двигают и доску монет;
  - `SpawnDummyThief:Invoke("Rare", 10)` — бот-вор с яйцом в N studs (по умолчанию 10) по прицелу первого игрока, держится там, пока жив (работает только в космосе); любая атака по нему выбивает яйцо и убирает бота;
  - `SetPlayTime:Invoke(3600)` — игровое время всех игроков на сервере (снять защиту новичка: 20 минут = 1200 с);
  - `PvpStats:Invoke()` — сколько раз использована каждая способность и сколько попало;
  - `ActivityStatus:Invoke()` — сколько секунд каждый игрок ничего не делает и не «отошёл» ли (3 минуты без движения и команд; от этого зависит число метеоров в дожде);
  - `CompleteQuests:Invoke()` — все задания дня первого игрока выполнены (проверить «Забрать»);
  - `NewQuestDay:Invoke()` — новые задания и новая замена первому игроку, как будто наступил новый день;
  - `NextLoginDay:Invoke()` — как будто с последнего подарка за вход прошёл день: ждёт следующий день серии (экран откроется сам);
  - `MissLoginDay:Invoke()` — как будто игрок пропустил день: серия начнётся заново;
  - `StartEvent:Invoke("Storm", "IceRings")` — ивент прямо сейчас, без предупреждения; вторым аргументом — зона, тогда на экране метка к точке в ней (`"Meteor"` с зоной — полоса дождя через точку в этой зоне, без зоны — в случайном направлении; бурю `StartEvent` и `QueueEvent` не ждут);
  - `QueueEvent:Invoke("Storm", 30)` — ивент через N секунд, с предупреждением и таймером (работает и для ивента, выключенного в расписании);
  - `StopEvent:Invoke("Storm")` — закончить ивент сейчас;
  - `HitSerpent:Invoke(3)` — N попаданий по Звёздному змею, будто их нанёс первый игрок (третье выбивает звёздное яйцо в сторону от игрока); змей должен быть на охоте с яйцом внутри;
  - `HoldSerpent:Invoke(true, 30)` — змей неподвижно в N studs по прицелу первого игрока (проверить удар, гарпун, бомбу); `HoldSerpent:Invoke(false)` — отпустить;
  - `SimulatePurchase:Invoke("Training", 3600)` — покупка за робуксы без робуксов: поддельный чек первому игроку через настоящий обработчик чеков (выдаётся один раз, ждёт сохранения). Виды: `"Training"` (вторым — секунды: 3600, 28800, 86400), `"ReadyNow"` (вторым — ступень 1–8, третьим — uid яйца), `"IncubatorSlot"` (ступень 1–3), `"CollectDouble"`. Работает только в опубликованном плейсе (`MonetizationConfig.catalogFor(game.GameId)`);
  - `GivePass:Invoke("NightShift")` — отметить пропуск (`"DoubleTraining"`, `"NightShift"`) купленным в профиле.
- **Магазин** (кнопка «Магазин» в меню, «Больше ⚡» у цели роста; покупки и в окне отсека, и на экране возвращения) есть только в игре, чей `game.GameId` есть в `MonetizationConfig` (Dev — `10774871729`); в непубликованном плейсе его нет. Цены приходят от Roblox, и Managed Pricing меняет их сам — расхождение с решением 061 нормально. Окно покупки Roblox в Studio — тестовая покупка без робуксов; нажимает его пользователь. Без окна — `SimulatePurchase`. Перед окном покупки клиент шлёт `PurchasePrompted` (откуда и какое яйцо), иначе «готово сейчас» достанется запасному яйцу.
- **Пропуски у создателя игры:** Roblox считает их купленными у владельца игры, так что в Studio у тебя оба пропуска есть всегда (`[PurchaseService] … owns …` в Output).
- **Силы на мёртвом персонаже роняют Studio**: `VectorForce` на частях тела, умершего в космосе (рэгдолл на шарнирах под Server Authority), дважды обрушили Studio в момент смерти. Мёртвое тело в космосе не трогаем физикой — `SpaceService.floatWhenDead` закрепляет его (`Anchored`) и двигает `PivotTo` со скоростью, которая была при смерти.
- В космосе нет трения: персонаж, сошедший с платформы, дрейфует с той же скоростью. Для тестов удара сначала обнули `HumanoidRootPart.AssemblyLinearVelocity` на сервере, иначе бот через секунду окажется позади.
- Окно отсека открывается кнопкой «Отсек» или клавишей B, окно заданий — кнопкой «Задания» или J. Кнопки в окне нажимаются только мышью (через `computer-use`); из `execute_luau` их не вызвать. Нажатия клавиш через MCP `user_keyboard_input` до `UserInputService.InputBegan` не доходят (B и J окна не открывают). Чтобы проверить окно без мыши: в клиентском `execute_luau` поставь окну `Visible = true` и отправь ту же команду, что кнопка (`require` модуля `Remotes` из `PlayerScripts`, например `Remotes.ClaimQuest.Fire(1)`).
- Тренажёр — очерченная зона справа от отсека: поставь персонажа в неё (`PivotTo` на `Trainer.Position + (0, 3.2, 0)` своего отсека); улучшение — кнопка на табличке над зоной (мышью). Капсулы покупаются кнопкой на табличке между рядами капсул (или в окне отсека). Магазин джетпаков — киоск `World.JetpackShop` у спавна: E у прилавка открывает окно, покупка — мышью.

## Luau

- **`if`-выражение возвращает одно значение**: `local a, b = if x then f() else nil, nil` кладёт в `b` всегда `nil` (второе значение `f()` теряется). Для функций с несколькими результатами — обычный `if` с присваиванием. Уже дважды давало тихие ошибки (`Prey.root`, `RigPose`).

## Vide

- `Vide.effect`, `derive`, `indexes` и прочее реактивное — только внутри `Vide.mount`/`Vide.root`; снаружи Vide бросает «cannot use effect() outside a stable or reactive scope», и остаток `start()` контроллера не выполняется.
- Источник с необязательным значением (`source(nil :: T?)`) нельзя читать как `s()` под новым солвером (пересечение типов читателя и писателя неоднозначно). Читай через приведённый геттер: `local read = s :: () -> T?`, или отдавай источник компоненту как `() -> T?`.
- `create` не знает `UIPadding`, `UISizeConstraint`, `UIStroke` — они делаются через `src/client/UI/Layout.luau`.
- **Rojo падает и от `lune run format`** (StyLua пишет через временные файлы). После форматирования проверь вкладку `rojo serve`; упал — перезапусти и нажми Connect в плагине.
- Не переноси персонажа далеко через `PivotTo` в тестах: перенос на сотни studs рвёт физические суставы, и персонаж может остаться мёртвым без респауна. Для теста подноси объекты к игроку (команды разработчика) или лети.

## Анимации

- Позы задаются **данными** в коде (`src/shared/Character/FlightPose.luau`: углы суставов R15), из них `FlightAnimation.buildSequence()` собирает `KeyframeSequence`.
- Под Server Authority персонаж игрока проигрывает **только загруженные** анимации, и только запущенные внутри симуляции. Временные анимации Studio (`RegisterKeyframeSequence`) не работают.
- **Загрузка** (делает пользователь, от владельца игры — аккаунта или группы): Explorer → `ServerStorage.JetpackFlight` → правый клик → **Save to Roblox** → тип Animation. Полученный ID — в `JetpackConfig.FLIGHT_ANIMATION_ID` (`rbxassetid://…`). Для правки позы — повторная загрузка с перезаписью того же ассета, ID не меняется. Удар — так же: `ServerStorage.Strike` (собирается из `StrikePose.SPEC` через `PoseAnimation.build`), ID — в `PvpConfig.STRIKE_ANIMATION_ID`.
- В Edit-режиме `require` из `execute_luau` кэширует модули: после правки исходника он вернёт старую версию. Чтобы собрать последовательность из свежего кода, клонируй папку `ReplicatedStorage.Shared.Character` во временное место и требуй клоны.
- **Предпросмотр позы без игры:** в Edit-режиме манекен R15, у которого `AnimationConstraint` заменены на `Motor6D` (поза пишется в `C0`), и снимки через MCP `screen_capture`. `AnimationConstraint` позу без физики не показывает.
- Суставы аватара — `AnimationConstraint`, а не `Motor6D`; `Animate` — модуль, его нельзя отключить. Переопределять суставы скриптом бесполезно: аниматор пишет их последним перед физикой.
- В тестах через MCP переносить персонажа — только `character:PivotTo(...)` (см. CONVENTIONS, «Персонаж»). Фоновые задачи (`task.spawn`) из `execute_luau` завершаются вместе с вызовом: для замеров во время ввода зажми клавишу (`user_keyboard_input` keyDown), замерь в одном вызове, потом отпусти.
- MCP после каждого `execute_luau` сбрасывает камеру. Чтобы снять кадр с нужной точки в игре, держи камеру через `RunService:BindToRenderStep`; в режиме редактирования — `screen_capture` с позицией камеры. `computer-use` `zoom` увеличивает **последний** полный скриншот, а не делает новый.
