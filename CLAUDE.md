# Steal from Space

Roblox-игра (рабочее название «Укради у Космоса»): крадёшь космо-яйца у стражей, убегаешь на джетпаке, выращиваешь пришельцев. Разработчик один, весь код пишет Claude, пользователь тестирует в Studio.

Перед работой прочитай нужное:
- [docs/CONVENTIONS.md](docs/CONVENTIONS.md) — **обязательные правила кода**. Нарушать нельзя; менять — только через запись в журнале решений.
- [docs/ARCHITECTURE.md](docs/ARCHITECTURE.md) — слои, папки, запуск, данные, сеть.
- [docs/DECISIONS.md](docs/DECISIONS.md) — что уже решено и почему. Не переигрывай решения без обсуждения.
- [docs/GAME_DESIGN.md](docs/GAME_DESIGN.md) — геймдизайн и этапы.
- [docs/IDEAS.md](docs/IDEAS.md) — идеи на далёкое будущее (после запуска): пользователь накидывает их по ходу, сюда и записывай такие; без обсуждения не делаются.
- [docs/STYLE_TEXT.md](docs/STYLE_TEXT.md), [docs/GLOSSARY.md](docs/GLOSSARY.md) — тексты для игроков.
- [docs/design/BLENDER_ROBLOX.md](docs/design/BLENDER_ROBLOX.md) — **обязательно перед любой работой с 3D-моделями** (скрипты Blender, экспорт, загрузка в Studio, одевание): оси и знаки, что в игре читается не так, лимиты загрузки сеток, порядок работы. Новый урок по моделям дописывай туда же.
- [docs/design/DESIGN.md](docs/design/DESIGN.md) — стиль интерфейса; экран меняется только по брифу из `docs/design/screens/` со статусом `approved` (решение 066).

## Команды

```
lune run install      # после клонирования и после правки wally.toml / rokit.toml
lune run check        # перед КАЖДЫМ коммитом; должен быть зелёным
lune run format       # если check упал на форматировании
lune run test [фильтр]
lune run content      # только проверка строк локализации
lune run net          # после правки net/remotes.zap
lune run balance      # темп игры по конфигам; после правки экономических конфигов
lune run icons        # иконки интерфейса: SVG из assets/ui → PNG в build/icons (Chrome)
lune run icons serve  # раздать PNG на localhost:8790 для загрузки через Studio MCP upload_image
rojo serve            # синхронизация в Studio
```

Если `lune` и другие инструменты не находятся в PATH, обнови его в той же команде:
`$env:Path = [Environment]::GetEnvironmentVariable('Path','Machine') + ';' + [Environment]::GetEnvironmentVariable('Path','User')`

## Как работать

- Качество важнее скорости. Пиши код так, чтобы его можно было поддерживать годами.
- Код, комментарии, коммиты — на английском. Документация и общение — на русском; база знаний для агента (черновики скиллов, `docs/design/BLENDER_ROBLOX.md`) — на английском (решение 078).
- Не торопись: крупные шаги сначала обсуждай с пользователем. Не начинай следующий этап без его слова.
- Новая доменная логика приходит с тестами в `tests/`.
- Любой текст для игрока — через скилл `game-copy`, на двух языках, только термины из глоссария.
- Новая зависимость или изменение правила — запись в `docs/DECISIONS.md`.
- Ветки `<тип>/<кратко>`, коммиты Conventional Commits. Перед `git push` покажи пользователю, что уйдёт.
- Не правь сгенерированное: `Packages/`, `ServerPackages/`, `src/*/Net/Remotes.luau`, `sourcemap.json`, `types/`, `build/`.
- Studio: при подключённом MCP-сервере `Roblox_Studio` можно запускать плейтесты, выполнять Luau и читать Output. Код всё равно правится только в файлах.

## Studio: что важно знать

- **Плейс** — **облачный**, Dev-игры: placeId `120029163657587` (universe `10774871729`), в Studio **File → Open from Roblox** (или из недавних), потом `rojo serve` и **Connect** в плагине Rojo; сохраняется Ctrl+S в облако. В нём всё, что вставляется руками: `ServerStorage.Aliens`, `ZoneKit`, `TerminalKit`, `IncubatorKit`, анимации `JetpackFlight`, `Strike`. Старый локальный файл `C:\Code\Roblox\StealFromSpace.rbxl` устарел (без моделей пришельцев и наборов) — **не открывать** (пользователь, 2026-11-10). Если плейс потерян — `rojo build -o build/game.rbxl` даёт основу со всеми настройками Workspace из `default.project.json` (включая `AuthorityMode = Server` и радиусы стриминга), а модели и наборы вставляются заново по их модулям (`World/AlienModel`, `World/ZoneKit`, `World/TerminalKit`). В самой `build/` не работать — `lune run check` её перезаписывает.
- **Prod-игра** «Fly & Steal Space Eggs» — universe `10775754016`, плейс `113469823655044`, владелец — сообщество `1096766348`. Без слова пользователя «в прод» её не трогать: ни плейс, ни Creator Hub. Порядок выпуска Studio → Dev → метка → Prod и чек-лист — [docs/RELEASE.md](docs/RELEASE.md) (решение 100). Ctrl+S и MCP `save_place` только сохраняют плейс. Чтобы изменения увидели игроки (и тестеры в Dev), нужен **File → Publish**. Ручная правка плейса нужна теперь дважды, в Dev и в Prod, поэтому всё, что можно, делай в коде. **Любой новый ассет пользователя** (сетка, картинка, звук, анимация) **расшаривай на Prod-игру** (право `Use` для universe `10775754016`), иначе в Prod он не загрузится. Как это делать — [docs/ASSETS.md](docs/ASSETS.md).
- **Server Authority** включается в плейсе вручную: Workspace → Properties → `AuthorityMode = Server`. Из скриптов, MCP и плагина Rojo это свойство недоступно. Так же вручную ставятся `StreamingMinRadius = 2048` и `StreamingTargetRadius = 4096` (значения в `default.project.json` — только документация: плагин свойства Workspace в открытый плейс не пишет, а `StreamingEnabled` под Server Authority выключить нельзя). Так же — `TextChatService → ChatVersion = TextChatService` (новый чат; старый `LegacyChatService` Roblox убирает) и `Lighting → LightingStyle = Realistic`, `PrioritizeLightingQuality = false` (решение 076; старое `Technology` устарело; из MCP в режиме редактирования эти свойства ставятся, из обычных скриптов — нет). Свойства `StarterPlayer` плагин в открытый плейс пишет, но убранное из `default.project.json` свойство не сбрасывает: значение остаётся в плейсе, пока его не вернуть руками (было с `DevTouchMovementMode`). Под ним нет сетевого владения: `SetNetworkOwner` — ошибка; серверные объекты (стражи) просто симулирует сервер, а предсказание им выключается через `RunService:SetPredictionMode(model, Enum.PredictionMode.Off)`.
- **Размер станции — два числа** (решение 068): радиус центральной платформы `StationSize.PLATFORM_RADIUS` и острова `ISLAND_RADIUS`. Купола, кольцо из 8 островов (по одному на игрока, свой отсек на каждом), граница (стражи, край бури), спавн, зоны и край карты считаются от них. Новые расстояния около станции выражай через эту цепочку. Игрок появляется на своём острове (`Player.RespawnLocation`); под куполом любого острова и центра — ходьба и кислород не тратится; яйцо засчитывается на центральной станции или на своём острове.
- **Солнечная буря идёт по расписанию** (каждые 5 мин 15 с): при тестах в Studio она может начаться сама и перенести персонажа на станцию. `StopEvent:Invoke("Storm")` её не отменяет навсегда — следующая придёт через 5 минут. Метеоритный дождь тоже по расписанию (раз в 15–25 мин, сразу после бури): кратеры — модели `MeteorCrater{n}` в `workspace.World.Nests`, их стражи — в `workspace.World.Guardians`; в Studio с одним игроком падает 4 метеора, раз в 3 с. Звёздный змей — тоже по расписанию (раз в 15–25 мин, после бури, 3 мин): модель `StarSerpent` в `workspace.World` (серая голова сервера; у клиента она скрыта, вид змея — клиентская папка `workspace.SerpentBody`); он несёт звёздное яйцо и убегает, а выбитое яйцо сторожит, как страж (гонится за носителем) — для тестов вдали от станции его можно убрать `StopEvent:Invoke("Serpent")`. Звёздное яйцо (выпавшее или в руках) принадлежит дому `StarSerpent`, а не гнезду (`Domain/EggHomes`).
- **Пришельцы — только из реестра `AlienConfig`**, общие формулы и списки — в одном модуле каждый (CONVENTIONS, раздел 3, «Одна правда — одно место»). Перед тем как написать расчёт или список, поищи, нет ли его уже.
- **Модели пришельцев** (решение 081) — в `ServerStorage.Aliens` плейса, **не через Rojo** (живая синхронизация теряет сетки MeshPart). Источник — `assets/aliens/<вид>.rbxm`; после `lune run aliens <файл>` вставь `out/Aliens.rbxm`: удали старую папку `Aliens`, выдели `ServerStorage`, **File → Import Roblox Model**, сохрани плейс. Если в Output при старте `[AlienModel] The place's alien models differ from the repo` — плейс отстал. Порядок целиком — `docs/design/BLENDER_ROBLOX.md`, раздел 5a.
- **Модели стражей** (решение 090) — в `ReplicatedStorage.Guardians` плейса (их клонирует клиент), тоже **не через Rojo**. Источник — `assets/guardians/<пост>.rbxm` (экспорт `assets/blender/guardians/export_guardians_roblox.py`); после `lune run guardians <файл>` вставь `out/Guardians.rbxm`: удали старую папку `ReplicatedStorage.Guardians`, выдели `ReplicatedStorage`, **File → Import Roblox Model**, сохрани плейс. Отстал плейс — в Output при старте `[GuardianModel] The place's guardian models differ from the repo`. Поста без модели — серый страж; модель видит только клиент (`workspace.GuardianLooks`), сервер держит серое тело.
- **Набор гарпуна и гравибомбы** (решение 095) — `ReplicatedStorage.PvpKit` плейса (16 MeshPart, ассет 102305810487584), вставкой, не через Rojo. Источник — `assets/blender/pvp/pvp_kit.py` → `out/pvp_kit/pvp-kit.glb` (загрузка Open Cloud, вставка, детали без моделей-обёрток в папку). Эффекты рисует клиент по событиям `HarpoonShot`, `BombThrown`, `BombExploded`; без набора — грейбокс и в Output `[PvpKit] No complete ReplicatedStorage.PvpKit`.
- **Набор змея** (решение 093) — папка `ReplicatedStorage.SerpentKit` плейса (детали рисует клиент, `World/SerpentVisual`), **не через Rojo**. Источник — `assets/blender/serpent/serpent_kit.py` → `serpent-kit.glb`: выгрузка через Open Cloud, вставка, MeshParts — в папку `SerpentKit` без сдвига, сохранить плейс (сейчас — ассет 113543789501678). Нет набора — серый змей из шаров (в Output `[SerpentVisual] No whole kit…`).
- **`rojo serve` падает**, если в `src/` файл создаётся и сразу удаляется. Так делают `sed -i`, `perl -pi` и временные пробные файлы. **Пока работает `rojo serve`, файлы в `src/` правь только редактором (Edit/Write), без `sed -i`/`perl -pi`**; пробные файлы клади вне `src/`. Признак падения — новые файлы не появляются в Studio, во вкладке терминала `Rojo crashed`. Лечится перезапуском `rojo serve` и повторным Connect в плагине.
- **Атрибуты персонажа, записанные сервером вне симуляции** (`CarriedEgg`, `HitVelocity`), на клиенте **не вызывают** `GetAttributeChangedSignal`: персонаж — предсказываемый инстанс, и такие изменения приходят через откат, а не обычной репликацией. Клиент читает их опросом (`RenderStepped`/`Heartbeat`). Атрибуты, которые пишет сама симуляция (`Oxygen`, `InSpace`), и атрибуты на `Player` сигналы дают.
- Перед плейтестом после правок проверь, что изменения дошли до Studio (например, наличие нового модуля через `execute_luau` в Edit).
- **Код в запущенном плейтесте не обновляется** — после правок перезапускай Play. Перед Play дай Rojo секунду-две на синхронизацию: если запустить сразу после правки, в игру попадёт старый код.
- В Studio всё работает на mock-хранилище ProfileStore (плейс не опубликован) — это ожидаемо.
- **Кнопки SurfaceGui** нажимаются, только если луч попадает в часть-адорни: у неё должен быть `CanQuery = true`. Ловушка: на сталкивающейся части (`CanCollide = true`) `CanQuery = false` не действует, а стоит выключить столкновения — кнопки молча перестают нажиматься (так было с экранами терминалов).
- Доска монет в Studio работает на хранилище в памяти (в Output `[LeaderboardService] No data stores…`): на ней только игроки текущего плейтеста. Доска — «корона» в центре станции (решение 087): четыре экрана, вблизи топ-10, дальше 110 studs — топ-3 крупно; колонка `●` — в списке игроков. По экранам кольца над куполом бежит строка киосков.
- Строковые атрибуты инстансов здесь ограничены 50 символами: длинные данные для клиента клади в `StringValue`.
- **Язык игры** — один на всё, `Text.localeOf(player)`: в опубликованной игре — язык аккаунта игрока (`Player.LocaleId`, его Roblox отдаёт для контента игр); `LocalizationService.RobloxLocaleId` — язык интерфейса самого Roblox, он бывает другим (на телефоне так смешались английские окна и русская подсказка с сервера). Не читай язык напрямую. Автоперевод Roblox (`AutoLocalize`) у наших GUI выключает `AutoLocalizeGuard` (решение 071). **В Studio** `Text.localeOf` берёт `RobloxLocaleId`: туда приходит язык эмулятора, а `Player.LocaleId` остаётся языком аккаунта. Русский для плейтеста: **Test → Player Emulator → Enable Test Profile**, Locale — Russian (`ru-ru`); работает со следующего Play и остаётся включённым, пока тестовый профиль не выключат.
- Аналитика в Studio не отправляется: события печатаются в Output с префиксом `[Metrics]` (суммы — раз в 30 с).
- Плейтест через MCP: `start_stop_play`, ввод — `user_keyboard_input`, проверки — `execute_luau` в `Server`/`Client`, вывод — `get_console_output`.
- **Поток MCP урезан в правах** (Studio 0.746+): у него нет `Network`, поэтому из серверного `execute_luau` нельзя ни `Invoke` наших `BindableFunction`, ни `require` наших модулей (ошибка «…has an additional value for the Capabilities property: Network»). `Sandboxed` у наших объектов уже `false` — это не лечится. **На клиенте `require` работает:** `local Remotes = require(game.Players.LocalPlayer.PlayerScripts.Client.Net.Remotes)`, потом `Remotes.Bench.Fire(true)`, `Remotes.BenchGuardians.Fire("Bench")` (замер 2026-11-11) — так из клиентского `execute_luau` шлются команды, как от кнопок. Команды разработчика из MCP — через почтовый ящик: запиши JSON `{"id": "<guid>", "command": "GiveEgg", "args": ["Rare", "Large", 1]}` в `ServerStorage.DevCommands.Request` (StringValue) и жди в `DevCommands.Result` JSON `{"id", "ok", "result"}` с тем же `id`. Пользователю команды давай как прежде — через `Invoke` в Command Bar.
- **Команды разработчика** (только Studio, `src/server/Services/DevService.luau`) — `BindableFunction` в `ServerStorage.DevCommands`, вызываются из серверного `execute_luau`:
  - `SetInfiniteOxygen:Invoke(true/false)` — кислород не тратится в этом плейтесте (по умолчанию — из `DevConfig.STUDIO_INFINITE_OXYGEN`, в коммитах `false`);
  - `SpawnEggNearPlayer:Invoke("Rare", "Large")` — выпавшее яйцо перед игроком (размер: Small / Medium / Large; под куполом его вытолкнет за купол — выпавшим яйцам туда нельзя); третий и четвёртый аргументы — гнездо, чей страж его охраняет (туда же оно вернётся, если яйцо гнезда в пути), и вариант (`"Meteor"` — метеоритное);
  - `RefillOxygen:Invoke()` — полный баллон;
  - `SetSpeed:Invoke(2500)` — скорость ⚡ первого игрока (пишется в профиль; HUD и скорость полёта обновляются сразу);
  - `GiveAlien:Invoke(2, "Rare")` — пришелец грейда 2 ступени Rare в отсек первого игрока (в свободную капсулу, иначе на пол); как вылупившийся — появляется в индексе; третьим аргументом `"Meteor"` — метеоритный, четвёртым — вид: номер среди видов стража (`2` — второй, `3` — редкий) или id вида (`"droneRay"`), по умолчанию основной;
  - `GiveEgg:Invoke("Uncommon", "Large", 1)` — яйцо в инкубатор первого игрока, как будто доставлено от стража 1; четвёртым аргументом `"Meteor"` — метеоритное, пятым — добавочная удача (`0.7` — как у звёздного яйца);
  - `HatchNow:Invoke()` — все яйца на местах инкубатора первого игрока становятся готовыми; вылупляет их сам игрок — подсказкой «Вылупить» у яйца в своём отсеке (решение 059), тогда ждущее в очереди переходит на освободившееся место;
  - `SetIncubatorSlots:Invoke(6)` — сколько мест в инкубаторе первого игрока (1–12), как будто куплены; ждущие яйца сразу переходят на новые места. У новичка 2 места: лишние яйца (и из `GiveEgg`) встают в очередь на платформе;
  - `DumpProfile:Invoke()` — строка с монетами, ⚡, капсулами, инвентарём, полом и числом яиц первого игрока;
  - `SimulateAway:Invoke(3600)` — как будто первый игрок отсутствовал N секунд: начисляет офлайн-доход и показывает экран «С возвращением!»;
  - `GiveCoins:Invoke(5000)` — монеты первому игроку (проверять покупки, не зарабатывая); считаются заработанными, так что двигают и доску монет;
  - `SpawnDummyThief:Invoke("Rare", 10)` — бот-вор с яйцом в N studs (по умолчанию 10) по прицелу первого игрока, держится там, пока жив (работает только в космосе); любая атака по нему выбивает яйцо и убирает бота;
  - `SetPlayTime:Invoke(3600)` — игровое время всех игроков на сервере (снять защиту новичка: 20 минут = 1200 с);
  - `PvpStats:Invoke()` — сколько раз использована каждая способность и сколько попало;
  - `ActivityStatus:Invoke()` — сколько секунд каждый игрок ничего не делает и не «отошёл» ли (3 минуты без движения и команд; от этого зависит число метеоров в дожде);
  - `CompleteQuests:Invoke()` — все задания дня первого игрока выполнены (проверить «Забрать»);
  - `NewQuestDay:Invoke()` — новые задания и новая замена первому игроку, как будто наступил новый день;
  - `NextLoginDay:Invoke()` — как будто с последнего подарка за вход прошёл день: ждёт следующий день серии (окно откроется само); новичку без доставки засчитывает доставку от стража 1 — без неё подарка нет;
  - `MissLoginDay:Invoke()` — как будто игрок пропустил день: серия начнётся заново;
  - `StartEvent:Invoke("Storm", "IceRings")` — ивент прямо сейчас, без предупреждения; вторым аргументом — зона, тогда на экране метка к точке в ней (`"Meteor"` с зоной — полоса дождя через точку в этой зоне, без зоны — в случайном направлении; бурю `StartEvent` и `QueueEvent` не ждут);
  - `QueueEvent:Invoke("Storm", 30)` — ивент через N секунд, с предупреждением и таймером (работает и для ивента, выключенного в расписании);
  - `StopEvent:Invoke("Storm")` — закончить ивент сейчас;
  - `HitSerpent:Invoke(3)` — N попаданий по Звёздному змею, будто их нанёс первый игрок (третье выбивает звёздное яйцо в сторону от игрока); змей должен быть на охоте с яйцом внутри;
  - `HoldSerpent:Invoke(true, 30)` — змей неподвижно в N studs по прицелу первого игрока (проверить удар, гарпун, бомбу); `HoldSerpent:Invoke(false)` — отпустить;
  - `SimulatePurchase:Invoke("Training", 3600)` — покупка за робуксы без робуксов: поддельный чек первому игроку через настоящий обработчик чеков (выдаётся один раз, ждёт сохранения). Виды: `"Training"` (вторым — секунды: 3600, 28800, 86400), `"ReadyNow"` (вторым — ступень 1–8, третьим — uid яйца: оно сразу вылупится), `"IncubatorSlot"` (ступень 1–3), `"CollectDouble"` (ступень 1–8; ниже ступени награды — выдаст только до предела ступени). Работает только в опубликованном плейсе (`MonetizationConfig.catalogFor(game.GameId)`);
  - `ReplayLastReceipt:Invoke()` — ещё раз тот же чек последней `SimulatePurchase` (так Roblox повторяет чек, если не уверен, что игра его получила): ответ `PurchaseGranted`, но выдачи второй раз нет;
  - `GivePass:Invoke("NightShift")` — отметить пропуск (`"DoubleTraining"`, `"NightShift"`) купленным в профиле;
  - `SetJetpack:Invoke(5)` — первый игрок носит джетпак с этим номером (0 — Стартовый … 11 — Бесконечность), первую модель: посмотреть корпус и пламя каждого (решение 089); скорость пересчитывается;
  - `SetTrainerLevel:Invoke(9)` — уровень тренажёра первого игрока, как будто куплен: терминал, вид стенда (новая модель с 0, 3, 6, 9, 12, 15, между ними лампы шкалы; решение 091) и пламя обновляются сразу;
  - `ResetCommunityGift:Invoke()` — подарок сообщества первого игрока снова не получен, и до конца плейтеста сервер сам не проверяет членство (при входе и в конце туториала): так плитка «Сообщество» видна и участнику (владелец игры в сообществе всегда). «Вступить» в окне проверяет Roblox по-настоящему; у участника окно Roblox сразу отвечает «уже в сообществе», и подарок приходит. Плитка — только после туториала (`SetTutorialStep:Invoke(4)`) и только в игре с сообществом в `CommunityConfig` (Dev);
  - `SetTutorialStep:Invoke(0)` — вехи туториала первого игрока (0 — с начала, 1 доставил, 2 вылупил, 3 натренировал, 4 пройден). Новый профиль в Studio (mock-хранилище) всегда начинает туториал с начала; первое яйцо в туториале готово сразу, и `GiveEgg` при вехе 0 тоже даёт готовое.
- **Скамья питомцев** (решение 082) — кнопки «/bench» и «/bench clear» справа на экране: 30 пришельцев на места для замера и обратно (что поставила скамья, хранится в профиле — очищается и после перезахода). «/bench guardians» ставит кольцом вокруг игрока 42 стража Горизонта событий (неподвижные, без мозга, треть спит, треть в погоне, треть возвращается) — для замера; «/gallery guardians» — по одному стражу каждого из 24 постов, все в погоне, — посмотреть модели. Живут до «/bench guardians clear» или выхода игрока; команда — `Remotes.BenchGuardians.Fire("Bench" / "Gallery" / "Off")`. Видны в Studio и в опубликованной Dev-игре только её создателю; в Studio их можно нажать и командой `Remotes.Bench.Fire(true/false)` из клиентского `execute_luau`.
- **Магазин** (кнопка «Магазин» в меню, «Больше ⚡» у цели роста; покупки и в окне отсека, и на экране возвращения) есть только в игре, чей `game.GameId` есть в `MonetizationConfig` (Dev — `10774871729`); в непубликованном плейсе его нет. Цены приходят от Roblox, и Managed Pricing меняет их сам — расхождение с решением 061 нормально. Окно покупки Roblox в Studio — тестовая покупка без робуксов; нажимает его пользователь. Без окна — `SimulatePurchase`. Перед окном покупки клиент шлёт `PurchasePrompted` (откуда и какое яйцо), иначе «готово сейчас» достанется запасному яйцу. На греющемся яйце своего отсека — подсказка «Вылупить за … R$» (атрибут `ReadyNowTier` у `ProximityPrompt`); покупка для выбранного яйца вылупляет его сразу.
- **Пропуски у создателя игры:** Roblox считает их купленными у владельца игры, так что в Studio у тебя оба пропуска есть всегда (`[PurchaseService] … owns …` в Output).
- **Силы на мёртвом персонаже роняют Studio**: `VectorForce` на частях тела, умершего в космосе (рэгдолл на шарнирах под Server Authority), дважды обрушили Studio в момент смерти. Мёртвое тело в космосе не трогаем физикой — `SpaceService.floatWhenDead` закрепляет его (`Anchored`) и двигает `PivotTo` со скоростью, которая была при смерти.
- В космосе нет трения: персонаж, сошедший с платформы, дрейфует с той же скоростью. Для тестов удара сначала обнули `HumanoidRootPart.AssemblyLinearVelocity` на сервере, иначе бот через секунду окажется позади.
- Окна открываются плитками меню в HUD (ряд под целью роста, `PlayerGui.Hud.Stats.Menu`) или клавишами: отсек B, магазин M, задания J, индекс N, подарок L (порядок и клавиши — в `State/MenuState`). Кнопки в окне нажимаются только мышью (через `computer-use`); из `execute_luau` их не вызвать. Нажатия клавиш через MCP `user_keyboard_input` до `UserInputService.InputBegan` не доходят (клавиши окна не открывают). Чтобы проверить окно без мыши: в клиентском `execute_luau` поставь окну `Visible = true` и отправь ту же команду, что кнопка (`require` модуля `Remotes` из `PlayerScripts`, например `Remotes.ClaimQuest.Fire(1)`).
- Тренажёр — стенд джетпака слева от спавна на своём острове: поставь персонажа в его зону (`PivotTo` на `Stand.Trainer.Position + (0, 3.5, 0)` своего отсека) — симуляция сама пристегнёт (атрибут `Stand` на персонаже: `Boarding`/`On`/`Left`). Сходит прыжком или шагом — это проверяет пользователь. Улучшение тренажёра, места и капсулы инкубатора покупаются кнопками на экранах **терминалов** у входа (мышью; клиентский `execute_luau` экраны не нажмёт — шли `Remotes.BuyPod.Fire()` и т. п.), места — ещё и в окне отсека. Скриптовые покупки в профиле, где уже всё куплено, дают тост отказа на каждую. Магазин джетпаков — киоск-капсула `World.KioskJetpacks` на центральной станции: E у стойки открывает окно, покупка — мышью. Остальные киоски станции (`KioskStore`, `KioskQuests`, `KioskGift`) открывают те же окна, что плитки меню; их подсказка видна, только пока видна плитка (решение 087).

## Luau

- **`if`-выражение возвращает одно значение**: `local a, b = if x then f() else nil, nil` кладёт в `b` всегда `nil` (второе значение `f()` теряется). Для функций с несколькими результатами — обычный `if` с присваиванием. Уже дважды давало тихие ошибки (`Prey.root`, `RigPose`).
- **Не держи инстансы ключами слабой таблицы** (`__mode = "k"`): Luau собирает обёртку инстанса, пока сам инстанс жив, и запись пропадает (пламя джетпака собиралось заново каждый кадр). Обычная таблица + очистка по `Destroying`.

## Vide

- `Vide.effect`, `derive`, `indexes` и прочее реактивное — только внутри `Vide.mount`/`Vide.root`; снаружи Vide бросает «cannot use effect() outside a stable or reactive scope», и остаток `start()` контроллера не выполняется.
- Источник с необязательным значением (`source(nil :: T?)`) нельзя читать как `s()` под новым солвером (пересечение типов читателя и писателя неоднозначно). Читай через приведённый геттер: `local read = s :: () -> T?`, или отдавай источник компоненту как `() -> T?`.
- `create` не знает `UIPadding`, `UISizeConstraint`, `UIStroke` — они делаются через `src/client/UI/Layout.luau`.
- **Rojo падает и от `lune run format`** (StyLua пишет через временные файлы). После форматирования проверь вкладку `rojo serve`; упал — перезапусти и нажми Connect в плагине.
- Не переноси персонажа далеко через `PivotTo` в тестах: перенос на сотни studs рвёт физические суставы, и персонаж может остаться мёртвым без респауна. Для теста подноси объекты к игроку (команды разработчика) или лети.

## Анимации

- Позы задаются **данными** в коде (`src/shared/Character/FlightPose.luau`: углы суставов R15), из них `FlightAnimation.buildSequence()` собирает `KeyframeSequence`.
- Под Server Authority персонаж игрока проигрывает **только загруженные** анимации, и только запущенные внутри симуляции. Временные анимации Studio (`RegisterKeyframeSequence`) не работают.
- **Загрузка** (делает пользователь, от владельца игры — аккаунта или группы): Explorer → `ServerStorage.JetpackFlight` → правый клик → **Save to Roblox** → тип Animation. Полученный ID — в `JetpackConfig.FLIGHT_ANIMATION_ID` (`rbxassetid://…`). Для правки позы — повторная загрузка с перезаписью того же ассета, ID не меняется. Удар — так же: `ServerStorage.Strike` (собирается из `StrikePose.SPEC` через `PoseAnimation.build`), ID — в `PvpConfig.STRIKE_ANIMATION_ID`.
- В Edit-режиме `require` из `execute_luau` кэширует модули: после правки исходника он вернёт старую версию. Чтобы собрать последовательность из свежего кода, клонируй папку `ReplicatedStorage.Shared.Character` во временное место и требуй клоны.
- **Предпросмотр позы без игры:** в Edit-режиме манекен R15, у которого `AnimationConstraint` заменены на `Motor6D` (поза пишется в `C0`), и снимки через MCP `screen_capture`. `AnimationConstraint` позу без физики не показывает.
- Суставы аватара — `AnimationConstraint`, а не `Motor6D`; `Animate` — модуль, его нельзя отключить. Переопределять суставы скриптом бесполезно: аниматор пишет их последним перед физикой.
- В тестах через MCP переносить персонажа — только `character:PivotTo(...)` (см. CONVENTIONS, «Персонаж»). Фоновые задачи (`task.spawn`) из `execute_luau` завершаются вместе с вызовом: для замеров во время ввода зажми клавишу (`user_keyboard_input` keyDown), замерь в одном вызове, потом отпусти.
- MCP после каждого `execute_luau` сбрасывает камеру. Чтобы снять кадр с нужной точки в игре, держи камеру через `RunService:BindToRenderStep`; в режиме редактирования — `screen_capture` с позицией камеры. **После снимков верни камеру игроку:** сними свою привязку и на несколько кадров привяжи другую, которая ставит `CameraType = Custom` и `CameraSubject` — гуманоид, потом отвязывается (простое присваивание в `execute_luau` MCP откатывает обратно в `Scriptable`, и камера у пользователя заблокирована). Пользователю: остановить и снова запустить Play. `computer-use` `zoom` увеличивает **последний** полный скриншот, а не делает новый.
